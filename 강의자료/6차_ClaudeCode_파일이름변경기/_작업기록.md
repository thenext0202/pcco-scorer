## 한 줄 요약
"파일 이름 일괄 변경기"를 그릇으로 **Claude Code 핵심 기능을 종합 체득 + 재사용 스캐폴드를 가르치는** 6차 강의 자료를 만들고, 슬라이드·러닝시트(PDF)·라이브 진행 시트까지 제작한 뒤, 랜딩 플랫폼에 6차로 추가·배포 완료.

## 핵심 결정 (왜 이렇게 했나)
- **강의 정체성**: "파일 변경기 만들기"가 아니라 *"어떤 프로그램이든 만드는 표준 흐름 + 재사용 구조"*를 가르치는 종합 입문. 프로그램은 그릇.
- **프레임워크 = 빌드 5단계** (묘사·실행·분리·갖춤·공유 / Describe·Run·Layer·Scaffold·Share).
- **프로그램 형태**: 웹앱/Artifacts가 아니라 **Node 로컬 프로그램**(내 폴더 파일을 `fs.rename`으로 제자리 변경). 추가 설치 0(Node 내장만).
- **핵심 교육 포인트**: 2단계 이상이면 **레이어로 쪼개 단계별 지침(스펙)으로 넘긴다** = 2차 I-MRKO "I/O 계약(포·필·범·메)"의 코드판.
- **재사용 스캐폴드**: CLAUDE.md·README·DEVLOG·HANDOVER·specs·.env·.gitignore·SKILL — "프로그램 = 코드 + 구조 파일들".
- **배포 교훈**: 내 파일을 만지는 도구는 URL 배포로 남이 못 씀 → **GitHub로 코드 공유**(각자 로컬 실행). 남의 파일 안 만지는 앱만 Vercel URL 배포.
- **수강생 눈높이**: 바이브코딩 첫 수강생 기준 — 프롬프트는 쉬운 한국어 + 코딩 용어(Node.js·포트·localhost·Git Bash·스펙·git/커밋)는 주석으로 풀이.
- **명령어 교정**: plan(계획) 모드 = **Shift+Tab**(또는 "먼저 계획만 보여줘"), `/permissions`는 권한 허용/차단. `/compact`(토큰 절약) 포함.

## 주의 / 미해결 (다음에 참고)
- 작업 환경(샌드박스 리눅스 마운트)이 호스트와 **동기화 지연**이 잦아, 코드/콘텐츠 파일이 마운트에서 잘려 보이는 일이 있었음 → 호스트 파일(실파일)은 정상. 검증은 파일 도구(호스트)로 했고, git 커밋은 호스트(Claude Code)에서 진행해 안전.
- 레포에 **CRLF/LF 추정 line-ending churn**으로 20여 개 파일이 수정된 것처럼 잡힘(이번 작업과 무관, 미해결). 커밋 시 `git add .` 금지, 의도한 파일만 스테이징하는 게 안전.
- PDF는 한글이 **나눔고딕**으로 렌더됨(샌드박스에 Pretendard 웹폰트 못 받음). Pretendard 그대로 원하면 `슬라이드.html`을 브라우저에서 열어 인쇄→PDF.
