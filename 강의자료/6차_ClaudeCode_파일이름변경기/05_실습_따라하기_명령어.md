# 6차 실습 — Claude Code 따라 하기 명령어 (자연어 스크립트)

> Claude Code를 켜고 아래 **회색 박스 안 문장을 그대로 복사해 입력**하면 됩니다.
> 두 가지 모드: **A) 완성본 바로 돌려보기** · **B) 빈 폴더에서 처음부터 따라 만들기**(실제 강의 흐름)

---

## A. 완성본 폴더에서 — 바로 실행·테스트

> 폴더: `04_완성샘플_파일이름변경기` 에서 `claude` 실행 후.

**1) 프로젝트 파악**
```
이 폴더가 무슨 프로그램인지, 구조가 어떻게 되어 있는지 CLAUDE.md랑 specs 폴더 보고 한국어로 요약해줘.
```

**2) 자체 테스트 돌리기**
```
node test.js 를 실행해서 결과를 보여줘. 통과/실패를 정리해줘.
```

**3) 서버 띄워서 실제로 써보기**
```
node server.js 로 로컬 서버를 띄워줘. 그리고 이 폴더 안 '테스트용_연습폴더'를 대상으로 scan API가 잘 도는지 확인해줘.
```
→ 직접 브라우저에서 `http://localhost:3000` 열고, 폴더 칸에 `테스트용_연습폴더`의 전체 경로를 붙여넣어 미리보기 → 적용 → 되돌리기 확인.

**4) 코드 한 부분 설명 요청**
```
@src/transform.js 이 파일이 '순번 매기기'를 어떻게 처리하는지 한 줄씩 설명해줘.
```

**5) 작은 개선 시켜보기 (선택)**
```
규칙에 '날짜 접두사'(오늘 날짜 YYYYMMDD_)를 추가하고 싶어. 큰 변경이니 먼저 계획만 보여주고, 내가 좋다고 하면 진행해줘.
```

---

## B. 빈 폴더에서 — 처음부터 따라 만들기 (실제 강의 흐름)

> **새 빈 폴더**를 만들고 그 안에서 `claude` 실행. (완성본 04는 정답지로 두세요.)
> 각 단계는 커리큘럼(`01_강의기획안.md`)의 Part와 짝지어 둡니다.

### Part 1~2 · 명령어 + 첫 버전 (R-PCCO로 작게 시작)
```
/help
```
```
너는 간단한 Node 프로그램을 만드는 개발자야. 내가 폴더 경로를 입력하면, 그 폴더 안 파일들 이름 앞에 글자(접두사)를 붙여 제자리에서 바꿔주는 가장 단순한 로컬 웹 도구를 만들어줘. 조건: Windows에서 Node 내장 기능만 쓰고(추가 설치 없이), 로컬 서버로 띄워 브라우저에서 쓴다. 실제로 바꾸기 전에 반드시 미리보기를 보여준다. 지정한 폴더 '바로 아래 파일'만 대상. 한글 파일명도 안전하게. node server.js로 띄우면 브라우저에서 열리는 한 페이지로 만들고, 실행 방법도 알려줘.
```

### Part 3 · 로컬 서버로 돌려보기
```
방금 만든 걸 로컬 서버로 띄워서 어떻게 도는지 보여줘. 포트는 3000으로.
```
```
@server.js 이 파일이 무슨 일을 하는지 한국어로 쉽게 설명해줘.
```

### Part 4 · 미리보기 + 규칙 추가 (계획 모드)
```
바꾸기 전에 '원래 이름 → 새 이름' 미리보기 표를 보여주고, 내가 '적용'을 눌러야 실제로 바뀌게 해줘.
```
```
규칙을 더 넣고 싶어: 순번 매기기(자릿수 지정), 찾기·바꾸기, 공백을 _로 바꾸기. 큰 변경이니 먼저 계획만 보여주고 내가 OK 하면 진행해줘.
```
```
방금 바꾼 걸 되돌리는 기능도 넣어줘. 직전 변경 내역을 파일로 기록해서 복원하게.
```

### Part 5 · 디버깅 (일부러 에러 → 고치기)
```
없는 폴더 경로를 넣으면 ENOENT 에러가 그대로 화면에 떠. scan 단계에서 나는 거야. 사용자에게는 '폴더를 찾을 수 없습니다. 경로를 확인하세요.' 같은 친절한 한국어 메시지로 바꿔줘.
```

### Part 6 · 레이어로 쪼개기 (핵심 · I/O 계약)
```
지금 로직이 한 곳에 엉켜서 복잡해졌어. 2차 강의에서 배운 'I/O 계약'을 적용해서 '수집 → 변환계획 → 출력' 3단계 레이어로 나눠줘.

- 각 단계를 src/collect.js, src/transform.js, src/output.js로 분리하고, 검증은 src/validate.js로.
- 단계 사이는 JSON으로만 주고받게 해줘(산문 금지).
- 단계별 지침을 specs/01_수집.md, 02_변환.md, 03_출력.md에 '먼저' 써줘. 각 지침엔 입출력 계약을 포맷·필수항목·범위·메타정보(포·필·범·메) 4가지로 명시.
- 한 단계는 다른 단계 일을 하지 않게(한 책임).

먼저 specs의 지침 MD 3개를 보여주고, 그 계약대로 각 모듈을 구현해줘.
```

### Part 7 · 재사용 스캐폴드 파일 갖추기
```
/init
```
```
방금 만든 CLAUDE.md를 다듬어줘. 개요, 실행법(node server.js), 그리고 절대 하지 말 것(미리보기 없이 변경 금지, 시스템 폴더 금지)을 넣어줘.
```
```
README.md(사람용 설명서), .gitignore, .env, .env.example도 만들어줘. .env엔 PORT=3000, .gitignore엔 .env와 node_modules와 .rename-history.json을 넣어줘.
```
```
개발로그 DEVLOG.md와 핸드오버 HANDOVER.md도 만들어줘. DEVLOG엔 오늘 한 일과 결정·이유를, HANDOVER엔 현재 상태와 다음 할 일을 정리해줘.
```
```
자주 쓰는 커밋을 conventional commits 규칙으로 정리하는 절차를 스킬로 만들어줘. .claude/skills/커밋정리/SKILL.md 로.
```

### Part 8 · 테스트 + git
```
수집→변환→검증→적용→되돌리기를 자동으로 점검하는 test.js를 만들어줘. node test.js로 돌리면 항목별 통과/실패가 보이게.
```
```
node test.js 를 돌려서 결과 보여줘.
```
```
git 저장소를 초기화하고 지금까지 만든 걸 커밋해줘. 방금 만든 '커밋정리' 스킬 규칙대로.
```

### Part 9 · 공유 (배포 한계 교훈)
```
이 프로그램을 다른 사람도 쓰게 하고 싶어. 이건 내 컴퓨터의 파일을 직접 바꾸는 도구인데, Vercel 같은 데 URL로 배포하면 남이 쓸 수 있어? 안 된다면 왜 안 되고, 그럼 어떻게 공유하는 게 맞는지 알려줘. 그리고 GitHub에 올리는 절차도 도와줘.
```

## 막힐 때 쓰는 만능 문장
- 새 작업 시작: `/clear`
- 큰 변경 전 안전하게: `큰 변경이니 먼저 계획만 보여주고 진행해줘.`
- 에러 해결: `이 명령을 했더니 이런 에러가 나: (에러 전체 붙여넣기). 환경은 (OS/Node 버전). 원인 찾아서 고쳐줘.`
- 이해 안 될 때: `방금 바꾼 부분을 초보자도 알게 한국어로 설명해줘.`
