# 02 · 변환계획(Transform) + 검증(Validate) 단계 지침

## 역할
파일목록을 받아, 규칙대로 '새 이름'을 계산하고(`src/transform.js`),
위험한 결과를 검증해 표시한다(`src/validate.js`). **실제로 바꾸지는 않는다.**

## 입력 (이전 단계에서 받음)
- 계약1 '파일목록 JSON' (`files[]`: originalName, baseName, ext, index)
- 사용자 규칙 `rule` (prefix / suffix / find·replace / space / lowercase / numbering)

## 출력 (다음 단계로 넘김) — I/O 계약
- **포(Format)**: JSON `{ rule, conflictCount, plan[] }`
- **필(Required)**: `plan[]` 각 항목 = `originalName, newName, conflict`
- **범(Scope)**: 입력 파일과 1:1. 누락/중복 금지
- **메(Metadata)**: `rule`(규칙 설명 문자열), `conflictCount`(정수)

## 규칙 (변환의 책임)
- 확장자는 기본 보존. `lowercase`일 때만 확장자도 소문자.
- `numbering` 켜짐 → 원래 이름 버리고 `(접두사) + 순번(패딩)`.
- 꺼짐 → 원래 이름에 find·replace → space → prefix → suffix 순서로 적용.

## 검증 (검증의 책임)
- 빈 이름 / `.확장자`만 있는 이름 → `conflict=true`
- 새 이름이 다른 파일과 중복 → `conflict=true`
- 금지 문자(`\ / : * ? " < > |`) 포함 → `conflict=true`

## 절대 하지 않는 것
- 실제 파일 변경 ❌ (3단계 출력의 책임)
- 파일 읽기/수집 ❌ (1단계 수집의 책임)
