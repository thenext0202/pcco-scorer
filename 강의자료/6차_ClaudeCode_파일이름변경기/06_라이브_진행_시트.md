# 6차 라이브 진행 시트 (하이브리드) — 붙여넣기용

> 강의 중 **위에서부터 순서대로** 회색 박스를 복사해 Claude Code에 붙여넣으면 됩니다.
> ⚠️ **회색 박스 하나 = 한 번 보내기**(붙여넣고 Enter). 한 단계에 박스가 여러 개면 **하나 보내고, 끝나길 기다렸다가** 다음 박스를 보냅니다. (예: `/init` 먼저 보내고 → CLAUDE.md가 만들어지면 → 그다음 다듬기 프롬프트)
> 각 단계에 ⟦슬라이드⟧ · 📚용어(강사 설명용) · 🧩정의하는 것 · 복사 블록 · ✅예상 결과 · ⚠️안 되면(폴백)을 달았습니다.
> 프롬프트만 빠르게 복사하려면 → `06_프롬프트만.txt`

> ✍️ **작성 원칙**: 붙여넣는 문장은 이전 강의 지식이 없어도 통하게 쉽게. 단, **코딩 용어(Node.js·포트·로컬 서버·git 등)는 일부러 넣고 주석으로 풀이**합니다. 너무 자연어로만 하면 이해는 쉬워도 학습이 덜 되니까요.

## 📖 이 강의에 나오는 코딩 용어 한눈에 (강사 치트시트)

| 용어 | 한 줄 설명 (이렇게 말하세요) |
|---|---|
| **터미널 / Git Bash** | 컴퓨터에 명령을 글로 입력하는 검은 창. 윈도우에선 'Git Bash'를 씁니다. 여기서 `claude`를 켜요. |
| **Node.js** | 우리가 만들 프로그램(자바스크립트)을 내 컴퓨터에서 실행해주는 엔진. Claude Code 깔 때 같이 깔려 있어요. |
| **서버 / 로컬 서버** | 화면을 띄워주는 프로그램. '로컬'은 인터넷이 아니라 **내 컴퓨터 안에서만** 돈다는 뜻. |
| **포트(port)** | 내 컴퓨터 안에서 프로그램이 쓰는 '문 번호'. 예: 3000. |
| **localhost** | '내 컴퓨터 자신'을 가리키는 주소. `localhost:3000` = 내 컴퓨터의 3000번 문. |
| **도구(Tools)** | Claude가 컴퓨터에 손대는 능력. 화면에 Read(읽기)·Write(쓰기)·Bash(실행)로 떠요. |
| **스펙(spec) / 설명 메모** | "이 단계는 무엇을 받아 무엇을 내보낸다"를 적은 약속 문서. 코드보다 먼저 정합니다. |
| **git / 커밋(commit)** | 작업 내용을 시점별로 저장(백업)하는 도구. '커밋' = 한 번 저장하는 것. 망쳐도 되돌릴 수 있어요. |
| **GitHub** | git으로 저장한 걸 인터넷에 올려 남과 나누는 곳. |

> 💡 위 표를 출력해 옆에 두면, 용어가 나올 때마다 한 줄로 바로 설명할 수 있습니다.

## 0단계 · 명령어 둘러보기  ⟦슬라이드 6⟧
📚 **슬래시 명령**: `/`로 시작하는 Claude Code 단축 명령. `/help`는 명령어 목록.
```
/help
```
✅ 명령어 목록이 뜸. "막히면 /help"만 각인.

📌 **자주 쓰는 명령 (강사가 짚기)**
- `/help` — 명령어 목록
- `/clear` — 대화 비우기 (새 작업 시작할 때)
- `/compact` — 지금까지 대화를 요약본으로 압축 → **토큰 절약**. 대화가 길어지면 한 번씩.
- `/init` — CLAUDE.md(설명서) 자동 생성 (7단계에서 사용)
- `/permissions` — 권한(허용/차단) 설정
- `Shift+Tab` — **plan(계획) 모드** 전환 (위험 변경 전 '계획만 먼저'). 쉽게는 그냥 "먼저 계획만 보여줘"라고 말해도 됨.

## 1단계 · 단순 버전 만들기  ⟦슬라이드 7~9⟧
📚 **Node.js**: 우리가 만들 프로그램을 내 컴퓨터에서 실행해주는 엔진(추가 설치 필요 없음, 이미 깔려 있음).
🧩 **프로그램을 요청할 땐 다섯 가지를 정한다**(= 슬라이드 8): ①역할 ②목적 ③맥락 ④제약 ⑤출력. 아래 문장에 다 들어 있습니다.
```
너는 코딩을 잘 모르는 사람도 쉽게 쓸 수 있는 작은 프로그램을 잘 만드는 개발자야.        ← ① 역할
나는 파일 이름을 한꺼번에 바꿔주는 프로그램이 필요해. 내가 폴더를 하나 정해주면, 그 폴더 안 파일들 이름 앞에 내가 원하는 글자를 붙여서 한 번에 바꿔주는 거야.   ← ② 목적
나는 코딩을 잘 몰라. 윈도우를 쓰고, 크롬 같은 브라우저에서 버튼으로 조작하고 싶어. 추가 설치 없이 Node.js 기본 기능만으로 만들어줘.   ← ③ 맥락
진짜로 바꾸기 전에 어떻게 바뀔지 목록으로 먼저 보여주고, 내가 확인해야 바뀌게 해줘. 내가 정한 폴더 바로 안의 파일만 건드려.   ← ④ 제약
결과는 크롬 같은 브라우저에서 열리는 한 페이지로 만들고, 다 만들면 어떻게 실행하는지도 알려줘.   ← ⑤ 출력
```
> 💡 붙여넣을 땐 화살표(← ①…)는 둬도 Claude가 무시합니다. 강의 중 "좋은 요청엔 이 5가지가 들어가요"라고 짚기.
✅ Node.js로 도는 실행 파일 + 간단한 브라우저 화면 생성. 권한 확인 창 뜨면 같이 읽고 승인(슬라이드 9).
⚠️ 너무 복잡하면: "더 단순하게, 꼭 필요한 것만 다시 만들어줘". 그래도 꼬이면 창 B로 설명.

## 2단계 · 실행해서 브라우저로 보기  ⟦슬라이드 10~11⟧
📚 **로컬 서버 / 포트 / localhost**: 내 컴퓨터 안에서만 도는 서버를 띄우고, '문 번호(포트) 3000'으로 접속. 브라우저에 `localhost:3000`을 치면 열림.
📚 **도구(Tools)**: 실행 중 화면에 `Bash`(명령 실행)·`Read`(읽기) 같은 게 떠요 — Claude가 지금 뭘 하는지 보여주는 표시(슬라이드 11).
```
방금 만든 걸 Node.js로 실행해줘. 포트는 3000으로 로컬 서버를 띄우고, 브라우저에서 localhost:3000으로 열면 되는지 알려줘.
```
✅ Claude가 `Bash` 도구로 서버 실행 → 브라우저에 `localhost:3000` 입력 → "내 컴퓨터에서 진짜 돈다" 순간.
```
방금 만든 게 무슨 일을 하는 건지, 코딩 처음 하는 사람도 알아듣게 쉽게 설명해줘.
```
✅ 코드 설명도 시켜볼 수 있다는 걸 보여줌.
⚠️ 포트 충돌 뜨면(이미 3000을 쓰는 중): "다른 포트, 예를 들어 3001로 다시 띄워줘".

## 4단계 · 에러를 쉬운 안내로  ⟦슬라이드 14⟧
📚 **에러 메시지**: 프로그램이 잘못됐을 때 뜨는 영어 경고문. 무서운 게 아니라 '어디가 문제인지 알려주는 정보'예요.
👉 먼저 브라우저에서 **있지도 않은 폴더 이름**을 입력해 에러를 일부러 띄웁니다.
```
방금 없는 폴더 이름을 넣었더니 어려운 영어 에러가 그대로 화면에 떴어. 사용자가 보기엔 무서우니까, '폴더를 찾을 수 없어요. 경로를 다시 확인해 주세요.' 같은 쉬운 한국어 안내로 바꿔줘.
```
✅ "에러는 잘 말하면 고쳐진다"(슬라이드 14).
⚠️ 에러가 안 나면: "잘못된 입력에 대한 친절한 안내 메시지를 추가해줘"로 우회.

## 5단계 · 기능을 단계로 나누기 (핵심)  ⟦슬라이드 15~19⟧
📚 **스펙(spec) / 설명 메모**: "이 단계는 무엇을 받아 무엇을 내보낸다"를 적은 **약속 문서**. 코드를 짜기 **전에** 먼저 정해두면 단계끼리 안 어긋납니다.
🧩 **각 단계 스펙에는 다섯 가지를 정한다**(= 슬라이드 18~19): ①하는 일 ②입력 ③출력 ④형식·필수항목 ⑤하면 안 되는 일.
```
지금은 모든 기능이 한 파일에 다 들어 있어서 점점 복잡하고 고치기 어려워졌어. 하는 일에 따라 세 단계로 나눠줘.
- 1단계: 폴더에서 파일 목록을 읽어오는 일
- 2단계: 규칙에 따라 새 이름을 정하는 일 (아직 실제로 바꾸진 않음)
- 3단계: 실제로 이름을 바꾸는 일
여기에, 새 이름이 비어 있거나 서로 겹치지 않는지 확인하는 부분도 따로 만들어줘.

그리고 각 단계마다 '설명 메모(스펙)'를 하나씩, 코드보다 먼저 만들어줘. 메모에는 이걸 적어줘:
  ① 이 단계가 하는 일
  ② 무엇을 받는지(입력)
  ③ 무엇을 내보내는지(출력)
  ④ 내보내는 정보의 형식과 꼭 들어갈 항목
  ⑤ 이 단계가 하면 안 되는 일
다음 단계가 그대로 이어받을 수 있게, 주고받는 정보의 모양을 분명하게 정해줘. 각 단계는 자기 일만 하고 다른 단계 일은 건드리지 않게 해줘.

먼저 그 설명 메모(스펙)들부터 보여주고, 그다음에 실제로 나눠서 만들어줘.
```
✅ **이 강의의 클라이맥스.** 슬라이드에선 이걸 '레이어로 나눈다', '단계별 지침(스펙)'이라 부른다고 설명. 결과로 역할별 파일 + 스펙 메모들이 생김(슬라이드 17 그림과 매칭).
⚠️ 시간/꼬임 위험이 가장 큰 구간. 2분 넘으면 창 B의 `src/`·`specs/` 폴더를 열어 "이렇게 나뉜다" 보여주고 넘어가기.

💾 **토큰 팁**: 여기까지 오면 대화가 꽤 길어집니다. 다음 단계로 넘어가기 전에 `/compact`를 한 번 보내면 지금까지 내용을 요약본으로 압축해 **토큰을 아낄 수 있어요**(작업 내용은 그대로 유지).

## 6단계 · 반복 작업 저장(스킬)  ⟦슬라이드 20⟧
📚 **스킬**: 자주 하는 절차를 저장해두면, 다음엔 이름만 불러 똑같이 실행하는 기능. **커밋(commit)** = 작업을 한 번 저장하는 것(9단계에서 자세히).
```
앞으로 작업 내용을 저장(커밋)할 때 메시지를 항상 같은 규칙으로 쓰고 싶어. (예: 메시지 앞에 '기능추가:' 또는 '버그수정:' 붙이기) 이 규칙을 '스킬'로 저장해두고, 다음에 그 이름만 부르면 똑같이 따라 하게 해줘.
```
✅ "자주 하는 절차를 저장 = 스킬" 맛보기.
⚠️ 부담되면 개념만 말하고 창 B의 `claude_예시/skills` 폴더 보여주기.

## 7단계 · 꼭 필요한 파일 갖추기  ⟦슬라이드 21~23⟧
📚 **CLAUDE.md**: 이 폴더에 두면 Claude가 매번 자동으로 읽는 '설명서' 파일. **.env**: 비밀값·설정을 따로 보관(공개 금지). **.gitignore**: 인터넷에 올리면 안 되는 파일을 걸러주는 목록. **DEVLOG.md**: 오늘 한 일을 적는 개발로그. **HANDOVER.md**: 다음에 이어서 작업할 때 보는 인수인계 메모.
> 👉 `/init`을 **먼저 보내고(Enter)** → Claude가 CLAUDE.md를 다 만들 때까지 기다린 뒤 → 아래 다듬기 프롬프트를 보냅니다. (두 번 나눠 보내기)
```
/init
```
```
방금 자동으로 만들어진 CLAUDE.md(이 프로젝트를 AI가 매번 읽는 설명서)를 다듬어줘. 이 프로그램이 뭔지, 어떻게 실행하는지(Node.js로 실행), 그리고 절대 하면 안 되는 것(확인 없이 파일 바꾸기, 윈도우 시스템 폴더 건드리기)을 넣어줘.
```
