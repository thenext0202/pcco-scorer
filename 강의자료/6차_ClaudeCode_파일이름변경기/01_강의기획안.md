# 6차 강의 기획안 — Claude Code 종합 실습

> **부제**: 로컬 프로그램을 만들고 → 레이어로 쪼개고 → 로컬서버로 돌려 내 폴더를 제자리 정리하고 → GitHub로 공유하기. 그 과정에서 Claude Code 핵심 기능 전부 체득
> **연계 자료**: 『Claude Code 한국어 입문 가이드』(정금구, 28섹션) + 2차 강의 I-MRKO(지침 체인·I/O 계약)
> **프레임워크 재활용**: R-PCCO(1·4차) + I/O 계약 포·필·범·메(2차)
> **상태**: 기획안 (v4 · 레이어 구조 + 단계별 지침 MD 핵심 파트 추가)

---

## 0. 한 문장 요약

> **"내 손으로 로컬 프로그램을 만들어, 2단계 이상이면 레이어로 쪼개 단계별 지침으로 넘겨받게 하고, 로컬서버로 돌려 내 폴더의 파일을 제자리에서 진짜로 바꾸고, GitHub로 공유한다 — 그 한 사이클로 Claude Code를 통째로 체험한다."**

수강생은 코드를 한 줄도 직접 안 쓰고 "파일 이름 일괄 변경기 로컬 프로그램"을 만들며 — **슬래시 명령 · 도구(Tools) · 권한 · 로컬 서버 테스트 · 미리보기/계획 모드 · 디버깅 · 레이어 구조(I/O 계약) · 단계별 지침 MD · 스킬 · git · 공유**까지 전부 손으로 밟는다.

> ⚠️ **핵심 전제**: 만드는 프로그램은 단순하다. 주인공은 *프로그램*이 아니라, 수강생이 가져갈 **재사용 구조(스캐폴드)** — 즉 "어떤 프로그램이든 이렇게 시작한다"는 파일 뼈대와 흐름이다. (→ `03_표준구조_가이드.md`가 이 강의의 핵심 산출물)

## 1. 강의 개요

| 항목 | 내용 |
|---|---|
| 강의명 | Claude Code 종합 실습 — 로컬 프로그램 만들고 레이어로 쪼개 로컬서버·공유까지 |
| 차수 | 6차 (바이브 코딩 시리즈 심화 · Claude Code 입문) |
| 대상 | 1차(R-PCCO)·2차(I-MRKO)·4차(바이브 코딩) 수강한 비개발자 |
| 선수 조건 | **Claude Code 설치·로그인 완료**(가이드 04), R-PCCO·I/O 계약 개념 |
| 교재 | 『Claude Code 한국어 입문 가이드』 + 2차 I-MRKO 복습 |
| 소요 시간 | 약 118분 (+ 배포 보너스 15~20분) |
| 만드는 것 | 파일 이름 일괄 변경기 **Node 로컬 프로그램** (3단계 레이어: 수집→변환계획→출력) |
| 결과물 | 내 폴더의 파일을 제자리에서 바꾸는 로컬 도구 + 단계별 지침 MD + (시간 남으면) GitHub 공유 |

### 왜 "파일 이름 변경기 로컬 프로그램"인가
- **누구나 공감 + 단순함이 미덕**: 기능이 단순해 *Claude Code 학습*에 집중.
- **레이어 교육에 최적**: 수집→변환→출력 3단계로 자연스럽게 쪼개져 *I/O 계약*을 코드로 보여주기 좋다.
- **추가 설치 0 + 제자리 변경**: Node 내장 기능만으로 내 폴더의 파일을 진짜로 바꾼다(`fs.rename`). 로컬 서버로 띄워 브라우저에서 조작.
- **안전 교육 내장**: 진짜 파일을 바꾸니 "미리보기 → 확인 → 적용 → 되돌리기"와 권한 개념을 자연스럽게 가르친다.

## 3. 학습 목표 (이 강의가 끝나면)

1. Claude Code가 Artifacts와 **무엇이 다른지** 한 문장으로 말한다.
2. **만능 5단계**로 어떤 작업이든 시작하고, 자주 쓰는 **슬래시 명령어**를 안다.
3. **Tools 표시**를 읽고 **로컬 서버**를 띄워 브라우저에서 테스트한다.
4. **계획(plan) 모드**로 위험 변경을 미리 보고, **디버깅 5요소**로 에러를 고친다.
5. ⭐ 프로그램이 2단계 이상이면 **레이어로 쪼개** 단계마다 **지침 MD(I/O 계약)**를 두고 **JSON으로 넘겨받게** 설계한다.
6. ⭐ **재사용 스캐폴드**(CLAUDE.md·README·DEVLOG·HANDOVER·specs·.env·SKILL·.gitignore)를 갖춰, **다음 프로그램도 같은 구조로 혼자 시작**할 수 있다.
7. **git**으로 안전망을 치고, (시간 되면) **GitHub로 공유**해서 남들이 받아 자기 컴퓨터에서 쓸 수 있게 한다.

## 4. 핵심 메시지 & 킬러 인사이트

### 핵심 한 문장
> **"Claude Code의 맥락(Context)엔 '내 컴퓨터'가 들어간다 — 내 폴더의 파일을 진짜로 바꾸고, 그 코드를 GitHub로 나눌 수 있다. 단, 일이 커지면 레이어로 쪼개 '접점'을 계약으로 고정해야 무너지지 않는다."**

### 킬러 인사이트 4가지
**① 같은 R-PCCO, 달라진 '맥락(C)'** — 코딩 맥락엔 "어떤 환경·무슨 파일·어떻게 실행·어디 배포"가 들어간다.

**② 만들기 ≠ 끝. 돌려보고 → 고치고 → 공유해야 진짜** — 로컬 테스트 → 디버깅 → 반복 개선 → 공유의 한 사이클을 돈다.

**③ ⭐ 2단계 이상이면 레이어로 — 인풋/아웃풋을 분리하고 접점을 계약으로 고정하라**(2차 복습) — "체인의 성패는 지침이 아니라 지침 사이의 '접점'에 달렸다." 각 단계는 *한 책임*만 지고, 단계 사이는 **구조화된 JSON(포·필·범·메)**으로 넘긴다. *산문은 체인의 적.*

**④ 위험·되돌릴 수 없는 일은 미리보기·plan·git부터** — 기능이자 습관(가이드 12 실수 #1·#5).

### 습관 3가지 (수강생 체크카드)
- [ ] 묘사는 **R-PCCO**로, 2단계 넘어가면 **레이어로 쪼개고 단계별 지침 MD**
- [ ] 만들면 **바로 로컬 서버로 확인**, 위험 변경은 **plan·git 먼저**
- [ ] **작게 시작 → 써보고 → 레이어 추가**, 작업 바뀌면 `/clear`

### Part 6. 레이어로 쪼개기 — I/O 계약 + 단계별 지침 MD ⭐ (22분) · 이번 강의의 심장
- **문제 제기**: "규칙·미리보기·적용·되돌리기가 한 파일에 다 엉켜 복잡해졌다. 2차에서 배운 거 기억나죠?"
- **원칙 소환(2차 I-MRKO)**: *"2단계 이상이면 레이어로. 한 단계=한 책임. 접점은 JSON으로 고정. 산문은 체인의 적."*
- **3단계로 분해**:

  ```
  [1 수집]  →〈계약1: 파일목록 JSON〉→  [2 변환계획]  →〈계약2: 변경계획 JSON〉→  [3 출력]
   올린 파일               파일목록+규칙                old→new 매핑(미리보기)        이름 바뀐 파일 묶음
  ```

- **단계별 지침 MD 작성**(핵심 실습): `specs/01_수집.md`·`02_변환.md`·`03_출력.md`. 각 MD에 **I/O 계약 포·필·범·메**를 적는다.
  - 예) `02_변환.md` → 입력: 파일목록 JSON / 출력: `[{old, new, conflict}]` / 범위: 한 번에 최대 N개 / 메타: 충돌 표시.
- **spec-first로 구현 요청**: "이 지침 MD들의 계약대로 각 단계를 **별도 파일(모듈)**로 구현하고 JSON으로 넘겨받게 해줘." → 멀티파일 리팩토링 자연 발생(Artifacts가 못 하는 것).
- **검증 단계 끼우기**(2차 원칙): 변환계획 뒤 "빈 이름·중복 충돌 검증" 한 단계.
- **스킬 연결**(가이드 17): "이 단계 지침을 **스킬로 저장**하면 다음 프로그램에서 재사용." 가벼운 시연/언급.
- 메시지: "프로그램도 글처럼 **레이어로 쌓는다.** 접점만 계약으로 잡으면 안 무너진다."

- **핵심 메시지**: "오늘 만든 건 파일 변경기 하나지만, *진짜 배운 건 모든 프로그램에 깔 구조*다."
- `/init`으로 **CLAUDE.md** 초안(가이드 08) → 다듬기(개요·실행법·절대금지).
- 나머지 파일을 같이 갖춘다(역할만 빠르게, 템플릿은 03 가이드 복붙):
  - **README.md** — 사람용(남이 받아 실행하는 법)
  - **DEVLOG.md**(개발로그) — 무엇을·언제·왜 했나 (다음에 열어도 1초 복원)
  - **HANDOVER.md**(핸드오버) — 현재 상태·다음 할 일 (세션 끊겨도 이어가기)
  - **.env / .env.example** — 비밀·설정 분리(`.env`는 깃 제외, example만 공유)
  - **.gitignore** — `.env`·node_modules 제외
  - (반복작업 보이면) **SKILL.md** 한 개
- 4차 복습 확장: CLAUDE.md=AI용 한 장, README=사람용 한 장, specs/=단계 설계도, DEVLOG/HANDOVER=내 미래를 위한 기록.
- 마무리 한마디: "**다음 프로그램도 이 체크리스트로 시작한다**"(03 §8 복붙 체크리스트 띄우기).

### Part 9. 공유하기 ⭐ (보너스 · 15~20분 · 시간 남으면)
- **클라이맥스이자 솔직한 배포 수업**: "이건 URL로 남이 못 써요. 왜?" → *배포된 웹서버는 남의 컴퓨터 파일을 못 만지니까*(브라우저 보안). 내 파일을 만지는 도구의 숙명.
- 그래서 **GitHub에 코드 공유** → 남이 `git clone` 받아 **자기 컴퓨터에서 `node server.js`** 실행. "이 프로젝트 GitHub에 올려줘" 요청.
- 대조 교훈: 4차 운세 앱처럼 *남의 파일 안 만지는* 웹앱은 Vercel URL 배포가 맞다 → **무엇을 만드느냐에 따라 배포 방식이 다르다.**
- ⚠️ GitHub 인증 변수 있음 → 시간 없으면 강사 시연 대체.
