📖 사용법

한 페이지 = 한 슬라이드. ★ KEY POINT(청록) = 반드시 전달할 한 문장 · 🖥 화면(파랑) = 이 슬라이드에 띄울 것 · 💬 이렇게 말하세요(검정) = 실제 멘트 · 💡 강사 팁(노랑) · ⚠️ 주의(빨강) · 📌 참고(회색) · → 넘어가며.
이 수업은 진단 세션이다 — 정답(기능 체크리스트)은 슬라이드 13 전까지 절대 화면에 띄우지 않는다.

📚 핵심 개념 한 줄 (강사용)

역설계 3단계 = 쓰다(Use — 사용자로 충분히) · 뜯다(Decompose — 기능·결과물·예외를 목록으로) · 적다(Specify — 재량이 안 남게)
기준 한 줄 = "이 프롬프트만 받은 AI가, 이 프로그램을 그대로 만들 수 있는가?" · 채점 4축 = 관찰·명세·예외·구조 (각 25점) · 분반 = 본인 희망 + 강사 원문 검토 → 개별 통지
수업 전 준비 = ① 배포 zip(exe+샘플 폴더) ② 링크 배정표 ③ 채점기 reverse 세션 생성(코드·QR) ④ 관찰 워크시트 인쇄

01Part 0 · 오프닝
표지 — "오늘은 만들지 않습니다"
⏱ 1분
★ KEY POINT
오늘은 거꾸로 가는 날 — 완성된 프로그램에서 프롬프트를 뽑아낸다.
🖥 화면
표지 — 강의명 + "프롬프트 → 프로그램"에 취소선, 그 아래 "프로그램 → 프롬프트".
💬 이렇게 말하세요
안녕하세요. 오늘은 좀 이상한 수업입니다. 아홉 번의 수업 동안 우리는 계속 뭔가를 만들었어요. 프롬프트를 쓰고, 프로그램을 얻고. 오늘은 아무것도 만들지 않습니다. 대신 거꾸로 갑니다 — 이미 완성된 프로그램을 여러분께 드릴 테니, 여러분이 그 프로그램을 만들어낼 프롬프트를 쓰는 겁니다.
→ 넘어가며: "왜 거꾸로 가냐 — 이게 실력의 본체이기 때문입니다."

02Part 0 · 오프닝
왜 거꾸로 가나 — 프롬프트 실력의 정체
⏱ 3분
★ KEY POINT
좋은 프롬프트는 글재주가 아니라 관찰의 양이다. 관찰→분해→명세가 실력의 본체.
🖥 화면
"글재주 ✗ / 관찰의 양 ✓" 대비 + 관찰→분해→명세 3화살표.
💬 이렇게 말하세요
1차부터 지금까지, 프롬프트를 잘 쓰는 법을 배웠습니다. R-PCCO, 바이브 코딩 5요소… 그런데 그 공식들의 공통점이 뭐였는지 아세요? 전부 '빈칸 채우기 틀'이에요. 틀은 드렸습니다. 문제는 빈칸에 넣을 내용이죠. 그 내용은 어디서 오느냐 — 관찰에서 옵니다. 원하는 걸 정확히 보고, 목록으로 분해하고, 옮겨 적는 것. 오늘은 그 능력만 순수하게 꺼내서 단련합니다. 눈앞에 완성품을 놓고, 그걸 얼마나 정확히 '읽어내는지' 보는 거예요.
💡 강사 팁
"글재주가 아니라 관찰의 양" — 오늘 최소 세 번 반복할 문장. 여기서 처음 등장시킨다.
→ 넘어가며: "오늘 여러분이 제출할 것은 딱 하나입니다."

03Part 0 · 오프닝
오늘의 제출물 — 한 방 프롬프트
⏱ 3분
★ KEY POINT
기준은 단 하나 — "이 프롬프트만 받은 AI가, 그 프로그램을 그대로 만들 수 있는가?"
🖥 화면
기준 한 줄을 화면 중앙에 크게. 아래에 "제출물 = 프롬프트 텍스트 1개".
💬 이렇게 말하세요
제출물은 프롬프트 텍스트 하나입니다. 길이 제한도, 형식 제한도 없어요. 판정 기준이 딱 하나 있을 뿐입니다. 여러분의 프롬프트를 오늘 처음 보는 AI에게 줬을 때 — 그 AI가 여러분이 오늘 써본 프로그램과 같은 것을 만들어낼 수 있는가. 상상해보세요. AI는 그 프로그램을 본 적이 없습니다. 여러분이 안 적은 것은 AI가 모릅니다. 그러니까 오늘의 승부는 — 프롬프트에 없는 것은 만들어지지 않는다, 이 한 문장에 달려 있습니다.
→ 넘어가며: "그리고 솔직하게 말씀드릴 게 하나 있습니다."

04Part 0 · 오프닝
솔직한 안내 — 오늘은 레벨 점검입니다
⏱ 3분
★ KEY POINT
시험이 아니라 배치 상담 — 비슷한 속도끼리 묶어 다음 강의를 딱 맞는 속도로 가기 위한 것.
🖥 화면
"시험 ✗ / 배치 상담 ✓" + 반영 요소 2개(본인 희망 + 강사 검토) + "결과는 추후 공지".
💬 이렇게 말하세요
숨기지 않고 말씀드립니다 — 오늘 제출물은 여러분의 학습 정도를 확인하는 자료로 씁니다. 열 번의 수업이 쌓였고, 이제부터는 초급반과 중급반으로 나눠서 각자에게 맞는 속도로 진행하려고 해요. 오해는 하지 마세요. 등수를 매기는 게 아닙니다. 초급반은 벌점이 아니라 기초를 한 번 더 단단하게 다지는 코스고요. 제출할 때 희망하는 반도 함께 적어주시면, 제가 제출물을 직접 읽고 희망과 함께 반영해서 분반 결과를 추후에 공지드리겠습니다.
💡 강사 팁
이 슬라이드의 톤이 오늘 수업의 심리적 안전을 결정한다. "여러분이 어디까지 왔는지 확인하고, 딱 맞는 속도로 가기 위한 시간" — 담백하게, 서두르지 말고.
→ 넘어가며: "자, 그럼 오늘의 절차 — 딱 세 단어입니다."

05Part 1 · 역설계 3단계
쓰다 · 뜯다 · 적다
⏱ 2분
★ KEY POINT
쓰다(Use) → 뜯다(Decompose) → 적다(Specify). 2단계를 건너뛴 사람의 프롬프트는 얇다.
🖥 화면
3단계 카드 (쓰·뜯·적 + 영문 + 한 줄 설명).
💬 이렇게 말하세요
절차는 세 단어입니다. 먼저 씁니다 — 사용자로서 충분히, 그리고 일부러 이상하게도. 다음은 뜯습니다 — 본 것을 워크시트에 목록으로 분해합니다. 마지막에 적습니다 — 그 목록을 하나의 프롬프트로 재조립합니다. 제일 위험한 건 뭐냐면, 조금 써보고 바로 적기 시작하는 겁니다. 뜯는 단계를 건너뛴 프롬프트는 반드시 얇아요. 오늘 시간표도 그래서 관찰에 30분을 통째로 드립니다.
→ 넘어가며: "그 대상이 뭔지 — 직접 보여드릴게요."

06Part 1 · 시연
라이브 시연 — IG 아카이버
⏱ 4분
★ KEY POINT
기본 사용법(링크 붙여넣기 → 시작)만 보여준다 — 관찰 포인트는 절대 짚어주지 않는다.
🖥 화면
화면 미러링으로 실제 프로그램 시연 (슬라이드는 "지금 화면을 보세요" 한 장).
💬 이렇게 말하세요
제가 실제로 만들어 쓰고 있는 프로그램입니다. 인스타그램에서 카드뉴스 같은 게시물을 보관하는 도구예요. (링크 붙여넣고, 시작 누르고, 로그 올라가는 것 보여주며) 쓰는 법은 이게 전부입니다 — 링크 넣고, 시작. 소스 코드는 안 드립니다. 여러분이 받는 건 실행 파일 하나예요. 왜 코드를 안 주냐 — 오늘 측정하는 건 코드 읽기가 아니라 사용자로서의 관찰력이기 때문입니다. 여러분이 재현하고 싶은 세상의 좋은 프로그램들, 대부분 소스가 없잖아요.
⚠️ 주의 — 답 유출 금지
시연 중 결과 폴더를 열거나, 두 번 실행하거나, 잘못된 링크를 넣는 모습을 보여주지 말 것. 그건 전부 수강생이 스스로 발견해야 할 관찰 포인트다. 링크 2개 정상 다운로드까지만.
📌 참고
시연용 링크는 전날 실측으로 검증한 것 2개를 사용. 차단에 대비해 미리 받아둔 결과 화면 스크린샷도 백업으로 준비.
→ 넘어가며: "이제 여러분 차례 — 받기 전에 규칙 네 개만."

07Part 1 · 배포와 수칙
배포 + 사용 수칙 4
⏱ 4분
★ KEY POINT
링크는 배정받은 것만 1~2개 · 거부 메시지 뜨면 재시도 금지 · 경고창은 "추가 정보→실행" · 맥은 2인 1조.
🖥 화면
수칙 4개 카드 + 배포 방법(zip 전달 경로) + SmartScreen "추가 정보 → 실행" 스크린샷.
💬 이렇게 말하세요
zip을 풀면 실행 파일 하나랑 샘플 폴더가 있습니다. 수칙 네 개만 지켜주세요. 첫째 — 인스타그램 링크는 제가 배정해드린 것만, 1~2개만 넣으세요. 우리 전부가 같은 와이파이거든요. 한꺼번에 요청이 몰리면 인스타그램이 우리를 차단합니다. 둘째 — '요청을 거부했습니다'가 뜨면 재시도하지 마세요. 재시도할수록 차단이 길어집니다. 그럴 땐 같이 드린 샘플 폴더로 관찰을 계속하시면 돼요, 지장 없습니다. 셋째 — 처음 실행할 때 파란 경고창이 뜨면 '추가 정보', '실행'. 제가 서명 없이 만든 개인 프로그램이라 뜨는 정상 경고입니다. 넷째 — 맥이신 분들은 배정된 짝과 함께 한 화면으로 관찰하시고, 워크시트와 프롬프트는 각자 씁니다.
💡 강사 팁
시작 타이밍을 조별로 2~3분 분산시키면 차단 확률이 뚝 떨어진다. "1조부터 시작하세요" 방식. 핫스팟 사용자는 자유 시작.
→ 넘어가며: "30분 드립니다 — 쓰고, 뜯으세요."

08Part 2 · 쓰다 + 뜯다 ⭐
체험 + 관찰 워크시트 (30분)
⏱ 30분
★ KEY POINT
정상적으로도, 일부러 이상하게도 써 보라. 워크시트 ①~⑤를 채우는 것이 이 시간의 목표.
🖥 화면
타이머(30:00) + 관찰 미션 5줄(워크시트 ①첫인상 ②써보기 ③결과물 ④실험 ⑤이상한 점) 고정 표시.
💬 이렇게 말하세요 (시작 멘트)
지금부터 30분, 여러분은 사용자이자 탐정입니다. 워크시트의 다섯 칸을 채우세요. 특히 ④번 — 일부러 이상하게 써 보세요. 같은 걸 두 번 하면? 틀린 걸 넣으면? 프로그램의 진짜 설계는 '안 될 때'에 숨어 있습니다. 그리고 ⑤번 — 쓰다가 뭔가 이상하거나 불편하면, 불평하지 말고 적어두세요. '왜 일부러 이렇게 만들었을까?' 그 추측이 점수가 됩니다.
💡 순회 힌트 가이드 (수위 조절)
허용 힌트(방향만): "화면 말고 다른 데서도 확인할 게 있을 텐데요?" · "결과물이 어디에 남았는지 봤어요?" · "④번 실험 몇 개 해봤어요?"
금지 힌트(정답): 특정 파일·폴더명 언급, "○○ 기능 봤어요?", 딜레이의 이유 설명. — 발견은 본인 몫.
📌 진행 콜 (타이머 기준)
10분 경과 — "아직 화면만 보고 계신 분, 결과물을 찾아가 보세요." · 20분 경과 — "이제 ④⑤번, 괴롭히고 추측할 시간입니다." · 27분 — "3분 뒤 마칩니다. 밑줄 치며 정리하세요."
⚠️ 주의
차단 발생 조가 나오면 즉시 샘플 폴더 관찰로 전환시킨다. "차단도 관찰거리입니다 — 왜 차단됐을까요?"라고만 던지고 답은 주지 않는다.
→ 넘어가며: "손 떼세요 — 이제 적으러 갑니다."

09Part 3 · 작성 브리핑
작성 규칙 — 그리고 더는 안 가르쳐드립니다
⏱ 5분
★ KEY POINT
45분 · AI 사용 금지 · 서로 공유 금지 · 기준은 여전히 한 줄 — 그대로 만들 수 있는가.
🖥 화면
규칙 3개(45분 / AI 금지 / 공유 금지) + 기준 한 줄 재표시. 작성 요령은 띄우지 않는다.
💬 이렇게 말하세요
지금부터 45분간 한 방 프롬프트를 씁니다. 규칙 셋. 하나 — AI 도구는 쓰지 않습니다. 오늘 측정하는 건 여러분 자신의 능력이니까요. AI가 대신 쓰면 AI가 채점받는 겁니다. 둘 — 옆 사람과 프롬프트를 공유하지 않습니다. 남의 답을 보면 자기 위치를 알 수 없게 돼요. 셋 — 어떻게 쓰라는 요령은 더 안 알려드립니다. 지난 아홉 번의 수업이 전부 그 요령이었으니까요. 기준만 다시 한번: 이 프롬프트만 받은 AI가, 그 프로그램을 그대로 만들 수 있는가. 워크시트의 밑줄들이 여러분의 재료입니다.
💡 강사 팁
"어떻게 시작해요?"라는 질문에는 "워크시트에 적힌 것부터 문장으로 옮기세요"까지만. R-PCCO를 쓰라는 지시도 하지 않는다 — 스스로 구조화하는지가 D축 측정 대상.
→ 넘어가며: "시작하세요."

10Part 4 · 적다 ⭐
한 방 프롬프트 작성 (45분)
⏱ 45분
★ KEY POINT

💬 이렇게 말하세요
제출은 두 갈래입니다. 먼저 화면의 QR로 채점기에 들어가서 — 닉네임 넣고, 프롬프트를 붙여넣고, 채점을 받으세요. 4개 축으로 점수가 나오고 리더보드에도 올라갑니다. 그리고 원문을 희망하는 반(초급/중급)과 함께 저한테 보내주세요. 미리 말씀드리면 — 리더보드 점수가 분반을 정하는 게 아닙니다. 제가 원문을 전부 직접 읽습니다. 점수는 참고용이에요. 아, 그리고 채점기가 여러분한테 정답을 안 알려줄 겁니다. 대신 '다시 관찰하러 갈 질문'을 줘요. 그게 이 채점기의 설계입니다.
📌 참고
세션은 수업 전에 미리 생성해둔다 (/practice → 세션 만들기 → 🔍 역설계). 재제출 허용 — 단 "점수를 올리는 유일한 방법은 더 관찰하는 것"임을 안내.

13Part 5 · 셀프 체크
"왜 이렇게 느려요?" — 불편함은 사양이다
⏱ 6분
★ KEY POINT
느린 건 버그가 아니라 차단 회피용 의도적 딜레이 — 불편함을 사양으로 읽는 눈이 중급의 눈.
🖥 화면
"느리다 = 불평(초급) / 일부러 천천히 = 사양(중급)" 대비 + 게시물 사이 딜레이의 이유.
💬 이렇게 말하세요
써보면서 다들 느끼셨을 거예요 — 게시물 하나 받고, 한참 쉬고, 다음 걸 받죠. 답답하셨죠? 그거, 버그가 아니라 이 프로그램에서 제일 공들인 기능입니다. 인스타그램은 로그인 없는 요청을 아주 빡빡하게 제한해요. 빨리 받으면 몇 개 만에 차단당하고, 결과적으로 훨씬 느려집니다. 그래서 일부러 천천히 요청하는 겁니다. 자 — 프롬프트에 "요청 사이에 일부러 쉬어라"를 적은 분? (손 확인) 이게 오늘 제일 무거운 한 줄이었습니다. '느리다'는 불평은 누구나 해요. '일부러 느려야 한다'는 사양을 쓰는 것 — 그게 관찰이 명세가 되는 순간입니다. 수업 초반에 제가 시작 시간을 조별로 나눈 것도, 링크를 1~2개로 제한한 것도 전부 같은 이유였어요.
💡 강사 팁
오늘 수업 전체의 지적 클라이맥스. 수칙(슬라이드 7)—체험의 답답함—채점 기준이 한 줄로 꿰이는 순간이므로 충분히 시간을 쓸 것.
→ 넘어가며: "오늘 여러분이 뭘 얻었는지 정리하겠습니다."
