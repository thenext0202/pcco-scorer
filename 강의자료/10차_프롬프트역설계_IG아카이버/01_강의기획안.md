# 10차 강의 기획안 — 거꾸로 만들기: 한 방 프롬프트 역설계

> 버전: v1.1 (2026-07-29) — 제출 방식·분반 방식 확정, 모범답안·11차 시연 제외
> 강사: 정금구
> 형태: 진단 실습 강의 (120분)
> 대상 프로그램: **IG 아카이버** (인스타그램 캐러셀 이미지 아카이빙 데스크톱 앱)

---

## 1. 이 강의는 무엇이 다른가

지금까지의 강의는 **프롬프트 → 프로그램** 방향이었다. 이번에는 거꾸로 간다.

**완성된 프로그램을 먼저 쓰게 하고, 그 프로그램을 통째로 재현할 수 있는
"한 방 프롬프트" 하나를 써내게 한다.**

- 수강생에게 주는 것: `IG-Archiver.exe` 하나. **소스 코드는 주지 않는다.**
- 수강생이 내는 것: 프롬프트 텍스트 하나. 기준은 단 하나 —
  **"이 프롬프트만 받은 AI가, 오늘 써본 프로그램을 그대로 만들 수 있는가?"**

### 숨은 목적 (강사용)

제출된 프롬프트는 지금까지 배운 것이 실제로 몸에 붙었는지를 보여주는
**진단 데이터**다. 이걸 채점해서 **초급반 / 중급반**을 나누고, 이후 커리큘럼을
반별로 운영한다.

수강생에게는 "레벨 점검"이라는 사실을 숨기지 않되, 긍정적으로 프레이밍한다:
*"여러분이 어디까지 왔는지 확인하고, 딱 맞는 속도로 다음 단계를 진행하기 위한 시간"*.
시험이 아니라 **배치 상담 자료**라는 톤을 유지한다.

### 왜 이 방식이 진단에 좋은가

- 강의를 따라 치는 실습은 누구나 결과가 비슷하게 나온다. **백지에서 스스로
  명세를 쓰는 과제**는 실력 차이가 그대로 드러난다.
- 프롬프트 작성력의 본질 = **관찰 → 분해 → 명세** 능력. 코드를 안 보여주기
  때문에 암기·복붙이 불가능하고, 순수하게 이 능력만 측정된다.
- 산출물이 텍스트 하나라 **채점·비교·보관이 쉽다.** (프롬포트 채점 플랫폼과도
  자연스럽게 이어진다.)

## 2. 대상 프로그램 — IG 아카이버 요약

| 항목 | 내용 |
| --- | --- |
| 위치 | `D:\개발\인스타 캐러셀 아카이빙\ig_archiver` (배포: `dist\IG-Archiver.exe` 13.7MB) |
| 정체 | 인스타그램 공개 게시물 **링크를 붙여 넣으면 이미지만** 저장하는 Windows GUI 앱 |
| 특징 | 무로그인 · 영상 스킵 · 단일 exe 휴대용 · 캐러셀 순서 보존 |
| 구현 | Python + Tkinter + instaloader (수강생에게는 비공개) |

### 관찰 가능한 기능 지도 (채점 체크리스트의 원천)

수강생이 exe만 만져서 **발견할 수 있는 것**과 **추론해야 하는 것**을 구분해 둔다.
이 구분이 그대로 채점 기준의 난이도 층이 된다.

**층 1 — 쓰면 바로 보이는 것 (초급도 담아야 정상)**
1. 링크를 여러 줄 붙여 넣으면 이미지가 저장된다
2. 로그인 없이 된다
3. 영상(릴스)은 저장되지 않는다
4. 캐러셀이면 여러 장이 순서대로 저장된다
5. 저장 폴더를 바꿀 수 있다 / 시작·중지 버튼이 있다 / 진행 로그가 보인다

**층 2 — 결과물 폴더를 열어봐야 보이는 것 (관찰력 변별)**
6. 계정 아이디별 하위 폴더로 정리된다
7. 파일명 규칙: `날짜_시각_코드_번호.jpg` (캐러셀 순번이 파일명에 있다)
8. `manifest.json` — 게시물별 메타데이터(캡션·URL·파일 목록·장수)
9. `state.json` — 같은 링크를 다시 넣으면 **건너뛴다** (재실행 체험 필요)
10. 기본 저장 위치가 exe 옆 `Instagram아카이브` 폴더다

**층 3 — 실험하거나 추론해야 보이는 것 (중급 변별)**
11. `/p/` `/reel/` `/tv/` 등 여러 링크 형식 인식, 못 읽는 줄은 로그에 남기고 스킵
12. 같은 링크 중복 입력 시 한 번만 받는다
13. 게시물 사이에 일부러 **긴 딜레이**가 있다 (레이트리밋 회피 — "왜 느리지?"를 파고들었는가)
14. 연속 실패 시 자동 중단 / 차단되면 기다려야 한다
15. `파일에서 불러오기` 기능, 마지막 저장 폴더 기억, USB로 옮겨도 동작(휴대용)

층 3의 13·14번(레이트리밋)은 **"불편함을 사양으로 읽어내는 눈"**을 측정하는
핵심 문항이다. 초급은 "느리다"고 불평하고, 중급은 "차단 회피용 딜레이를 넣어라"고 쓴다.

## 3. 수업 프레임워크 — 역설계 3단계 "쓰다 · 뜯다 · 적다"

기존 회차들처럼 기억에 남는 프레임워크 하나로 수업을 관통시킨다.

| 단계 | 이름 | 하는 일 | 결과물 |
| --- | --- | --- | --- |
| 1 | **쓰다** (Use) | 사용자로서 프로그램을 충분히 써 본다 | 체험 |
| 2 | **뜯다** (Decompose) | 기능·데이터·예외를 목록으로 분해한다 | 관찰 메모 |
| 3 | **적다** (Specify) | 분해한 것을 하나의 프롬프트로 재조립한다 | 한 방 프롬프트 |

핵심 메시지: **"좋은 프롬프트는 글재주가 아니라 관찰의 양이다."**
2단계(뜯다)를 건너뛰고 3단계로 직행하는 사람의 프롬프트가 어떻게 빈약해지는지를
수업 후반 셀프 체크에서 스스로 확인하게 한다.

## 4. 120분 타임라인

| 시간 | 구간 | 내용 |
| --- | --- | --- |
| 00–10 (10분) | 오프닝 | 오늘은 만들지 않는다 — 거꾸로 간다. 역설계 3단계 소개, 제출물과 기준 안내 |
| 10–20 (10분) | 시연·배포 | 강사 시연(링크 2개 → 저장까지), exe 배포, **사용 수칙** 공지 (§6 리스크 대책) |
| 20–50 (30분) | **쓰다·뜯다** | 자유 체험 + 관찰 메모 작성. 강사는 순회하며 "결과 폴더 열어봤어요?" 수준의 힌트만 |
| 50–55 (5분) | 작성 브리핑 | 프롬프트 요건 재확인. **작성 요령은 가르치지 않는다** (진단 오염 방지) — 기준 한 줄만 반복 |
| 55–100 (45분) | **적다** | 한 방 프롬프트 작성. 이 시간 동안 **AI 사용 금지** (§6-4) |
| 100–110 (10분) | 제출·셀프 체크 | 제출 후 관찰 체크리스트 공개 → 각자 "내가 놓친 것" 확인 (답안 공유는 금지) |
| 110–120 (10분) | 클로징 | 분반 안내 예고(희망 반 조사 + 강사 검토 후 추후 공지) + 다음 커리큘럼 소개 |

시간이 밀리면 체험 30분을 25분으로, 셀프 체크를 5분으로 줄인다. 작성 45분은 지킨다.

## 5. 채점과 분반 (강사용)

### 5-1. 채점 4축 (각 25점, 총 100점)

| 축 | 이름 | 무엇을 보나 | 초급 답안의 전형 | 중급 답안의 전형 |
| --- | --- | --- | --- | --- |
| A | **기능 관찰** | §2 기능 지도 중 몇 개를 담았나 | 층 1만 나열 | 층 2까지 + 층 3 일부 |
| B | **명세 구체성** | 폴더 구조·파일명 규칙·JSON 파일을 형식 수준까지 적었나 | "폴더에 저장해줘" | "계정별 폴더, 파일명은 날짜_시각_코드_순번" |
| C | **예외·제약 인식** | 중복·오류 줄·재실행 스킵·레이트리밋·차단 대응 | 언급 없음 | 딜레이 필요성, 실패 시 중단 규칙까지 명시 |
| D | **프롬프트 구조** | 목표/요구/제약/완료 기준의 구획, 검증 조건 포함 여부 | 통짜 문단 하나 | 섹션 구분 + "완성 판정 기준"까지 제시 |

### 5-2. 분반 방식 (확정)

점수 컷으로 자동 분반하지 않는다. **두 입력을 함께 반영해 결정한다:**

1. **수강생 본인 요청** — 제출 시 희망 반(초급/중급)을 함께 받는다
2. **강사 의견** — 채점 결과(4축 점수 + 층별 관찰 수준)를 근거로 한 판단

점수 구간은 강사 판단의 **참고 지표**로만 쓴다:

- **~49점**: 층 1 나열 수준 → 초급 권장
- **50~74점**: 층 2 관찰 + 부분적 구조화 → 중급 권장
- **75점~**: 층 3 추론 + 제약·검증 기준 포함 → 중급 (심화 트랙 후보)

분반 결과는 **추후 공지**하며, 본인 희망과 강사 판단이 어긋나는 경우 개별 상담으로 조율한다.
목표는 정확한 측정이 아니라 **비슷한 속도끼리 묶는 것**.

### 5-3. 제출 방식 (확정 — 2가지 병행)

1. **프롬포트 채점 플랫폼 10차 채점 모드** — 즉시 채점 + 리더보드
   (CLAUDE.md "채점 모드 추가 14단계" 절차로 수업 전 구축)
2. **프롬프트 원문 제출** — 텍스트 파일/메시지로 별도 제출 (강사 보관·정밀 검토용
   + 플랫폼 장애 시 폴백)

수업에서는 둘 다 하게 한다: 플랫폼에 넣어 점수를 받고, 원문도 제출.
분반 판단은 플랫폼 점수가 아니라 **강사의 원문 검토**를 기준으로 한다.

## 6. 리스크와 대책 ★ 수업 성패가 여기 달림

### 6-1. 교실 공용 IP 레이트리밋 (최대 리스크)

이 앱은 익명 요청이라 한도가 빡빡하다(30초당 1~2회 수준, 게시물 간 8~15초 딜레이 내장).
**한 교실 20명이 같은 와이파이(=같은 공인 IP)로 동시에 돌리면 거의 확실히 차단된다.**

대책 (전부 적용):
- **1인당 링크 1~2개만** 넣게 한다. 수업 수칙으로 못 박는다
- **검증된 공개 게시물 링크 목록을 강사가 미리 나눠준다** (각자 다른 링크를 받도록
  번호 배정 — 같은 게시물 중복 요청 방지). 개발기록 §4-1의 테스트 게시물 유형 참고:
  이미지 캐러셀 1건 + "영상 섞인 캐러셀" 1건 조합이 관찰 학습에 가장 좋다
- 시작 타이밍을 분단위로 **분산**시킨다 (조별로 2~3분 간격)
- **휴대폰 핫스팟** 사용을 공식 안내한다 (IP 분산 효과가 가장 확실)
- 차단에 대비해 **강사가 미리 받아 둔 완성 결과 폴더**(Instagram아카이브 샘플)를
  배포 zip에 함께 넣는다 → 다운로드가 막혀도 층 2 관찰(폴더 구조·JSON)은 전원 가능
- "요청 거부" 로그가 뜨면 재시도 금지, 관찰 단계로 넘어가라고 안내

### 6-2. exe 실행 경고

서명 없는 exe라 SmartScreen "알 수 없는 게시자" 경고와 일부 백신 오탐이 나올 수 있다.
슬라이드에 **"추가 정보 → 실행" 스크린샷**을 넣어 사전 안내. 수업 전 강사 PC 외
**타 PC 1대에서 실행 검증** (개발기록 §9: 파이썬 없는 PC 실측 미검증 상태 — 이번에 해소).

### 6-3. Windows 전용

맥 수강생은 실행 불가. 사전 조사 후 해당자는 **윈도우 수강생과 2인 1조**로 묶고,
관찰 메모와 프롬프트는 **각자** 작성하게 한다 (진단은 개별 유지).

### 6-4. 진단 오염

- 작성 45분간 **AI 도구 사용 금지** (측정 대상이 본인 능력이므로). 체험·관찰 단계는 자유
- 프롬프트 **서로 공유 금지**, 셀프 체크 때도 체크리스트만 공개하고 답안 낭독은 안 함
- 관찰 체크리스트는 **제출 이후에만** 공개 (미리 주면 관찰력 측정이 무너짐)

### 6-5. 기타

- 비공개·삭제 게시물 링크를 넣는 사고 → 배부 링크 목록만 쓰게 하면 자연 차단
- 배포 zip은 **윈도우에서 압축** (리눅스 zip 한글 파일명 깨짐 — 9차에서 확인된 함정)
- 저장 폴더를 Program Files 등에 두는 사고는 앱이 알아서 바탕화면 폴백 (개입 불요)
