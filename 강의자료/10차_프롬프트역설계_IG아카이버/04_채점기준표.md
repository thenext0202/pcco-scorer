# 10차 채점 기준표 — 한 방 프롬프트 루브릭 (강사용)

> 버전: v1.0 (2026-07-29) · **수업 전 비공개** (수강생에게는 제출 후 §5 셀프 체크리스트만 공개)
> 용도: ① 강사 원문 검토(분반 판단 기준) ② 플랫폼 10차 채점 모드 시스템 프롬프트의 원천

## 0. 채점 대상과 대원칙

제출물: **"이 프롬프트만 받은 AI가 IG 아카이버를 그대로 만들 수 있는가"**를 기준으로 쓴
프롬프트 1건.

- **행동 명세를 채점한다, 구현 기술을 채점하지 않는다.** 수강생은 exe만 만졌으므로
  Python/Tkinter/instaloader를 알 수 없다. 기술 스택 언급은 **가점도 감점도 아니다.**
  "무엇이 어떻게 동작해야 하는가"를 얼마나 담았는지만 본다.
- 같은 내용을 다른 말로 썼어도 인정한다. (예: "다시 실행하면 받은 건 건너뛴다" =
  state.json 언급 없이도 9번 기능 관찰로 인정)
- 총점 100 = A 기능 관찰 25 + B 명세 구체성 25 + C 예외·제약 인식 25 + D 프롬프트 구조 25

---

## 1. A축 — 기능 관찰 (25점)

기획안 §2 기능 지도의 15개 항목. **프롬프트에 담겼으면 득점** (관찰 메모가 아니라
프롬프트 기준 — 관찰했어도 프롬프트에 안 적었으면 AI는 모른다).

**층 1 — 각 1점 (5점)** · 못 담으면 초급 신호

| # | 항목 | 인정 예 |
| --- | --- | --- |
| 1 | 링크 여러 줄 입력 → 이미지 저장 | "링크를 한 줄에 하나씩 붙여 넣으면" |
| 2 | 로그인 불필요 | "로그인 없이", "계정 연동 없이" |
| 3 | 영상은 저장 안 함 | "릴스/영상은 건너뛴다" |
| 4 | 캐러셀 여러 장이 순서대로 | "여러 장이면 전부, 순서 유지" |
| 5 | 저장 폴더 선택 / 시작·중지 / 진행 로그 | GUI 구성 요소 언급 (3개 중 2개 이상 = 1점) |

**층 2 — 각 2점 (10점)** · 결과 폴더를 열어봐야 보이는 것

| # | 항목 | 인정 예 |
| --- | --- | --- |
| 6 | 계정 아이디별 하위 폴더 | "계정별로 폴더를 나눠" |
| 7 | 파일명 규칙 (날짜_시각_코드_순번) | 구성 요소 2개 이상 언급 (완전 규칙은 B축에서 추가 득점) |
| 8 | manifest.json (게시물 메타데이터 기록) | "게시물 정보를 JSON으로 남긴다" |
| 9 | 재실행 시 받은 게시물 건너뜀 (state.json) | "이미 받은 링크는 다시 안 받는다" |
| 10 | 기본 저장 위치 = 실행 파일 옆 폴더 | "exe 옆에 폴더가 생긴다" |

**층 3 — 각 2점 (10점)** · 실험·추론해야 보이는 것 (중급 변별)

| # | 항목 | 인정 예 |
| --- | --- | --- |
| 11 | 여러 링크 형식 인식 + 못 읽는 줄은 로그 남기고 스킵 | "잘못된 줄은 무시하되 알려준다" |
| 12 | 중복 링크는 한 번만 | "같은 링크가 여러 개면 하나로" |
| 13 | 게시물 사이 **의도적 딜레이** (차단 회피) | "요청 사이 몇 초씩 쉬어라" ← 핵심 문항 |
| 14 | 연속 실패 시 자동 중단 / 차단 시 대기 안내 | "계속 실패하면 멈춰라" |
| 15 | 파일 불러오기 / 폴더 기억 / USB 휴대성 중 2개 이상 | 부가 기능 관찰 |

> **13번 특별 주석**: "느리다"를 불평이 아니라 **사양**("일부러 천천히 요청해야 한다")으로
> 옮겨 적었는가. 층 3에서 가장 무거운 신호이며, 분반 판단 시 이 항목을 별도로 표시해 둘 것.

## 2. B축 — 명세 구체성 (25점)

관찰한 것을 **AI가 재량 없이 구현할 수 있는 수준**까지 적었는가. 5개 부문 × 5점.
각 부문: 0 = 언급 없음 / 2~3 = 방향만 ("알아서 정리") / 5 = 형식·규칙 수준.

| 부문 | 5점 기준 |
| --- | --- |
| B1 저장 구조 | 루트 폴더명 + 계정별 하위 폴더 구조를 그림이나 예시로 제시 |
| B2 파일명 규칙 | `날짜_시각_게시물코드_순번.jpg` 형태를 예시 파일명 수준으로 명시 |
| B3 데이터 파일 | manifest·state 역할 구분 + 담길 필드(캡션, URL, 파일 목록 등) 열거 |
| B4 화면(GUI) 명세 | 입력창·폴더 선택·시작/중지·로그 영역의 배치와 동작을 재현 가능하게 서술 |
| B5 산출물 정의 | "설치 없이 실행되는 Windows 프로그램(단일 실행 파일)" 등 전달 형태 명시 |

## 3. C축 — 예외·제약 인식 (25점)

정상 흐름 밖을 다뤘는가. 5개 부문 × 5점.
각 부문: 0 = 언급 없음 / 3 = 현상 인지 / 5 = 대응 규칙까지 명시.

| 부문 | 5점 기준 |
| --- | --- |
| C1 요청 한도 | 차단 위험 인지 + 딜레이·속도 제한을 **수치나 규칙**으로 지시 |
| C2 실패 처리 | 잘못된 링크·비공개 게시물·연속 실패 시의 동작(스킵/로그/중단)을 지시 |
| C3 중복·재실행 | 중복 입력 처리 + 재실행 시 이어받기 규칙을 지시 |
| C4 영상 처리 | 영상 스킵 + "전부 영상인 게시물"일 때의 동작까지 지시 |
| C5 중단·안전 | 중지 시 안전하게 멈추는 규칙, 저장 폴더에 쓸 수 없을 때의 대비 등 |

> A축과의 관계: A는 "언급했는가"(관찰), C는 "규칙으로 만들었는가"(설계).
> 같은 소재가 양쪽에서 득점할 수 있으며 이는 의도된 설계다.

## 4. D축 — 프롬프트 구조 (25점)

R-PCCO(1차 강의)가 몸에 붙었는지 보는 축. 5개 부문 × 5점.

| 부문 | 5점 기준 | R-PCCO 대응 |
| --- | --- | --- |
| D1 역할·목적 | AI에게 역할을 주고, 프로그램의 존재 이유(누가 왜 쓰나)를 밝힘 | R·P |
| D2 맥락 | 사용 환경(Windows PC, 비개발자 사용자 등)을 밝힘 | C |
| D3 구획화 | 기능/규칙/제약이 섹션으로 구분됨 (통짜 문단 = 0~2점) | — |
| D4 제약 명시 | 하지 말 것(로그인 요구 금지, 영상 저장 금지 등)이 별도로 있음 | C(제약) |
| D5 완료 기준 | "이렇게 되면 완성" 검증 시나리오나 수용 조건 제시 | O |

## 5. 수강생 공개용 — 셀프 체크리스트 (제출 후 배포)

> 아래만 잘라서 공개한다. 점수·배점·축 구조는 공개하지 않는다.

```
■ 내 프롬프트에 이게 들어 있었나? — 기능 15
□ 링크 여러 줄 입력          □ 로그인 불필요           □ 영상 저장 안 함
□ 캐러셀 순서 보존           □ 폴더선택·시작·중지·로그   □ 계정별 하위 폴더
□ 파일명 규칙                □ 게시물 정보 JSON 기록     □ 재실행 시 건너뛰기
□ 기본 저장 위치(exe 옆)     □ 잘못된 줄 처리           □ 중복 링크 처리
□ 요청 사이 딜레이(차단 회피) □ 연속 실패 시 중단        □ 파일 불러오기·폴더 기억·휴대성

■ 스스로에게 묻기 — 4가지
□ 폴더 구조와 파일명을, 예시를 들어 그대로 재현할 수 있게 적었나?
□ 잘 될 때 말고 "안 될 때" 어떻게 할지를 적었나?
□ 프로그램이 왜 느린지 생각해 봤나? 그걸 사양으로 옮겨 적었나?
□ "이렇게 되면 완성"이라는 판정 기준을 적었나?
```

## 6. 분반 판단 가이드 (강사 전용)

최종 분반 = **수강생 희망 + 아래 강사 판단**. 점수는 참고 지표.

| 참고 구간 | 전형적 답안 모습 | 권장 |
| --- | --- | --- |
| ~49 | 층 1 나열, 통짜 문단, 예외 언급 없음 | 초급 |
| 50~74 | 층 2 일부 관찰, 부분 구획화, 파일명·데이터 파일 중 하나 이상 명세 | 중급 |
| 75~ | 층 3 추론(특히 13번), 제약 규칙화, 완료 기준 제시 | 중급 (심화 후보) |

정성 신호 (점수와 별개로 기록):
- **13번(딜레이) 득점 여부** — 중급 판단의 단독 근거가 될 수 있는 가장 무거운 신호
- D5(완료 기준) 존재 여부 — 검증 사고의 유무
- 경계선(45~55점)은 원문을 다시 읽고 결정. 희망 반과 어긋나면 개별 상담

## 7. 플랫폼 채점 모드 이식 메모

- 시스템 프롬프트에 이 문서의 A~D 배점표를 그대로 옮기되, **기능 15항목의 "인정 예"를
  판정 기준으로 포함**시킬 것 (표현이 달라도 의미가 같으면 인정하도록 명시)
- 기술 스택 언급 무가점 원칙, "행동 명세만 채점" 원칙을 시스템 프롬프트 서두에 명시
- 기존 모드와 달리 **improved_example을 완전한 모범답안으로 만들지 말 것** — 수업 중
  재제출로 답을 캐낼 수 있다. 개선 피드백은 "빠진 범주"(예: "예외 상황 처리가 없다")
  수준으로 제한하고, 구체 기능명(manifest.json 등)은 노출 금지
- 리더보드 점수는 참고용임을 결과 화면에 명시 (분반은 강사 원문 검토 기준)
