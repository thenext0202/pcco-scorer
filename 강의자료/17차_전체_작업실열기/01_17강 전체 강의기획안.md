### ★ 제작·진행 원칙 (위반 금지)

1. **강제하지 않는다** — "이렇게 해야 한다"가 아니라 "이걸 빠뜨리면 이렇게 된다". 참고 카드는 참고. 순회에서 강사가 하는 건 **질문**뿐("상태 몇 칸이에요?" "핵심 과업 몇 탭?" "폰에서 열어 봤어요?").
2. **합반 용어 규칙** — 설계 용어는 중급 것(지도 3층·화면 해부 4단·상태·이동), 지침 용어는 1·2차 것(I-MRKO). 초급 전용 용어는 한 줄 대응. "아시죠?" 금지. 어느 반이든 처음 듣는 사람이 있다.
3. **코드를 읽지 않는다** — Claude Code 화면이 떠 있어도 폴더 트리·화면·주소만. 설명 금지.
4. **한 줄 복습, 새 것은 길게** — 9차 5요소·12차 지도 3층·14차 렌즈·상태·원칙 ③④·15차 지침·7차 PWA 5요소는 **한 줄 소환**. 길게 가는 것은 **"왜 github.io" · "UX란" · "설계 질문 5"**.
5. **"종료·수료" 금지 / OT 프레이밍** — "두 반이 가져온 것을 오늘 합친다. 앞으로 매 강의가 이 작업실에서 시작한다."
6. **무자료 내성** — 가져올 것 없음. 설계 카드는 수업 중 10분에 쓴다.

## 2. 왜 이 강의인가

### 2-1. 템플릿을 걷어내는 이유
v1은 실패하지 않게 설계하느라 CLAUDE.md 템플릿·과업 문장·합격 기준·공용 뼈대로 수강생을 레일 위에 올렸다. 그러면 배우는 건 "시키는 대로 하기"지 UX가 아니다. UX는 **내가 결정한 것**이 남의 손에서 어떻게 겪어지는지를 보는 일이라, 결정이 없으면 배울 것도 없다. 그래서 소재만 묶고(업무용 일정체크 캘린더) **설계는 각자**가 한다 — 월 보기냐 주 보기냐, 체크를 어떻게 하나, 종류를 몇 개 두나, 어디서 어디로 가나. 강사는 결정을 대신하지 않고 **빠뜨린 것을 묻는다**.

### 2-2. 왜 github.io인가 (강의 1의 논지)
서버 없이, 돈 없이, 따로 붙일 것 없이 **주소가 생기는 유일한 무대**. push 한 번이면 주소가 살고(9차 "push가 곧 배포"), 고쳐서 push하면 주소에서 바뀐다(맥박). 9차 5요소 중 몸·기억·무대·맥박이 전부 돌아오고 **창고만 없다** — 오늘 데이터는 내 폰 주머니(16차 localStorage)에만 남는다. 그래서 수업 끝에 "폰에서 열면 일정이 없다"가 다음 강의의 입구가 된다. 그리고 결정적으로: **주소가 있어야 남이 쓴다. 남이 써야 UX가 보인다.** github.io는 배포 기술이 아니라 UX를 배우기 위한 조건이다.

### 2-3. UX란 무엇이고 왜 중요한가 (강의 2의 논지)
14차 렌즈 — UI는 생김새(뼈대+옷), UX는 겪는 것(움직임+상태+이동). "예쁜데 불편한 앱"과 "못생겼는데 편한 앱"이 둘 다 있는 이유. AI 시대에 왜 중요한가: **AI는 화면을 잘 만들고, 사용감은 못 만든다.** Claude Code에게 캘린더를 시키면 그럴듯한 화면이 1분 만에 뜨지만, 빈 달에 안내가 없고, 저장됐는지 알 수 없고, 다음 달 갔다가 돌아오는 길이 없다 — 14차가 "AI가 가장 많이 빠뜨리는 게 상태와 이동"이라고 말한 그대로. 사용감은 **시킨 사람만** 얻는다. 그리고 시키려면 먼저 **무엇을 겪게 할지 결정**해야 한다 — 그게 설계다. 또 하나: **만든 사람은 자기 앱을 못 본다.** 어디를 눌러야 하는지 이미 아니까. 그래서 손님처럼 누르고, 그래서 남(강사)이 누른다.

### 2-4. 무엇을 설계해야 하나 (강의 3의 논지 — 자유도 안의 다섯 질문)
설계를 양식으로 주면 템플릿이 된다. 대신 **빠뜨리면 반드시 티가 나는 다섯 질문**만 준다: ① 쓰는 사람 한 명(나? 팀? 그 사람은 하루에 몇 번 여나) ② 핵심 과업 하나(이 앱으로 가장 자주 하는 일 — "오늘 할 일 체크"? "다음 주 일정 넣기"?) ③ 상태 4칸(비어 있을 때·기다릴 때·됐을 때·안 됐을 때 화면에 뭐가 보이나) ④ 이동과 돌아오는 길(어디서 어디로, 오늘로 어떻게 돌아오나) ⑤ 폰 먼저(엄지로 되나, 44px). 답은 각자. 답이 있으면 Claude Code에 시킬 수 있고, 없으면 AI가 멋대로 정한다.

### 2-5. 왜 PWA인가, 왜 마지막인가
7차에서 배운 그대로 — 주소를 홈 화면에 설치하면 "내 앱"이 된다. 수강생의 결과물이 "주소"보다 "폰에 깔린 앱"일 때 완결감이 다르다. 다만 서비스워커가 페이지를 캐시해 "고치고 push하면 바뀐다"를 가리므로 **설치는 네 번째 단계**, 고치기 반복이 끝난 뒤.

## 3. 프레임워크 (강의 내용 — 모든 자료에서 이 문구 그대로)

### 3-1. 왜 github.io인가 (슬라이드 04·05)

| 9차 5요소 | 오늘 | 한 줄 |
|---|---|---|
| 몸 | 내 폴더(3단계) | 작업실은 폴더 하나 — 12차 "파일에는 자리가 있다" |
| 기억 | GitHub 저장소 | 노트북을 바꿔도 남는다 — "앞으로 매 강의가 여기서" |
| 무대 | `아이디.github.io/내-캘린더` | 서버 없이·돈 없이·따로 붙일 것 없이 주소 |
| 맥박 | push → 1~3분 → 주소가 바뀜 | 오늘 여러 번 겪는다 |
| ~~창고~~ | 없음 — 데이터는 주머니(localStorage) | "폰에서 열면 일정이 없다" → 다음 강의 |

**결론 한 줄**: 주소가 있어야 남이 쓴다 → 남이 써야 UX가 보인다. **사람이 직접 해야 하는 2가지**: `gh auth login` 브라우저 로그인 / 저장소 설정 → Pages 켜기(Claude Code가 못 켜면).

### 3-2. 폴더 3단계 (슬라이드 06 — 12차 지도 3층 회수, 참고 카드 A)

| 단계 | 12차 이름 | 예시(참고일 뿐) | 왜 |
|---|---|---|---|
| 1 루트 | 지형 | `index.html` · `manifest.json` · `sw.js` · `CLAUDE.md`(권장) | 주소가 가리키는 곳. PWA 서류(manifest·sw)는 여기 |
| 2 폴더 | 골목 | `css/` · `js/` · `icons/` (`data/` 등 자유) | 옷·움직임·그림을 가른다 — 14차 "옷 바꾸다 뼈 부러지지 않게" |
| 3 파일 | 문패 | `style.css` · `app.js` · `icon-192.png` … | 이름·개수 자유. 한 파일에 한 역할 |

"3단계면 충분하고, 3단계는 있어야 한다" — 한 폴더에 다 쏟으면 AI가 다음 과업에서 엉뚱한 파일을 건드린다.

### 3-3. UX 렌즈 (슬라이드 08·09 — 14차 문구 그대로, 바닥부터)

| | UI = 생김새 | UX = 겪는 것 |
|---|---|---|
| 14차 | 뼈대 + 옷 | 움직임 + 상태 + 이동 |
| 캘린더에서 | 색·글꼴·둥근 모서리·분위기 | 오늘이 1초 안에 보이나 · 체크가 몇 탭이나 · 저장됐는지 아나 · 돌아오는 길이 있나 |
| 누가 만드나 | AI가 잘 만든다 | **사람이 시켜야 생긴다** |
| 오늘 | 자유(한 문장이면 바뀜) | 설계 질문 5로 결정 → 시킨다 |

**AI가 가장 많이 빠뜨리는 셋**: 비어 있을 때 · 안 됐을 때 · 돌아오는 길. 손들기 "상태 4칸 다 있는 사람?"이 ≈0인 것이 오늘의 증명.

### 3-4. 설계 질문 5 (슬라이드 10·11 — 02 UX 설계 카드의 본체)

| # | 질문 | 빠뜨리면 | 답의 예(참고) |
|---|---|---|---|
| ① | **쓰는 사람 한 명** — 누가, 하루 몇 번, 어디서(폰/PC) 여나 | AI가 "모두를 위한 앱"을 만든다 = 누구에게도 안 맞는 앱 | "나. 아침에 한 번, 퇴근 전 한 번. 폰." |
| ② | **핵심 과업 하나** — 이 앱으로 가장 자주 하는 일 | 모든 기능이 같은 크기 → 가장 자주 하는 일이 3탭 | "오늘 일정에 체크 표시" / "다음 주 마감 넣기" |
| ③ | **상태 4칸** — 비어 있을 때 · 기다릴 때 · 됐을 때 · 안 됐을 때 | 빈 화면이 고장처럼 보이고, 저장됐는지 몰라 두 번 누른다 | 빈 날 "오늘 일정 없음" / 체크하면 1초 초록 / 제목 없이 저장 거절 |
| ④ | **이동과 돌아오는 길** — 어디서 어디로, 오늘로 어떻게 | 다음 달 갔다가 못 돌아온다 | 상단 '오늘' 버튼 1탭 |
| ⑤ | **폰 먼저** — 엄지로 되나, 누르는 건 44px | PC에선 되는데 폰에서 깨진다 | 7열이 가로 스크롤 없이 · 체크 박스 44px(채점기 실물) |

"다섯 답이 있으면 AI에게 시킬 수 있고, 없으면 AI가 멋대로 정한다." 답은 **각자** — 월 보기든 주 보기든, 체크를 어떻게 하든.

### 3-5. 손님 모드 (슬라이드 13 — 실습 ③)
규칙 하나: **"아는 길로 가지 않는다. 화면이 알려주는 길로만 간다."** 내 폰에서 내 주소를 열고 **②의 핵심 과업**을 처음 쓰는 사람처럼 해 본다. 세는 것: 탭 수 · 멈칫한 곳 · 됐는지 화면이 말했나. 관찰 → 고칠 것 3패턴: 멈칫 → 보이지 않는 것(상태·안내) / 헤맴 → 이름·위치(이동) / 확인 불가 → 피드백 없음(상태). 고치는 법: Claude Code에 **한 가지만** 시키고 push → 폰 새로고침 → 다시 손님. "손님인 척해도 주인은 주인 — 마지막엔 강사가 누른다."

### 3-6. 막힘 해결 3단계 (슬라이드 07 · 08 가이드 2쪽) — v1.2 그대로
① 에러 그대로 복사 ② "내 OS / 하려던 것 / 에러 + 내가 직접 해야 하는 게 있으면 그것부터, 한 번에 한 단계만" ③ 한 단계만 → 확인 → 안 되면 ①. 3분 → 세팅 창구. 자유도를 주는 수업일수록 더 필요하다.

### 3-7. PWA 5요소 (슬라이드 16 — 7차 복습 한 장)
화(화면 — 폰 세로 먼저) · 정(정보 — manifest: 이름·아이콘·색) · 오(오프라인 — sw.js) · 저(저장 — localStorage, 오늘의 주머니) · 배(배포 — HTTPS = github.io). "주소를 앱으로 만들어 홈 화면에 설치해 줘 — manifest와 서비스워커를 추가해" 한 줄이면 Claude Code가 한다. **설치는 고치기가 끝난 뒤** — 설치 후엔 새로고침이 느리게 반영된다(캐시).

### 3-8. CLAUDE.md — 권장 (슬라이드 06 하단 · 참고 카드 A)
"폴더에 이 한 장을 두면 매 과업마다 다시 말하지 않아도 된다" — 15차 지침의 Claude Code판, 6차 "AI한테 한 장". 예시 한 장(정체성·임무·규칙·구조·화면·데이터·출력)을 참고 카드로. **안 써도 된다.** 쓰는 사람은 설계 질문 5의 답을 `## 화면`·`## 규칙`에 옮기면 그게 곧 지침.

## 5. 실습 설계 — 강사는 묻기만 한다

### 5-1. ① 작업실 열기 (14분)
폴더 3단계(참고 카드 A 예시 — 이름 자유) → `claude` 실행 → `gh auth status`. CLAUDE.md는 **권장**: 참고 카드 A의 예시를 복사해 이름·종류만 바꾸면 끝, 안 써도 됨. 막히면 3단계(3분) → 창구. 순회에서 "폴더 몇 단계예요?"만.

### 5-2. ② 설계 → 만들기 → 주소 (20분)
02 카드 질문 5에 한 줄씩(10분). 시키기는 **카드를 그대로 읽어 주는 것**으로 충분 — "쓰는 사람은 ___, 핵심 과업은 ___, 상태는 ___, 이동은 ___, 폰 먼저. 이대로 업무 일정체크 캘린더 v1을 만들어. 파일은 폴더 3단계로." CLAUDE.md에 옮긴 사람은 "CLAUDE.md대로 v1"로 끝. 로컬 확인 → push·Pages·주소(사람이 직접 하는 2가지는 Claude Code가 짚어 준다) → 카드에 주소 적기. **86분까지 전원 주소.** 순회 질문: "핵심 과업이 뭐예요?" "빈 달엔 뭐가 보여요?" "주소 떴어요?"

### 5-3. ③ 손님 테스트 → 고치기 (32분, 바퀴 자유)
내 폰에서 내 주소 → 핵심 과업을 손님 모드로 → 세기(탭·멈칫·확인) → 고칠 것 하나 → "___만 고쳐. 다른 건 건드리지 마" → push → 폰 새로고침 → 다시 손님. 2~3바퀴 도는 사람도, 1바퀴에 UI 한 문장 얹는 사람도 OK. 순회 질문: "몇 탭?" "어디서 멈칫?" "됐는지 화면이 말했어요?" "push했어요?" 기록이 전부 "없음" → "화면이 알려줬나요, 아셨나요?" 형용사로 시키는 사람 → "'알기 쉽게'를 숫자로 하면요?"

### 5-4. ④ 앱으로 만들기 → 설치 → 제출 (12분)
"이 주소를 앱으로 만들어 홈 화면에 설치할 수 있게 — manifest.json과 sw.js를 추가해. 아이콘은 icons/에" → push → 폰 브라우저에서 '홈 화면에 추가'. 설치 후 고치려면 캐시 때문에 느리게 반영됨을 알려준다(참고 카드 B). ③에 머무는 사람은 머문다. **슬랙 제출**: 주소 + 고친 것 한 줄 + (설치했으면) 캡처.

### 5-5. 긴급 경로 (08 가이드 2쪽 + 참고 카드 B 하단)
순서: 3단계 3분 → 세팅 창구 3분 → A(Claude Code 안 뜸 → claude.ai에 카드 다섯 답 + "단일 HTML 캘린더" → 다운로드 → 폴더) / B(gh 안 됨 → 강사 공용 저장소 `17-class` 하위 폴더에 파일을 슬랙으로 보내 강사가 push → `강사주소/17-class/내이름/`) / C(노트북 없음 → 강사 예비).

### 5-6. 강사 즉석 점검 (7분)
제출 링크 3개(지원자 우선). 강사 폰 미러링. **그 사람의 핵심 과업**(카드 ②)을 손님 모드로 수행하며 탭·멈칫을 소리 내어. 형식 "___에서 멈칫 → 어떻게 고쳤나 → 잡혔나?" 칭찬 1·보완 1. UI는 한 마디("색은 취향, 멈칫은 설계"). 나머지는 수업 후 07 §C로 전수 확인·회신.

## 8. 리스크 대응표

| 리스크 | 대응 |
|---|---|
| **자유도 → 범위 폭발**("구글 캘린더 연동", "알림", "팀 공유") | 질문 ①②로 되돌린다 — "쓰는 사람이 나 한 명이면 팀 공유는 오늘 아님", "핵심 과업 하나에 들어가요?" 공유·알림은 창고가 필요 → 다음 강의 |
| **설계 카드가 비어 있는데 바로 만들기 시작** | 순회 질문 "핵심 과업이 뭐예요?"에 답 못 하면 카드로. 카드 없이 만든 결과가 곧 강의 2의 증명이라 막지는 않는다 |
| **세팅 안 된 채 옴** | 08 가이드 일주일 전 + 전날 리마인드 + 시작 전 10분 창구 + 3단계. 당일도 안 되면 긴급 경로 |
| **Claude Code가 gh로 저장소·Pages 못 만듦** | 예정된 코스 — "내가 직접 해야 하는 게 있으면 그것부터" 한 줄이 사람 몫(로그인·Pages 클릭)을 짚게 함. 참고 카드 B에 두 줄 |
| **같은 막힘 3명 이상** | 강사 화면에 띄워 다같이 3단계 1회(3분). 07 §C 기록 |
| **날짜 계산 오류**(1일 요일·31일) | 손님 테스트에서 걸린다. "오늘이 목요일 맞아요?" 한 마디 |
| **UI만 계속 바꿈** | "색은 취향, 멈칫은 설계" — 손님 테스트 기록 보여달라고 |
| **손님 모드가 주인 모드로** | "화면이 알려줬나요, 아셨나요?" + 즉석 점검이 잡아 준다 + 선택 과제 ② |
| **설치 후 고쳤는데 안 바뀜** | 캐시 — 참고 카드 B. 설치는 마지막이라고 세 번 말한다(슬라이드 03·13·14) |
| **②까지밖에 못 감** | 그것도 결과물(주소). 제출은 주소만 필수. ③④는 선택 과제 |
| 초급반 UX 처음 | 강의 2는 복습 표제지만 바닥부터. 내 앱에 바로 대보니 추상적이지 않다 |
| 중급반 "내 앱으로" | 소재는 캘린더 — "질문 5는 소재를 안 가립니다. 내 앱은 선택 과제 ⑥" |
