## 3. 핵심 정의 (모든 자료에서 이 문구 그대로)

**왜 github.io** — 서버 없이·돈 없이·따로 붙일 것 없이 주소. 9차 5요소 중 몸(폴더)·기억(GitHub)·무대(github.io)·맥박(push → 주소가 바뀜) 회수, **창고 없음**(주머니 localStorage). "주소가 있어야 남이 쓴다 → 남이 써야 UX가 보인다." 사람이 직접 하는 2가지 = gh auth login 브라우저 로그인 / 저장소 설정 → Pages.

**폴더 3단계** — 루트(지형) → 폴더(골목) → 파일(문패). "3단계면 충분하고, 3단계는 있어야 한다 — 한 폴더에 다 쏟으면 AI가 다음 과업에서 엉뚱한 파일을 건드린다."

**UX 렌즈(14차 그대로)** — UI = 생김새(뼈대+옷) / UX = 겪는 것(움직임+상태+이동). "AI는 화면을 잘 만들고 사용감은 못 만든다 — 사용감은 시킨 사람만 얻는다." AI가 가장 많이 빠뜨리는 셋 = 비어 있을 때·안 됐을 때·돌아오는 길. "만든 사람은 자기 앱을 못 본다."

**설계 질문 5** — ① 쓰는 사람 한 명(누가·하루 몇 번·어디서) ② 핵심 과업 하나(가장 자주 하는 일) ③ 상태 4칸(비어·기다림·됐을 때·안 됐을 때) ④ 이동과 돌아오는 길 ⑤ 폰 먼저(엄지·44px). "다섯 답이 있으면 시킬 수 있고, 없으면 AI가 멋대로 정한다. 답은 각자."

**손님 모드** — "아는 길로 가지 않는다. 화면이 알려주는 길로만 간다." 내 폰에서 **내 핵심 과업**을 처음 쓰는 사람처럼. 세는 것: 탭 수·멈칫·됐는지 화면이 말했나. 관찰→고칠 것 3패턴(멈칫→상태·안내 / 헤맴→이름·위치 / 확인 불가→피드백). 한 가지만 시키고 push → 다시 손님. "손님인 척해도 주인은 주인 — 마지막엔 강사가 누른다."

**막힘 3단계** — 복사 → 세 줄로 묻기(내 OS / 하려던 것 / 에러 + "내가 직접 해야 하는 게 있으면 그것부터, 한 단계만") → 한 단계만. 3분 규칙.

**PWA 5요소(7차)** — 화·정·오·저·배. 시키는 문장 "이 주소를 앱으로 만들어 홈 화면에 설치할 수 있게 — manifest.json과 sw.js를 추가해. 아이콘은 icons/에". 설치는 마지막(캐시).

**손들기·제출**: "상태 4칸 다 있는 사람?"(②, ≈0) · 제출 링크 수 · 설치 수.
