## 1. 스타터의 레이어 구조 (한 파일 = 한 책임)

| 파일 | 레이어 | 입력 → 출력 | 책임 |
|---|---|---|---|
| `store.js` | 데이터 | (없음)→목록 / 목록→(저장) | localStorage 저장·불러오기 |
| `actions.js` | 동작 | (목록, 입력) → 새 목록 | 추가·완료·삭제 *계산*만 (순수 함수) |
| `render.js` | 화면 | 목록 → 화면(DOM) | 그리기만 (데이터 안 바꿈) |
| `app.js` | 연결 | 이벤트 → actions → store → render | 레이어를 잇는다 (모든 변경은 `update()` 한 곳) |

### 데이터 흐름
```
[사용자 입력]
  → app.js (이벤트)
  → actions.js : (현재 목록, 입력) → 새 목록     [순수 계산]
  → store.js   : 새 목록 저장                     [저장]
  → render.js  : 새 목록 → 화면                   [그리기]
```

### 왜 이렇게? (학습 포인트 = 강의 핵심)
- **actions는 순수 함수** (목록 in → 목록 out) → 입력/출력이 가장 명확. 저장·화면과 분리돼 안전·재사용 쉬움.
- **render는 읽기 전용** → 데이터를 직접 안 바꿈.
- **변경의 단일 통로 `update()`** → 흐름이 한눈에.
- 결과: **"고칠 곳이 보인다"** — 기능은 actions부터, 모양은 render·css부터. (2차 I/O·6차 레이어의 실물)

## 2. PWA 5요소 ↔ 파일 (받은 앱에서 찾기)

| 코드 | 요소 | 파일 |
|---|---|---|
| 화 | 화면 | `index.html` · `styles.css` |
| 저 | 저장 | `store.js` (localStorage) |
| 정 | 정보 | `manifest.json` · `icons/` |
| 오 | 오프라인 | `sw.js` (캐시 `todo-pwa-vN`) |
| 배 | 배포 | Vercel(기본) / Railway(`server.js`) |

## 3. 전체 파일 구조

```
할일앱(스타터)/
├── index.html          # 화면 + 매니페스트 링크 + 스크립트 로드(store→actions→render→app)
├── styles.css          # 모바일 우선 스타일
├── store.js            # [데이터] 저장/불러오기
├── actions.js          # [동작] 순수 함수 (목록→목록)
├── render.js           # [화면] 목록→화면
├── app.js              # [연결] 이벤트→actions→store→render
├── manifest.json       # [정] 이름·아이콘·테마색
├── sw.js               # [오] 캐시(오프라인)
├── icons/              # icon-192·512
├── server.js           # 로컬/Railway 정적 서버
├── vercel.json         # Vercel 정적 배포 설정(빌드 없음, 루트 서빙)
├── .vercelignore       # 배포 제외(server.js·specs·*.md) → 함수 오감지 방지
├── specs/레이어_구조.md  # 구조 설명(투어용 교보재)
├── 개조_미션.md          # 디자인·기능 미션 카탈로그
├── README.md · CLAUDE.md · .gitignore
```

## 4. 개조 미션 (디자인 + 기능)

> 전체 카탈로그는 스타터의 `개조_미션.md`. 핵심만:

**🎨 디자인 (성공 경험)** — 앱 이름 / 테마색 / 밝은 테마 / 둥글기 / **내 이미지로 아이콘**
**⚙️ 기능 ('내 앱'다워짐)** — 중요 표시(별표) / 완료율 통계 / 완료 항목 숨기기·모두 지우기 / 카테고리 / 마감일

| 미션 종류 | 주로 손대는 레이어 |
|---|---|
| 모양·색·글자 | `styles.css` (또는 render의 마크업) |
| 데이터에 항목 추가(중요·마감일 등) | `store`(형태) + `actions`(계산) + `render`(표시) |
| 새 동작(모두 지우기 등) | `actions`(함수) + `app`(연결) + `render`/버튼 |
| 보여주는 방식(통계·정렬·숨기기) | `render` 중심 |

> 💡 미션 시킬 때 **"어느 레이어를 고치는지"**를 같이 말하면 결과가 정확하고, '구조를 이해했다'는 신호가 된다.

## 6. 로컬 실행 & 배포·설치

```bash
node server.js        # → http://localhost:3000 (서비스워커는 localhost에서 동작)
```
- **배포(Part 6)**: GitHub → Vercel 연결 → 자동 HTTPS URL. (대안 Railway: `server.js`로 정적 서빙)
- **설치(Part 7)**: 폰에서 URL 열기 → 안드로이드 "홈 화면에 추가" / 아이폰 공유 → "홈 화면에 추가" → 비행기모드로 오프라인 확인.
- ⚠️ 개조 후엔 **sw.js 캐시 버전 올리기**(안 그러면 옛 화면). HTTPS 아니면 설치 안 됨(로컬 localhost 예외).
