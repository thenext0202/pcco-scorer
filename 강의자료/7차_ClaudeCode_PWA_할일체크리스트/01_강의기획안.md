# 7차 강의 기획안 — 잘 짜인 앱을 받아 '내 앱'으로 만들기

> **부제**: 레이어로 잘 짜인 PWA를 받아 → 구조를 읽고 → 내 입맛대로 개조하고 → 폰에 배포한다
> **프레임워크**: PWA 5요소 (화·정·오·저·배 / Screen·Manifest·Offline·Save·Deploy)
> **선수강(권장)**: 6차(Claude Code 빌드 5단계)
> **상태**: 기획안 (v2 · '받아서 개조' 방식으로 재설계)

---

## 0. 한 문장 요약

> **"잘 짜인 앱(레이어 구조)을 받아, 구조를 읽고, 디자인과 기능을 내 입맛대로 고쳐, 폰에 깔리는 '내 앱'으로 만든다."**

빈손에서 묘사로 만드는 게 아니라(그건 6차), **이미 잘 구조화된 PWA를 교보재로 받아** — ① 왜 이렇게 나뉘었는지 읽고(학습) ② 디자인·기능을 개조하고(주도) ③ 배포해 폰에 설치한다(성취).

> ⚠️ **왜 이 방식인가**: 빈 폴더에서 만들면 구조가 '마법처럼' 생겨 안 보인다. 잘 짜인 완성품을 주면 구조가 *읽힌다*. 그리고 '내가 고쳤다'가 쌓여 "구경"이 "학습+성취"가 된다.

---

## 1. 강의 개요

| 항목 | 내용 |
|---|---|
| 강의명 | 잘 짜인 앱을 받아 '내 앱'으로 — 할 일 체크리스트 PWA |
| 차수 | 7차 (바이브 코딩 시리즈 · 6차 자매편) |
| 대상 | 6차 수강 권장. 코딩 무경험 OK |
| 소요 시간 | 약 112분 |
| 받는 것 | **레이어로 잘 짜인 할 일 PWA 스타터** (데이터·동작·화면·연결 4겹) |
| 하는 것 | 구조 읽기 → **디자인 + 기능 개조** → 배포 → 폰 설치 |
| 배포 | Vercel(기본) / 대안 Railway |
| 결과물 | 내가 개조해 폰 홈 화면에 깐 앱 + 친구에게 보낼 URL |

### 6차와의 역할 분담
- **6차** = 맨손으로 만들기(빌드 5단계). **7차** = 잘 짠 구조를 *이해하고 개조*하고 배포.
- 중복 없이 한 단계 위로. 7차의 새 학습 = **좋은 구조 읽기 + 안전하게 고치기 + PWA 배포·설치**.

## 2. 시리즈 연결

| 차수 | 한 일 | 어디서 | 공유 |
|---|---|---|---|
| 4차 | 운세 앱 (Artifacts) | 브라우저 미리보기 | 못 남김 |
| 6차 | 파일 변경기 (맨손 빌드) | 내 컴퓨터 | GitHub 코드 공유 |
| **7차** | **잘 짠 앱 개조 (PWA)** | **배포 URL + 폰** | **링크로 누구나 설치** |

> 6차 떡밥 회수: "내 파일 만지는 도구는 URL 배포 불가"였지만, **할 일 앱은 안 만지니 URL 배포가 정답** → 폰 설치·공유.

---

## 3. 프레임워크 — PWA 5요소 (화·정·오·저·배)

> 웹을 폰 앱으로 만드는 다섯 가지. 7차에선 이걸 "받은 앱에서 *찾는*" 지도로 쓴다.

| 코드 | 요소 | 영어 | 받은 앱의 어느 파일 |
|---|---|---|---|
| 화 | 화면 | Screen | `index.html` · `styles.css` |
| 정 | 정보 | Manifest | `manifest.json` · `icons/` |
| 오 | 오프라인 | Offline | `sw.js` (서비스워커) |
| 저 | 저장 | Save | `store.js` (localStorage) |
| 배 | 배포 | Deploy | Vercel |

> 숨은 전제: 설치·오프라인은 **HTTPS에서만**(로컬은 localhost 예외).

---

## 4. 받는 스타터의 구조 — ⭐ 이 강의의 교보재

레이어로 잘 나뉜 PWA(한 파일 = 한 책임, 입력 → 출력이 분명):

| 파일 | 레이어 | 입력 → 출력 |
|---|---|---|
| `store.js` | 데이터 | (없음)→목록 / 목록→(저장) |
| `actions.js` | 동작 | (목록, 입력) → 새 목록 *(순수 함수)* |
| `render.js` | 화면 | 목록 → 화면 |
| `app.js` | 연결 | 이벤트 → actions → store → render |

```
[입력] → app.js → actions.js (계산) → store.js (저장) → render.js (화면)
```
> 이게 **수정의 지도**가 된다 — "기능 추가는 actions부터, 모양은 render·css부터." (2차 I/O·6차 레이어의 실물 예시)

## 5. 핵심 메시지 & 킬러 인사이트

### 핵심 한 문장
> **"잘 짜인 구조 = 고치기 쉬운 구조. 구조를 읽으면 '어디를 고칠지'가 보인다."**

### 킬러 인사이트 2가지
**① 구조를 읽으면 고칠 곳이 보인다** — 입력→출력으로 잘 나뉜 레이어가 곧 수정 지도. 좋은 구조는 설명보다 *예시로* 배운다.

**② 무엇을 만드느냐가 배포를 정한다** — 6차 변경기는 URL 배포 불가였지만, 할 일 앱은 안 만지니 URL 배포가 정답. 그래서 폰에 깔리고 친구가 링크로 설치한다.

### 습관 3가지
- [ ] 고치기 전에 **구조부터 읽기** — 입력→출력, 어느 레이어인지
- [ ] **작은 디자인 개조 → 기능 개조** 순서로 (성공 경험부터)
- [ ] 코드 바꾸면 **서비스워커 캐시 버전 올리기**, 설치·오프라인은 HTTPS에서

## 7. 시간 배분 & 파트별 흐름 (112분)

| 파트 | 시간 | 단계 | 핵심 |
|---|---|---|---|
| 0 | 5 | 오프닝+복습 | "오늘은 잘 짠 앱을 받아 내 것으로" |
| 1 | 12 | PWA란? + 5요소 | 화·정·오·저·배 |
| 2 | 10 | 스타터 받기·실행 | 로컬 서버로 폰처럼 보기 |
| 3 ⭐ | 18 | 구조 투어 | 레이어 4겹 읽기 + 5요소 찾기 |
| 4 | 15 | 디자인 개조 | 이름·색·테마·내 아이콘 |
| 5 ⭐ | 20 | 기능 개조 | 기능 1개 추가(어느 레이어?) |

| 마무리 | 5 | 회고 | 5요소·레이어 + 습관 |

---

### Part 0. 오프닝 + 복습 (5분)
- 4차→6차→7차 상승. "6차는 맨손으로 만들었죠. 오늘은 잘 짠 앱을 받아 이해하고 내 것으로 개조합니다."

### Part 1. PWA란? + 5요소 (12분)
- PWA = 웹인데 폰에 설치·오프라인 되는 앱. 앱스토어·네이티브 없이.
- **PWA 5요소(화·정·오·저·배)** — 오늘 받은 앱에서 이 다섯을 *찾을* 것.

### Part 2. 스타터 받기 + 실행 (10분)
- 강사가 준 스타터 압축 풀고 → `node server.js` → localhost → 모바일 뷰로 폰처럼.
- "이미 작동하는 할 일 앱이죠? 이제 이걸 뜯어봅니다."

### Part 3. 구조 투어 ⭐ (18분) · 이 강의의 학습 핵심
- `specs/레이어_구조.md`와 파일을 함께 열어, **데이터(store)·동작(actions)·화면(render)·연결(app)** 4겹을 읽는다.
- 데이터 흐름: 입력 → app → actions(계산) → store(저장) → render(화면).
- **PWA 5요소가 어느 파일인지** 짚는다(화=index/css, 저=store, 정=manifest, 오=sw, 배=Vercel).
- 메시지: "한 파일 = 한 책임이라, 고칠 곳이 바로 보인다."
- Claude Code 활용: "이 폴더 구조랑 각 파일이 무슨 일 하는지 쉽게 설명해줘" / `@store.js 이 파일 설명해줘`.

### Part 4. 디자인 개조 (15분) · 성공 경험
- 가벼운 것부터: 앱 이름·테마색·밝은 테마·둥글기, 그리고 **내 이미지로 아이콘 교체**(경로 알려주기).
- 매번 새로고침해 즉시 결과 확인. "벌써 내 앱 같죠?"

### Part 5. 기능 개조 ⭐ (20분) · 주도 학습
- 기능 1개 추가(택1): 중요 표시(별표)·완료율 통계·완료 항목 숨기기·완료 모두 지우기 등.
- 핵심: **"어느 레이어를 고치나"**를 같이 말하며 시킨다 — "actions에 함수 추가하고, render에 표시해줘."
- 구조가 좋아서 수정이 쉽다는 걸 체감. (`개조_미션.md` 참고)

### Part 6. 배포 — Vercel (15분)
- 설치·오프라인은 HTTPS에서만 → 배포해야 진짜 폰에 깔린다.
- GitHub에 올리고 Vercel 연결 → 자동 HTTPS URL. (대안 Railway: server.js로)
- 6차 배포 트리 회수: 남의 파일 안 만지는 앱은 URL 배포가 정답.

### Part 7. 폰 설치 + 공유 ⭐ (12분)
- 배포 URL을 폰에서 열고 "홈 화면에 추가"(안드로이드/아이폰 차이 안내) → **내가 개조한 앱**이 홈 화면에.
- 비행기모드로 오프라인 확인 + 단톡방에 링크 공유.

### 마무리 (5분)
- PWA 5요소 + 레이어 4겹 회고. 습관 3가지. 다음 예고(푸시·카메라 등 폰 기능).

## 8. 트러블슈팅 (강사 대비용)

| 증상 | 원인 | 대응 |
|---|---|---|
| 고친 게 화면에 안 보임 | 서비스워커 캐시 | 캐시 버전 올리기(v2→v3) / 개발 중 SW 잠시 끄기 |
| "홈 화면에 추가" 안 보임 | HTTPS 아님 / 매니페스트 | 배포 URL에서, manifest·아이콘 확인 |
| 기능 추가가 꼬임 | 엉뚱한 레이어 수정 | "actions부터, 그다음 render" 순서로 다시 |
| 아이폰 설치 다름 | iOS는 수동 | Safari 공유 → 홈 화면에 추가 |
| 새로고침하면 사라짐 | store 저장 누락 | update()가 saveTodos를 거치는지 |
