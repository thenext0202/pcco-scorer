## 1. 실측 전체 트리 (강사가 읽고 이해할 원본)

```
프롬포트 채점/                        ★=슬라이드에 등장 / ( )=슬라이드에서 생략
├─ ★ package.json                   재료 목록 — 앱 이름, 의존 패키지 목록, 실행 명령어(dev·build·start)

   │  ├─ host/page.tsx              /host        세션 만들기 (강사용)

   │  │  └─ board/page.tsx          /play/ABCD/board  리더보드
```

## 2. 슬라이드용 단순화 규칙

- **1층(슬라이드 08)**: 루트에서 ★만, 9줄 이내. src와 node_modules는 접어서 한 줄씩. 설정 4종은 "설정 파일들 (tsconfig 등 4개)"로 묶는다.
- **2층(슬라이드 11)**: src의 다섯 골목만. 폴더당 비유 한 줄. 파일명은 content.ts 하나만 노출(원칙 4의 증거).
- **주소(슬라이드 12)**: 주소↔폴더 대응 5줄 + api 한 줄. `[code]`는 "변하는 주소" 딱 한 마디.
- 개수·용량 같은 숫자는 임팩트 있는 것 2개만 쓴다: **content.ts 225KB** / **CLAUDE.md 39KB(A4 30장)**.

## 3. 폴더별 "왜" — 설명 대본의 뼈대

| 폴더 | 왜 갈라졌나 (한 줄) | 안 갈랐다면 생기는 일 |
|---|---|---|
| app vs components | 주소가 있는 것(페이지)과 없는 것(부품)의 분리 | 페이지 파일이 수천 줄 — 버튼 하나 고치러 지도 없이 밀림 탐험 |
| components vs lib | 보이는 것과 계산하는 것의 분리 (원칙 2) | 채점 로직을 고치다 화면이 깨짐 — 서로 인질 |
| lib vs types | 하는 일과 주고받는 약속의 분리 (원칙 3, 2차 I/O 한 줄 복습) | 점수 모양이 바뀌면 어디가 깨질지 아무도 모름 |
| data 분리 | 내용과 코드의 분리 (원칙 4) | 강의 하나 추가할 때마다 코드 수술 |
| app/api | 화면 없는 골목 — 열쇠(.env)를 쓰는 일은 서버에서만 | API 키가 브라우저에 노출 → 도난 (16차 떡밥) |

## 4. 학생 질문 대비 노트 (FAQ — 답은 짧게, 지도 밖으로 나가지 않기)

- **"page.tsx의 tsx가 뭐예요?"** → "ts는 타입스크립트, x는 화면 조각을 코드 안에 쓸 수 있게 한 확장. '화면 만드는 파일'이라고만 기억하세요." (14차에서 다룸 — 오늘은 여기까지)
- **"package-lock.json은요?"** → "재료 목록의 영수증. 어제 산 재료의 정확한 버전을 고정해두는 파일. 우리 팀 전원이 같은 재료를 쓰게 해줍니다."
- **".git 폴더가 있던데요?"** → "9차의 '기억'(GitHub)이 내 컴퓨터에 두는 분신. 오늘 지도에선 생략했습니다."
- **"Supabase는 폴더 어디 있어요?"** → ⭐ 좋은 질문으로 승격할 것 — "없습니다. 창고(DB)는 이 폴더 밖, 다른 회사 서버에 삽니다. 우리 폴더에 있는 건 창고 열쇠와 전화번호(lib/supabase.ts)뿐이에요. 그래서 '연결'이 필요한 겁니다."
- **"채점은 누가 해요? AI예요?"** → "api/score 골목이 채점 기준(시스템 프롬프트)을 들고 Claude를 부릅니다. 그 여정을 마지막에 통째로 따라갈 거예요(슬라이드 15)."
- **"왜 어떤 파일은 대문자예요? (CLAUDE.md, README.md)"** → "관례입니다 — '이 폴더의 문패'라는 뜻으로 소리치는 것. 폴더를 열면 제일 먼저 읽으라는 신호."
- **"우리도 폴더를 꼭 이렇게 짜야 해요?"** → "아니요. 이건 Next.js의 관례가 절반, 원칙이 절반. 숙제에서 여러분은 **원칙**만 지키면 됩니다 — 프레임워크 관례는 도구를 정한 뒤에 따라오는 것."

## 5. 겹치는 경계 — 숨기지 말고 가르칠 것 (슬라이드 11 말미)

app/ 폴더는 화면(페이지)과 연결(api)이 **한 동네에 산다**. 4겹이 폴더에 1:1로 딱 떨어지지 않는 게 실물이다. 대본: "지도는 단순화입니다. 실물은 경계가 흐려요. 그래도 지도 없이 다니는 것보단 백 배 낫습니다."

## 6. 채점 버튼의 여정 — 실물 파일 경로 (강사 암기용, 슬라이드 15의 원본)

1. [채점하기] 버튼 = `components/PromptScorer.tsx` (화면)
2. 브라우저가 `/api/score`로 프롬프트를 보냄 (연결)
3. `app/api/score/route.ts`가 받아서 `lib/scoringPrompt.ts`(채점 기준)와 함께 Claude API 호출 (동작) — **열쇠 `.env.local`은 이 서버 쪽에서만 열림**
4. 점수 JSON이 돌아오면 `components/ScoreResult.tsx`가 그림 (화면)
5. 리더보드 등록 시 `lib/sessionApi.ts` → Supabase 창고에 저장 (데이터)
6. `/play/[code]/board`가 창고를 읽어 순위를 그림 (화면)

퀴즈 정답 메모: 채점기 주소(화면) 개수 = **6개** (/ · /practice · /host · /play/[code] · /play/[code]/board · /install). node_modules 퀴즈 답 = "지워도 됨 — package.json이 있으면 `npm install` 한 번으로 창고가 다시 채워진다."
