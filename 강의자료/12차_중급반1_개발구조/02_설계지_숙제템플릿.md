## 2쪽 — 완성 예시: 「점심 메뉴 뽑기」 (이렇게 쓰면 됩니다)

**① 한 문장**: 내가 버튼을 누르면 등록해둔 메뉴 중 하나를 뽑아주고, 오늘 뽑은 결과가 기록으로 남는다.

**② 쏟아내기** (생각나는 대로, 순서 없이):

> 뽑기 버튼 / 메뉴 등록하는 곳 / 메뉴 지우기 / 어제 나온 메뉴는 빼고 뽑기 / 뽑은 기록 보기 / 메뉴 목록은 껐다 켜도 남아야 함 / 뽑은 기록도 남아야 함

**③ 묶기** (비슷한 것끼리):

> 보이는 것들(뽑기 화면·메뉴 관리·기록 보기) → **screens/** · 규칙·계산(어제 메뉴 빼고 뽑기) → **logic/** · 남아야 하는 것(메뉴 목록·기록) → **data/**

**④ 트리로 그리기** — 폴더마다 "왜" 한 줄 + 태그:

```
점심메뉴뽑기/
├─ README.md          왜: 사람용 문패 — 뭐 하는 앱인지, 어떻게 켜는지
├─ 재료목록            왜: 도구가 부품을 사 오게 (package.json 자리)
├─ screens/           왜: 보이는 화면들만 모아둔다                    [화]
│   ├─ 뽑기화면        왜: 첫 화면 — 큰 버튼 하나                     [화]
│   ├─ 메뉴관리화면     왜: 메뉴 등록·삭제                            [화]
│   └─ 기록화면        왜: 오늘까지 뽑은 결과 목록                     [화]
├─ logic/             왜: 뽑기 규칙 — 어제 나온 메뉴는 제외             [동]
├─ data/              왜: 메뉴 목록과 뽑기 기록이 남는 곳               [데]
└─ (창고 자리)         왜: 도구가 만들 자리 — 비워둠 (node_modules) ★보너스
```

**⑤ 문패 달기**: ☑ README(사람용 문패) · ☑ 재료 목록 · ☐ .env — 이 앱은 비밀 열쇠가 없어서 생략 · ☐ 연결[연] — 혼자 쓰는 앱이라 아직 없음. **나중에 "친구에게 결과 공유"를 붙이면 그때 생긴다** (비워도 되는 칸이 있다는 것도 설계!)

> ✅ 합격 기준과 대조: 최상위 폴더 3~6개? → screens·logic·data 3개 ✓ / 모든 폴더에 "왜"? ✓ / 4겹 태그? ✓ / 보너스(안 만들 파일 자리)? ✓
