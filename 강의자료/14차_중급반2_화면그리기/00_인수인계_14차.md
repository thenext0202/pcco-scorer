## 3. 핵심 정의 (모든 자료에서 이 문구 그대로)

**화면 해부 4단**
| 단 | 실명 | 한 줄 정의 | 채점기 결과 카드에서 |
|---|---|---|---|
| 뼈대 | HTML | 화면은 상자 속 상자 — 모든 것은 상자, 상자마다 이름표 | 카드 > 점수·등급·요소 5칸·피드백 |
| 옷 | CSS | 같은 뼈대에 다른 옷 — 색·크기·자리·간격 / 폰 옷·PC 옷(반응형) | 파랑·초록·teal — 뼈 같고 옷만 다름 |
| 움직임 | JavaScript | 누르면 일어난다 — 사건→상자가 바뀐다·생긴다·사라진다 | 채점 버튼 → 빙글 → 카드 등장 → 복사 |
| 부품 | 컴포넌트 | 반복되는 상자 묶음에 이름 붙인 것 · 빈칸(재료 자리)이 있다 | Scorer 5·Result 5·버튼·배지 — 26개 |

**렌즈 2개**: UI = 생김새(뼈대+옷) / UX = 겪는 것(움직임+상태+이동)

**상태 4장**: 비어 있음(입력 전 안내문) · 기다림(빙글) · 성공(결과 카드) · 실패(에러 문구). 문장: **"화면 하나는 그림 여러 장이다."** / "AI에게 시킬 때 사람이 가장 많이 빠뜨리는 세 장 = 비어·기다림·실패"

**좋은 화면의 원칙 5**: ① 한 화면=한 목적 ② 반복되면 부품 ③ 상태를 빠뜨리지 않는다⭐ ④ 폰 먼저(같은 뼈대 다른 옷) ⑤ 보이는 것과 하는 것을 나눈다

**여정 2개**: ① 설계도 세 장(12차 05 이어받기 — "브라우저는 세 장을 겹쳐 한 화면을 그린다") ② 채점 버튼을 화면 눈으로(12차 21 수미상관 — 버튼[움직임]→기다림[옷]→서버(한 줄)→결과 카드[부품]→등록 카드[고정 부품]→리더보드[이동]). 클로징 문장 "12차엔 지형으로, 오늘은 화면으로, 16차엔 창고로"

**16차 떡밥**: "화면에 보이는 것은 화면이 만든 게 아니라 창고에서 온 것" — 화면도의 「보이는 데이터」 칸이 16차 재료
