PART 1 · 왜 세 장으로 나누나
한 장에 다 쓰면 옷 바꾸다 뼈가 부러집니다
12차 원칙 ② "화면과 동작을 섞지 않는다" — 화면 안쪽에서도 똑같은 일이 벌어집니다.

한 장에 다 쓰면

  • 배지 색 하나 바꾸려다 상자 구조가 깨진다
  • 버튼 동작을 고치는데 디자인이 흔들린다
  • 디자이너와 개발자가 같은 종이를 놓고 싸운다
  • 폰 옷·PC 옷을 만들려면 뼈대를 두 번 써야 한다

세 장으로 나누면

  • 옷만 갈아입힌다 — 뼈대는 그대로
  • 움직임만 고친다 — 생김새는 그대로
  • 옷은 디자이너가, 움직임은 개발자가 — 종이가 다르면 사람이 달라도 된다
  • 같은 뼈대에 옷 두 벌 — 반응형
역할이 다른 것은 따로 둔다 — 폴더에서도(12차), 화면 안에서도(오늘). 같은 원리가 크기만 다르게 반복됩니다.
PART 1 / 왜 세 장인가10 / 24
PART 1 · 렌즈 둘 — UI와 UX
UI는 생김새, UX는 겪는 것 — 4단 위에 얹기

UI = 보이는 것 (뼈대 + 옷)

  • 등급 배지 여섯 색, 큰 숫자 87
  • 초록 점(강점) · 주황 점(개선점)
  • 둥근 카드, 숨 쉴 틈
  • 판단 기준: "예쁜가, 알아보기 쉬운가"

UX = 겪는 것 (움직임 + 상태 + 이동)

  • 채점 끝나면 등록 카드가 화면 하단에 고정 — 스크롤 안 해도 다음 행동이 보인다
  • 결과가 오면 자동으로 결과 위치로 내려간다
  • 세션 모드에선 결과 끝 버튼을 숨긴다 — "끝났다" 신호가 등록 버튼을 가리지 않게
  • 판단 기준: "몇 번 눌러야 하나, 기다릴 때 불안한가, 다음에 뭘 할지 보이나"
둘은 따로 좋고 따로 나쁩니다 — "예쁜데 불편한 앱"과 "못생겼는데 편한 앱"이 둘 다 존재하는 이유. 🙋 떠오르는 앱 있으세요?
☕ 10분 쉽니다. 쉬고 나면 부품을 뜯습니다.

PART 2 · 손수 만든 부품 vs 사온 부품
화면도 절반은 사온 것입니다 — 12차 "안 만든 파일들"의 화면판
기성 부품사온 부품 8개
ui/ 폴더 — 버튼·배지·카드·입력칸·글상자·알림·회색 뼈대·토스트. 남이 잘 만들어 공개한 부품 세트(shadcn/ui)를 내 폴더에 가져와 옷만 조금 바꿔 쓴다. 버튼 하나도 제대로 만들려면 잠김·키보드·색 상태를 다 챙겨야 하니까.
옷장옷을 미리 만들어 둔 곳
옷(CSS)을 한 벌씩 새로 짓지 않고 "파란 배경·둥근 모서리·가운데" 같은 옷 조각을 이름으로 골라 입힌다(Tailwind). 채점기 옷은 거의 전부 이 옷장. 등급 배지 여섯 색도.
움직임 상자연출 도구
상자가 스르륵 나타나고 사라지게 하는 도구(framer-motion). 홈 화면 카드들이 스크롤 따라 떠오르는 것. 없어도 앱은 된다 — 선택.
12차 — "내가 만든 건 절반뿐, 나머진 도구가 만든다." 오늘 — 내가 그린 부품도 절반뿐, 나머진 사 온다. 잘 만든 게 있으면 사 오는 것도 설계입니다.
이름 셋(기성 부품 · 옷장 · 움직임 상자)이면 오늘은 충분합니다. 더는 안 나열합니다.

실습은 채점만, 리더보드는 순위만. 한 화면에 셋을 넣으면 어디를 눌러야 할지 모른다
원칙 ②
반복되면 부품
버튼·배지·카드는 부품 하나를 여러 곳에서. 안 그러면 색 하나 바꾸는 데 수십 군데 수술
원칙 ③ ⭐
상태를 빠뜨리지 않는다

폰 먼저

뼈대·옷 / 움직임. 옷 바꾸다 채점이 멈추면 서로 인질 — 12차 원칙 ②의 화면판
