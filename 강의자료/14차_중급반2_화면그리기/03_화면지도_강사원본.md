## 1. 화면 목록 — 7개 (이동 화살표 포함)

12차엔 "화면 6개"라고 했다. 그 뒤 자료실이 생겨 **7개**가 됐다 — 슬라이드 17에서 "화면은 늘어난다"의 증거로 한 문장만.

| # | 화면 | 주소 (12차 복습용, 슬라이드엔 우리말만) | 한 목적 | 여기서 갈 수 있는 곳 |
|---|---|---|---|---|
| 1 | 랜딩(홈) | `/` | 강의 소개 | → 실습 / → 자료실 / → (강사) 호스트 |
| 2 | 실습 | `/practice` | 단독 채점 (탭 5개로 모드 전환) | → 홈 / → 참가(코드 입력) |
| 3 | 호스트 | `/host` | 세션 만들기 (비밀번호) | → 리더보드 |
| 4 | 참가 | `/play/[code]` | 세션 채점 + 등록 | → 리더보드 / → 홈 |
| 5 | 리더보드 | `/play/[code]/board` | 순위 보기 | → 참가 / → 홈 |
| 6 | 설치 | `/install` | PWA 설치 안내 | → 홈 |
| 7 | 자료실 | `/downloads` | 부록 다운로드 | → 홈 |

핵심 화살표(슬라이드 17·부록 24): **홈 → 실습** / **홈 → 호스트 → 리더보드** / **참가 → 채점 → 등록 → 리더보드**. 화면 없는 골목 `api/`는 12차 영역 — 오늘 화살표에서 뺀다.

## 2. 부품 목록 — 31개 (12차 "26개"에서 늘어남)

12차 슬라이드는 26개(2026-08-14)였다. 이후 자료실(ResourceLibrary)과 몇 개가 추가돼 **31개**. 슬라이드 14 `.tree`엔 **31개**로 올리고, 러닝시트 14에 "12차엔 26개라고 했죠 — 그 사이 다섯 개가 늘었습니다. 부품은 늘어나는 게 정상입니다"를 넣었다.

| 묶음 | 개수 | 파일 (본문에선 우리말로) | 강의 포인트 |
|---|---|---|---|
| 채점기(Scorer) | 5 | PromptScorer · InstructionScorer · ImageScorer · VibeScorer · ReverseScorer | 퀴즈 ② — 왜 하나로 못 만들었나 |
| 결과 카드(Result) | 5 | ScoreResult · InstructionScoreResult · ImageScoreResult · VibeScoreResult · ReverseScoreResult | 슬라이드 06·07·12의 해부 대상 = ScoreResult |
| 랜딩 부품 | 8 | Hero · PainPoints · USP · BeforeAfter · WhatYouLearn · FrameworkCards · FAQ · CTA | 한 화면 = 부품 8개 조립 |
| 기타 | 5 | CourseDetail · ResourceLibrary · InstallPrompt · ServiceWorkerRegister · UpdateNotification | 보이지 않는 부품도 있다(SW 등록) — 질문 나오면만 |
| 사온 기성 부품(ui/) | 8 | button · badge · card · input · textarea · alert · skeleton · sonner(토스트) | 슬라이드 15 — "화면도 절반은 사온 것" |

**퀴즈 ② 정답(슬라이드 14)**: Scorer 5개는 입력칸 수·안내문·요소 개수(5요소 vs 5요소 vs SSDHR…)·색이 달라서 **빈칸(재료)만으로는 못 덮는 차이**가 있었다 → 부품을 갈랐다. 반대로 **버튼·배지·카드는 빈칸으로 덮이니 하나**다. 부품 쪼개기 기준의 첫 등장: *"빈칸으로 안 되는 차이가 있으면 부품을 가른다."*

## 3. 결과 카드 해부 — 슬라이드 06·07·08·09·12의 실물 근거 (ScoreResult 실측)

결과 카드는 사실 **카드 6장 묶음**이다 (보너스/감점 카드는 있을 때만):

```
결과 카드 (부품)
├─ ① 총점 카드        큰 숫자 "87/100" + 등급 배지 "A 등급"
├─ ② 요소별 점수 카드   제목 "📊 요소별 점수" + 행 5개
│     └─ 행 하나 = 아이콘·이름 · 점수 "17/20" · 막대(프로그레스 바) · 감지된 문장(회색 상자) · 피드백 문단
├─ (③ 보너스/감점 카드)  있을 때만 — 조건부 상자
├─ ④ 강점 카드         제목 + 목록(초록 점)
├─ ⑤ 개선점 카드       제목 + 목록(주황 점)
└─ ⑥ 개선 예시 카드    제목 + [복사] 버튼 + 본문 상자 → 누르면 토스트 "복사 완료!"
```

**퀴즈 ① 정답(슬라이드 06 목업 기준)**: 목업은 ①·②·④·⑥ 네 장으로 단순화했고, 상자 수는 **목업에 그린 대로 11개**(카드 3 + 총점 카드 안 숫자·배지 2 + 요소 카드 안 제목·행·행 3 + 예시 카드 안 제목·버튼·문단 3). *정확한 수보다 "세는 눈"이 목적* — 손든 수가 제각각인 게 정상. 공개 답은 "이 목업에서 11개, 진짜 카드는 60개가 넘습니다."

**옷(슬라이드 08)의 실물**: 등급 배지 색 — S 호박 · A 초록 · B 파랑 · C 회색 · D 주황 · F 빨강 = **같은 뼈대(배지) 여섯 벌 옷**. 모드별 탭 색 — 프롬프트 파랑 · 지침 파랑 · 이미지 보라 · 바이브 남색 · 역설계 teal. 반응형 — 실습 화면 버튼은 폰에서 세로 1열, PC에서 가로(`sm:` 기준). 등록 카드는 **폰에서 화면 하단 고정**(fixed bottom)이라 본문에 하단 여백을 둔다.

**움직임(슬라이드 09)의 실물 — "채점 버튼이 하는 일 3"**: ① 버튼 글자가 "채점하기"→"채점 중…"으로 바뀌고 잠긴다 ② 회색 뼈대 상자 3개(스켈레톤)가 나타난다 ③ 결과가 오면 회색 상자가 사라지고 결과 카드가 생기며 **화면이 결과로 스크롤**된다. 그 밖의 움직임: 입력할 때마다 글자 수 "123/1000자" 갱신 · 30자 미만이면 빨간 안내 · [지우기] · [복사]→토스트.

## 4. 상태 4장 — 슬라이드 16 (채점 화면 실측)

| 상태 | 화면에 실제로 보이는 것 | 사람이 빠뜨리는 이유 |
|---|---|---|
| 비어 있음 | 회색 안내문 "여기에 프롬프트를 입력하세요. 예: 너는 10년차 마케터야…" + 버튼 **잠김** + "최소 30자 이상 입력하세요 • 0/1000자" | 완성된 화면만 상상하니까 |
| 기다림 | 버튼 "채점 중…"(잠김) + **회색 뼈대 상자 3개**(스켈레톤 — 결과 자리 예고) | "결과가 바로 온다"고 생각하니까 |
| 성공 | 결과 카드 6장 + [다른 프롬프트 채점하기] | (이건 다 그린다) |
| 실패 | 빨간 알림 상자 "채점에 실패했습니다." / 짧으면 "프롬프트가 너무 짧습니다. 최소 30자…" | 실패를 상상하고 싶지 않으니까 |

**퀴즈 ③ 정답(슬라이드 16)**: 채점 버튼을 누르고 결과까지 화면은 **3번** 바뀐다 — ① 누름(버튼 잠김·"채점 중…") ② 기다림(회색 상자) ③ 결과(카드). "실패하면 ③ 대신 빨간 상자" — 그래서 그림은 4장.

**기다림 상태의 강의 가치**: 스켈레톤은 **"뼈대만 먼저 보여주는 상자"** — 오늘 첫 개념(뼈대)이 상태 화면에서 재등장한다. "왜 회색 상자를 보여주나? 아무것도 안 보이면 사람은 두 번 누른다 → 두 번 채점" = 원칙 ③의 반례.

## 5. 부품의 빈칸 — 슬라이드 13 실물

배지 부품 하나에 들어가는 글자 5종(참가 화면 실측): 🎯 프롬프트 채점 · 📘 지침 채점 · 🎨 이미지 프롬프트 채점 · ⚡ 바이브 코딩 채점 · 🔍 역설계 채점 (한 방 프롬프트). 같은 부품, 다른 재료.
등급 배지: 빈칸 2개 — 글자(S~F)와 옷(색). 버튼 부품: 빈칸 = 글자("채점하기"/"채점 중…"/"리더보드에 등록하기 →")·크기·잠김 여부·옷(outline/ghost).

## 6. UI vs UX — 슬라이드 11 실물

| UI(생김새) | UX(겪는 것) |
|---|---|
| 등급 배지 색 6종 / 모드별 탭 색 / 카드 둥근 모서리 | 채점 완료 후 **등록 카드가 화면 하단에 고정** — 스크롤 안 해도 다음 행동이 보인다 |
| 큰 숫자 87 + 작은 "/100" | 결과가 오면 **자동으로 결과 위치로 스크롤** |
| 초록 점(강점)·주황 점(개선점) | 결과 카드 끝의 [다른 프롬프트 채점하기] 버튼을 세션 모드에선 **숨김** — "끝났다" 신호가 등록 버튼을 가리지 않도록 (코드 주석에 이유가 적혀 있다) |

"예쁜데 불편한 앱"을 수강생에게 묻기 — 사례가 안 나오면 "은행 앱: 예쁜데 이체까지 여섯 번 누른다".

## 9. FAQ (질의응답 — 부록 24 띄우고 답한다)

- **"HTML 태그 이름 좀 알려주세요"** → 용어사전 1부에 실명 있음. "오늘은 상자와 이름표로 봅니다. 이름표의 영어 이름은 사전에 — 집에서 검색하면 10분이면 됩니다."
- **"코드는 언제 보나요" / "더 보여주세요"** → 예비 슬라이드 23. "오늘은 슬라이드 07의 아홉 줄이 전부 — 다음 시즌. 그 아홉 줄이 읽힌 건 상자를 먼저 봤기 때문."
- **"React가 뭐예요"** → 12차 15 한 줄: "화면을 부품으로 조립하는 라이브러리 — 오늘 배운 '부품'이 바로 React의 부품(컴포넌트)입니다."
- **"디자이너가 하는 일이랑 뭐가 달라요"** → "디자이너는 옷과 UX를, 개발자는 뼈대와 움직임을 — 그래서 세 장으로 나눈 겁니다(슬라이드 10)."
- **"우리 앱은 화면이 하나뿐인데요"** → "한 화면이어도 상태는 네 장입니다 — 화면도 4쪽의 상태 4칸이 오늘 숙제의 본체예요."
- **"폰이랑 PC 둘 다 그려야 하나요"** → "대표 화면 1장은 폰 기준으로. PC에서 달라지는 부분 1곳만 보너스 칸에."
- **"상태가 4개보다 많은데요"** → "많아도 됩니다 — 예: '짧아서 못 보냄'도 상태. 4칸은 최소."

## 10. 슬라이드 07 「정체 공개」 — 오늘 유일한 코드 (2026-09-02 v1.2 추가)
