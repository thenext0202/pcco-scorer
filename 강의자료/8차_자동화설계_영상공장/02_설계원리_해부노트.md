# 8차 · 설계원리 해부노트 (PILOT)

> **용도**: 강사가 읽고 그대로 말로 풀 수 있는 **해부 대본 + 원리 노트**. 코드/JSON 원본은 여기 안 옮긴다 — 전부 **말과 그림으로** 설명한다.
> **교보재**: 선생님의 "제품 광고 영상 자동생성 공장" (입력=제품 정보 → 출력=한국어 음성 광고 영상).
> **프레임워크**: PILOT = Pipeline · I/O · Layer · Oversight · Trace.

---

## 0. 이 강의의 한 문장

> **"자동화는 코드가 아니라 설계다. 잘 쪼개고 잘 이으면, 지휘자(사람이든 AI든)는 갈아끼우면 된다."**

- 초심자는 자동화를 "툴 붙이기"로 오해한다. 진짜 어려움은 **어떻게 쪼개고, 무엇을 주고받게 할지 정하는 설계**다.
- 오늘은 **남의 공장(선생님 영상 공장)을 해부**해서 그 설계 원리 5개(PILOT)를 뽑고 → **각자 자기 설계도 한 장**을 그린다.
- 코드 한 줄 안 짜도 된다. 오늘의 결과물은 **'내 자동화 설계도'**다.

---

## 1. 공장 견학 — 해부 전에 통째로 보기

**한 줄 소개**: "제품 정보를 넣으면, 한국어 음성이 깔린 광고 영상이 나오는 공장."

**흐름 (말로):** 제품을 접수하고 → 제품을 분석하고 → 어떤 느낌으로 갈지 방향을 정하고 → 대본을 쓰고 → 장면 그림(키이미지)을 만들고 → 그림을 영상 클립으로 움직이고 → 검수·보정하고 → 하나로 합쳐 최종 영상을 낸다. (총 8칸)

**강의 멘트**: "복잡해 보이죠? 걱정 마세요. 오늘 **PILOT 다섯 개의 칼**로 해부하면, 여러분 업무에도 똑같이 쓰는 단순한 원리 5개만 남습니다."

> ⚠️ 이 단계에선 **원리 설명 금지**. 결과물(완성 광고 영상 1개)을 보여주고 "이게 나온다"는 충격만 남긴다.

## 2. P · Pipeline (쪼갠다) — 큰 일을 순서 있는 단계로

### 원리
큰 일 하나를 **한 번에** 시키지 않고, **끝이 분명한 작은 단계들**로 가로로 쪼갠다.
공장은 "광고 영상 만들기"를 8칸으로 쪼갰다: 접수 → 분석 → 방향 → 대본 → 그림 → 클립 → 검수 → 합본.

### 왜 쪼개나 (한 프롬프트로 다 시키면 왜 망하나)
- **한 번에 다 시키면** 어디서 틀어졌는지 모른다. 대본이 이상한 건지, 그림이 이상한 건지 뒤엉킨다.
- 쪼개면 **틀어진 단계만** 다시 돌린다. 대본이 별로면 대본 단계만, 그림이 별로면 그림 단계만.
- 각 단계가 **전문화**된다 — 판단·글쓰기는 Claude가, 그림·영상은 생성 도구가.

### 좋은 단계의 조건 (전이 규칙)
1. **하나의 책임** — 한 단계는 한 가지 일만. ("분석"과 "대본"을 한 칸에 넣지 않는다.)
2. **끝이 분명** — 그 단계가 끝나면 **딱 떨어지는 결과물**이 나온다(대본 한 편, 그림 6장처럼).
3. **다음 칸이 그걸 받아 이어감** — 앞 칸의 결과가 뒤 칸의 재료.

### 흔한 실패
- 너무 안 쪼갬(=한 프롬프트에 다 욱여넣기) → 품질·디버깅 다 무너짐.
- 너무 잘게 쪼갬(20단계) → 관리가 더 복잡. **3~7단계**가 보통 적당.

### 이전 강의 연결
- **5차 BATLR의 '쪼개기(Break)'** 의 심화 — 그때는 개념, 오늘은 "단계를 어떻게 설계하나".

### 실습 씨앗 (설계도 **P**칸)
"여러분 업무 하나를 골라 **3~7단계**로 쪼개보세요. 각 단계의 '끝(결과물)'이 뭔지도 적으세요."

## 3. I · I/O (정한다) — 단계 사이를 '계약'으로 잇는다

### 원리
쪼갠 단계들을 **말(기억)로** 잇지 않고, **정해진 양식의 결과물(파일)** 로 잇는다.
각 단계는 "**무엇을 받아서(입력) 무엇을 내놓는지(출력)**"를 계약처럼 못 박는다.

### 공장 실물 (말·미니 예시로, 원본 JSON은 안 보여줌)
- 분석 단계 ▶ 들어가는 것: *제품 정보* / 나오는 것: *제품 요약·설득 포인트*
- 방향 단계 ▶ 들어가는 것: *제품 요약* / 나오는 것: *영상 의도·톤·스타일*
- 대본 단계 ▶ 들어가는 것: *의도* / 나오는 것: *컷별 대사·장면 프롬프트*
- … 이런 식으로 **칸마다 입력→출력 한 줄**이 정해져 있다.

> 슬라이드용 미니 예시(손으로 만든 것):
> ```
> [대본 단계]
>   들어가는 것 : 영상 의도(누구에게·어떤 느낌)
>   나오는 것   : 컷별 대사 + 장면 묘사
> ```

### 왜 계약을 정하나
- 계약이 있으면 **단계를 따로 고치고, 따로 테스트**할 수 있다.
- **실행자를 바꿔도** 된다 — 대본 단계를 사람이 쓰든 AI가 쓰든, "의도 받아서 대사 낸다"는 계약만 지키면 OK.
- 뒤 칸은 앞 칸이 **어떻게** 만들었는지 몰라도 된다. **결과물의 모양**만 약속되면 된다.

### 흔한 실패
- 계약 없이 "알아서 잘 넘겨줘" → 다음 단계가 뭘 받을지 몰라 깨진다.
- 출력 양식이 그때그때 달라짐 → 자동화가 중간에 멈춘다.

### 이전 강의 연결
- **2차 I/O 계약(포·필·범·메: 포맷·필수·범위·메타)** 이 그대로 여기 온다. "지침의 입출력 계약"이 자동화에선 "**단계의** 입출력 계약".

### 실습 씨앗 (설계도 **I**칸)
"쪼갠 단계마다 '무엇이 들어가고(입력) 무엇이 나오나(출력)'를 **한 줄씩** 적으세요."

## 4. L · Layer (나눈다) — 지식·실행·창구를 층으로

### 원리
단계를 가로로 쪼갰다면(P), 이번엔 시스템을 **세로로 나눈다**. 성격이 다른 것을 **층(레이어)**으로 분리한다.

공장의 4층:
- **지식층(L0)** — 안 변하는 재료·규칙: 제품 지식, 제작 지침, 스타일 템플릿. (로직 없음, 그냥 앎)
- **스펙층(L1)** — 각 단계의 계약서(입력→출력·규칙). (언어중립, 누가 실행하든 동일)
- **지휘자층(L2)** — 단계들을 **순서대로 시키고 상태를 관리**하는 오케스트레이터.
- **창구층(L3)** — 사람이 요청을 넣고 결과를 받는 입출력 창구(웹 UI 등).

### ⭐ 강의 하이라이트 — 두 축
> **가로로 쪼개고(Pipeline), 세로로 나눈다(Layer).**
> - 가로(P): 시간 순서 — 접수→분석→…→합본
> - 세로(L): 성격 분리 — 지식 / 스펙 / 지휘 / 창구

이 두 축 그림 한 장이 8차의 핵심 비주얼.

### 얇은 지휘자 (왜 중요한가)
- 지휘자층(L2)은 **"순서·상태·호출·재시도"만** 한다. 창의(분석·대본)나 생성(그림·영상)은 안 한다.
- 지휘자가 얇으면 → **지휘자만 갈아끼워도** 공장이 돈다.
  - **오늘**: 지휘자 = Cowork(사람이 세션에서 트리거).
  - **내일**: 지휘자 = 외부 Python 프로그램 + Claude API(사람 없이).
  - 지식(L0)·스펙(L1)은 그대로 두고 **지휘자만 교체**.

### 흔한 실패
- 지식과 실행을 섞음 → 규칙 하나 바꾸려는데 코드를 건드려야 함.
- 지휘자가 너무 똑똑함(창의까지 함) → 갈아끼우기 불가, 이식 불가.

### 이전 강의 연결
- **6차 레이어 구조("파일 하나 = 한 책임")** 가 **시스템 규모**로 커진 것. 6차가 파일 4개였다면, 8차는 층 4개.

### 실습 씨앗 (설계도 **L**칸)
"내 자동화에서 **안 변하는 지식**(규칙·자료)과 **시키는 일**(실행)을 갈라 적으세요. 입력받는 **창구**도."

---

### 🔌 개념 상자 · API와 MCP (여기서 딱 6분, 깊게 X)

'나눈다'에서 지휘자가 **생성 도구**(그림·영상 만드는 힉스필드 등)를 부른다. 이때 "그 도구를 **어떻게 부르나**"가 API·MCP다.

- **MCP** = AI에게 **도구를 꽂는 표준 콘센트(USB)**. 붙이면 Claude가 그 도구를 바로 쓴다.
  → **지금 우리 공장이 쓰는 방식.** (이미지·영상 생성 등 도구를 MCP로 부착)
- **API** = 프로그램끼리 쓰는 **주문 창구**. 정해진 양식으로 요청하면 정해진 형식으로 답이 온다(식당 주문서).
  → **무인으로 이식하면** 같은 도구를 이 방식으로 부른다.
- **핵심**: MCP now → API later, **일은 그대로, 부르는 방식만 바뀐다.** (지휘자가 얇아서 가능)

> 시연(선택): 붙여둔 MCP로 **이미지 1장만** 실제 생성 → "방금 이게 MCP입니다." (코드 X, 결과만)
>
> 남길 두 줄: **"MCP는 AI에 도구 꽂는 USB, API는 프로그램 주문 창구."** 나머지 용어(SDK·REST·폴링)는 '이런 말도 있구나' 수준.

## 5. O · Oversight (지킨다) — 위험한 곳에 사람 관문

### 원리
자동화라고 **다 무인**이 아니다. **비용·위험이 큰 지점 앞에** 사람이 확인하는 **관문(게이트)**을 둔다.

공장의 관문 4곳:
- ◆**대본 검수** — 대본이 산으로 가면 뒤(그림·영상)가 다 헛수고. 그 전에 잡는다.
- ◆**스토리보드 검수** — 그림이 이상하면 영상 만들 필요 없다. **영상 생성 직전**이 가장 비싼 관문.
- ◆**영상 검수** — 합치기 전에 방향·음성·내용 점검.
- **최종 승인** — 내보내기 전 마지막.

### 관문의 작동 (전이 규칙)
**자동 점검(체크리스트) → 사람 승인 → 반려 시 직전 단계로 되돌림(루프).**
"어디에 브레이크를 달까"를 정하는 게 설계다. 도구가 **비싸거나(영상 생성) 되돌리기 어려운** 지점 앞에 단다.

### 흔한 실패
- 관문 0개(완전 무인) → 이상한 결과가 끝까지 가서 시간·비용 낭비.
- 관문 너무 많음 → 사람이 계속 붙어야 해서 '자동화'가 아님. **비싼 지점에만** 단다.

### 이전 강의 연결
- 새 개념이지만 감각은 익숙 — "AI에게 다 맡기지 말고 **중요한 길목은 사람이 본다**."

### 실습 씨앗 (설계도 **O**칸)
"내 자동화에서 **사람이 꼭 봐야 할 관문**은 어디? (되돌리기 어렵거나 비싼 단계 앞)"

## 6. T · Trace (남긴다) — 파일이 곧 상태다

### 원리
자동화의 **상태(어디까지 했나)**를 사람 머릿속이나 프로그램 메모리에 두지 않고, **전부 파일로 남긴다.**
공장은 실행 1건마다 폴더 하나(`runs/날짜_제품/`)를 만들고, **모든 중간 결과물과 미디어를 거기 쌓는다.**

### 왜 파일에 남기나
- **세션이 끊겨도** 그 폴더만 있으면 **다음 단계부터 이어서** 돌린다.
- **지휘자를 갈아끼워도**(Cowork→Python) 같은 폴더를 읽어 동일하게 진행.
- **멱등** — 이미 만든 결과물이 있으면 건너뛴다 → 다시 눌러도 안전, 크래시에 강함.
- **디버깅** — 뭐가 잘못됐는지 폴더의 파일만 열어보면 안다.

### 원칙 한 줄
> **"메모리에 숨은 상태 금지. 상태는 전부 파일에."**

### 마무리 다리 (강의 클라이맥스)
바로 이 **Trace 덕분에** "MCP now → API later"가 가능하다. 상태가 파일에 다 있으니 **지휘자만 갈아끼우면** 무인 공장이 된다. → 5개 원칙(PILOT)이 여기서 하나로 모인다.

### 흔한 실패
- 결과를 화면에만 출력하고 안 남김 → 끊기면 처음부터.
- job_id(주문번호)만 남기고 실제 결과 파일은 안 받아둠 → 나중에 회수 불가.

### 이전 강의 연결
- **5차 BATLR의 '기록(Record)'** 이 그대로 T(Trace). 자동화의 마지막 기둥.

### 실습 씨앗 (설계도 **T**칸)
"내 자동화의 **작업 폴더**엔 무엇이 남아야 하나? (중간 결과·최종물·기록)"

## 7. 종합 — PILOT 한 장 요약

| 글자 | 원칙 | 우리말 | 한 줄 | 공장 |
|---|---|---|---|---|
| **P** | Pipeline | 쪼갠다 | 큰 일을 순서 단계로 (가로) | 접수→…→합본 8칸 |
| **I** | I/O | 정한다 | 단계마다 입력→출력 계약 | 칸 사이 결과 파일 양식 |
| **L** | Layer | 나눈다 | 지식·실행·창구 층 분리 (세로) | 지식/스펙/지휘/창구 4층 |
| **O** | Oversight | 지킨다 | 비싼 지점 앞 사람 관문 | 대본·스토리보드·영상·최종 검수 |
| **T** | Trace | 남긴다 | 상태를 전부 파일로 | `runs/날짜_제품/` 폴더 |

> **뼈대 = P·L**(가로로 쪼개고 세로로 나눈다) · **관절 = I**(계약) · **브레이크 = O**(관문) · **피 = T**(상태).
> 이 다섯이 서면, 지휘자(사람이든 AI든)는 **갈아끼우면** 된다.

## 8. 설계 실습으로 넘기기 (Part 7 연결)

"자, 이제 여러분 차례입니다. **PILOT 5칸**에 **자기 업무 하나**를 자동화 설계도로 그려봅시다."
- 주제 예: 콘텐츠 발행, 주간 리포트, 이메일 분류·응답, 데이터 수집·정리, 고객문의 1차 응대.
- 완성 못 해도 됨 — **P(쪼개기)와 I(입출력)만** 채워도 절반은 성공.
