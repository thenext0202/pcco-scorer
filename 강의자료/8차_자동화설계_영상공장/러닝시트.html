★ KEY POINT
오늘은 코드가 아니라 '설계'를 배운다. 실전 공장을 해부해 내 설계도를 그린다.

표지 — 강의명 + 우측 PILOT 다섯 글자.

→ 넘어가며: "근데 자동화, 진짜 어려운 게 뭘까요?"

02Part 0 · 오프닝
자동화의 진짜 어려움은 '설계'다
⏱ 4분
★ KEY POINT
자동화는 '툴 붙이기'가 아니다. 진짜 어려움은 어떻게 쪼개고 뭘 주고받게 할지 — 설계다.
🖥 화면
흔한 착각 ✗ vs 진짜 핵심 ✓ 2단 + "설계하는 눈을 기른다".
💬 이렇게 말하세요
많은 분이 자동화를 이렇게 생각해요 — "좋은 툴 하나 붙이면 알아서 되겠지", "AI가 똑똑하니까 '다 해줘' 한 번에 시키면 되겠지." 그런데 실제로 해보면 앞부분은 그럴듯하게 되다가 대개 세 번째 단계쯤에서 무너집니다. 왜냐면 자동화의 진짜 어려움은 툴이 아니라 '설계'거든요. 일을 어떻게 쪼개고, 단계끼리 뭘 주고받게 할지. 5차에서 제가 뭐라고 했죠? "AI가 못하는 게 아니라 전달이 부족한 것." 오늘은 그 '전달'을 설계도로 그리는 날입니다. 그래서 오늘 배우는 건 툴 사용법이 아니라 '설계하는 눈'이에요.
📌 참고
5차(BATLR)를 들은 전제. 안 들었어도 '큰 일을 쪼개 잇는다'만 알면 충분.
→ 넘어가며: "그래서 오늘 뭘 하냐면."

03Part 0 · 오늘의 약속
남의 공장을 해부해, 내 설계도를 그린다
⏱ 3분
★ KEY POINT
실전 공장을 PILOT 5칼로 해부 → 각자 '내 자동화 설계도' 1장. 코드는 안 짠다.
🖥 화면
견학 → 해부(PILOT) → 설계 3카드 + "결과물 = 설계도 1장".
💬 이렇게 말하세요
순서는 셋이에요. 첫째, 공장을 통째로 견학합니다 — 실제로 돌아가는 걸 봐요. 둘째, PILOT이라는 다섯 개의 칼로 그 공장을 해부해서 설계 원리를 뽑습니다. 셋째, 그 원리로 여러분 업무 하나를 설계도로 그려요. 오늘 코드는 한 줄도 안 짭니다. 만드는 건 6·7차에서 배운 방식으로 그다음에 하면 돼요. 오늘은 '설계가 먼저'입니다.
💡 강사 팁
칠판에 P·I·L·O·T 세로로 적어두고, 원칙 하나 끝날 때마다 옆에 한 줄씩 채워가면 몰입도가 확 올라간다.
→ 넘어가며: "자, 그 공장부터 통째로 봅시다."

04Part 1 · 공장 견학
제품 정보 넣으면 광고 영상이 나온다
⏱ 6분
★ KEY POINT
입력(제품 정보) → 출력(한국어 음성 광고 영상). 결과물부터 보여주고 충격을 남긴다.
🖥 화면
입력→출력 한 장 → 완성 광고 영상 1개 재생(30초) ← 오늘 유일한 '원본 그대로'.
💬 이렇게 말하세요
제가 만든 공장을 소개합니다. 한 줄로 — 제품 정보를 넣으면 한국어 음성이 깔린 광고 영상이 나옵니다. 말보다 결과죠, 하나 보시죠. (영상 재생) 자, 방금 이거 제가 편집 프로그램 붙잡고 만든 게 아니에요. 제품 정보만 넣으면 공장이 단계를 밟아 알아서 뽑아낸 겁니다. 광고 하나에 보통 몇 시간씩 걸리던 걸, 이 설계 덕분에 반복해서 찍어냅니다.
💡 강사 팁
영상은 '감탄 포인트'. 제품 가격·상세 수치는 굳이 설명하지 말 것(민감). 흐름과 결과의 임팩트만.
→ 넘어가며: "이게 어떻게 나오는지 — 흐름을 봅시다."

05Part 1 · 흐름 지도
여덟 칸의 흐름
⏱ 4분
★ KEY POINT
접수→분석→방향→대본→그림→클립→검수→합본. 각 칸은 판단(Claude) 또는 생성(도구).
🖥 화면
아이콘 8칸 화살표 흐름도(원본 문서 X, 단순 재작성).
💬 이렇게 말하세요
흐름은 이래요. 제품을 접수하고, 분석하고, 어떤 느낌으로 갈지 방향을 정하고, 대본을 쓰고, 장면 그림을 만들고, 그림을 영상으로 움직이고, 검수·보정하고, 하나로 합칩니다. 여덟 칸이죠. 여기서 하나 봐두세요 — 앞쪽 접수·분석·대본은 '판단하고 글 쓰는' 일이라 Claude가 하고, 그림·영상은 '생성'이라 전용 도구가 합니다. 한 칸에 두 성격을 섞지 않았어요. 복잡해 보이지만, 지금부터 다섯 개의 칼로 해부하면 원리만 남습니다.
→ 넘어가며: "근데 이 큰 공장, 여러분 업무랑 무슨 상관? 그래서 예시를 하나 더."

06Part 1 · 오늘의 두 예시
공장 옆에 — '내 업무'도 같이 본다
⏱ 4분
★ KEY POINT
큰 공장(예시 A)과 누구나 쓸 작은 예시(예시 B·주간 리포트)를 나란히 놓고 원칙마다 둘 다 확인.
🖥 화면
예시 A(영상 공장) / 예시 B(주간 리포트) 2단.
💬 이렇게 말하세요
"영상 공장은 너무 크잖아, 나랑 상관없어" 하실까 봐, 오늘은 작은 예시를 하나 더 데리고 갑니다. '주간 업무 리포트 자동화' — 매주 흩어진 기록을 모아 리포트 초안을 뽑는 거예요. 누구나 당장 만들 만한 크기죠. 앞으로 다섯 원칙을 하나씩 볼 때마다, 큰 공장에서 한 번, 이 작은 리포트에서 한 번, 이렇게 두 번 확인할 거예요. 그러면 '아, 크든 작든 원리는 똑같구나'가 몸에 남습니다.
→ 넘어가며: "첫 번째 칼 — P, 쪼갠다."

07Part 2 · P 쪼갠다
한 방에? vs 여러 칸으로
⏱ 4분
★ KEY POINT
한 번에 다 시키면 어디서 틀어졌는지 모른다. 쪼개면 틀어진 칸만 다시.
🖥 화면
"제품 → ??? → 영상" ✗ vs "여러 칸으로 분해" ✓ 2단.
💬 이렇게 말하세요
첫 번째 칼, P — Pipeline, 쪼갠다. 제가 만약 AI한테 "제품 정보 줄게, 광고 영상 만들어줘" 한 방에 시키면? 십중팔구 이상한 게 나와요. 더 큰 문제는, 어디서 틀어졌는지를 모른다는 거예요. 대본이 문제인지, 그림이 문제인지 뒤엉켜버리죠. 그래서 쪼갭니다. 쪼개 놓으면 틀어진 칸만 다시 돌리면 돼요. 대본이 별로면 대본 칸만, 그림이 별로면 그림 칸만. 흔히 "AI가 똑똑하니 한 번에" 생각하는데, 큰 일일수록 정반대예요. 똑똑할수록 쪼개서 시켜야 결과가 좋습니다.
→ 넘어가며: "진짜 한 방에 시키면 어떻게 되는지, 실제 사례를 볼까요?"

08Part 2 · 실패 사례
"다 해줘"라고 하면 생기는 일
⏱ 4분
★ KEY POINT
한 방에 시키면 원인 추적 불가·전체 재실행·재현 불가 — 자동화가 아니라 도박이 된다.
🖥 화면
증상 1·2·3 목록.
💬 이렇게 말하세요
제가 실제로 초반에 한 방에 시켜봤어요. 세 가지 문제가 생기더라고요. 하나, 앞은 그럴듯한데 뒤로 갈수록 대본과 그림이 따로 놀아요 — 근데 어느 단계가 원인인지 알 수가 없어요. 둘, 한 군데만 고치고 싶은데 전체를 처음부터 다시 돌려야 해요. 시간도 돈(생성 비용)도 폭발하죠. 셋, 이게 제일 치명적인데 — 될 때도 있고 안 될 때도 있어요. 재현이 안 됩니다. 자동화의 생명은 '똑같이 나옴'인데 그게 깨지는 거예요. 결론은 하나예요. 큰 일을 한 프롬프트에 욱여넣지 마라. 쪼개는 순간 자동화가 됩니다.
💡 강사 팁
"여러분도 AI한테 한 번에 시켰다가 이상하게 나온 적 있죠?" 공감 질문으로 경험 소환.
→ 넘어가며: "그럼 어떻게 쪼개야 잘 쪼갠 걸까요?"

09Part 2 · 좋은 단계 3조건
좋은 단계의 세 조건
⏱ 4분
★ KEY POINT
① 하나의 책임 ② 끝이 분명(결과물이 딱 떨어짐) ③ 다음 칸이 그걸 받는다. 보통 3~7개.
🖥 화면
세 조건 카드 + "3~7단계" 감.
💬 이렇게 말하세요
좋은 단계엔 세 가지 조건이 있어요. 하나, 하나의 책임 — 한 칸은 한 일만 합니다. '분석'하면서 '대본'까지 쓰는 칸은 안 만들어요. 둘, 끝이 분명 — 그 칸이 끝나면 딱 떨어지는 결과물이 나와야 해요. 대본 한 편, 그림 여섯 장처럼요. "대충 진행됨" 같은 건 끝이 아니에요. 셋, 다음 칸이 그 결과물을 받아 이어갑니다. 개수 감을 드리면 보통 3~7단계예요. 2개면 덜 쪼갠 거고, 20개면 관리가 더 복잡해져요. 기준은 딱 하나 — '한 칸 = 한 책임'.
→ 넘어가며: "공장이랑 리포트, 둘 다로 쪼개볼게요."

10Part 2 · 두 예시로
같은 원리, 두 크기로 쪼개기
⏱ 3분
★ KEY POINT
공장 8칸 / 리포트 5칸 — 크기는 달라도 '한 칸=한 책임, 끝이 분명'은 똑같다.
🖥 화면
위: 공장 8칸 / 아래: 리포트 5칸(수집→분류→요약→작성→검토).

보세요. 위는 영상 공장 여덟 칸, 아래는 주간 리포트 다섯 칸. 리포트는 수집하고, 프로젝트별로 분류하고, 요약하고, 초안 작성하고, 사람이 검토. 크기는 다르지만 규칙은 똑같아요 — 각 칸이 한 가지 일만 하고, 끝나면 결과물이 딱 나오죠. 여러분 업무도 이렇게 다섯 칸 안쪽으로 쪼개질 겁니다. 이따 직접 해볼 거예요.
→ 넘어가며: "쪼갰으면 — 칸과 칸을 뭘로 잇죠?"

11Part 3 · I 정한다
단계를 '계약'으로 잇는다
⏱ 4분
★ KEY POINT
칸 사이는 '말'이 아니라 정해진 양식의 결과물로. 각 칸의 입력→출력을 못 박는다.
🖥 화면
손으로 만든 미니 카드: "대본 단계 ▶ 들어가는 것: 의도 / 나오는 것: 컷별 대사".
💬 이렇게 말하세요
두 번째 칼, I — I/O, 정한다. 칸을 쪼갰으면, 이제 칸과 칸 사이를 뭘로 잇느냐가 문제예요. 답은 '정해진 양식의 결과물'입니다. 각 칸이 뭘 받아서(입력) 뭘 내놓는지(출력)를 계약처럼 못 박아요. 예를 들어 대본 칸은 — 들어가는 건 '영상 의도', 나오는 건 '컷별 대사와 장면 묘사'. 이걸 미리 정해두는 거예요. "알아서 잘 넘겨줘"가 아니라, "너는 이걸 받아서 이 모양으로 내놔"라고요.
→ 넘어가며: "이 양식이 없으면 어떻게 되는지 봅시다."

12Part 3 · 계약이 없으면
양식이 없으면 중간에 멈춘다
⏱ 4분
★ KEY POINT
단계 사이 양식이 안 정해지면 다음 칸이 뭘 받을지 몰라 깨진다 — 자동화가 멈추는 대부분의 이유.
🖥 화면
계약 없음 ✗ / 계약 있음 ✓ 2단.
💬 이렇게 말하세요
계약이 없으면 이런 일이 생겨요. 대본 칸이 어떤 날은 대사만 주고, 어떤 날은 줄거리만 줘요. 그럼 다음 그림 칸이 "어? 대사가 있어야 하는데?" 하고 깨집니다. 결국 사람이 매번 사이에 끼어서 손봐야 해요 — 그럼 자동화가 아니죠. 반대로 "항상 컷별 대사 + 장면 묘사" 이렇게 양식을 고정해두면, 다음 칸은 믿고 그대로 받아 진행합니다. 사람이 안 껴도 흐르죠. 실제로 자동화가 중간에 멈추는 대부분의 이유가 바로 이거예요 — 단계 사이 양식이 안 정해져서.
📌 참고
여기가 강의의 지적 핵심. '계약'이라는 단어를 반복해 각인.

13Part 3 · 계약의 힘
계약이 있으면 — 갈아끼울 수 있다
⏱ 4분
★ KEY POINT
계약이 있으면 칸을 따로 고치고 따로 테스트하고, 실행자(사람↔AI)를 바꿔도 된다.
🖥 화면
따로따로 가능 / 실행자 교체 2단 + 2차 I/O 회수.
💬 이렇게 말하세요

14Part 3 · 아티팩트
단계 사이 결과물 = 서류철
⏱ 3분
★ KEY POINT
각 칸이 결과를 '서류(파일=아티팩트)'로 만들어 다음 칸 책상에 올려둔다. 서류만 있으면 누가 이어받아도 된다.
🖥 화면
분석 서류 → 방향 서류 → 대본 서류 → 그림 서류 (단계 카드).
💬 이렇게 말하세요
이 결과물들을 비유하면 '서류철'이에요. 분석 칸은 '제품 요약 서류'를 만들어 다음 책상에 올려두고, 방향 칸은 '방향 서류'를, 대본 칸은 '대본 서류'를 올려둡니다. 이런 서류를 전문 용어로 '아티팩트'라고 불러요. 어려운 말 아니고, 그냥 단계가 남기는 결과 파일이에요. 핵심은 — 서류만 제대로 있으면 누가 이어받아도 일이 굴러간다는 거예요. 담당자가 바뀌어도, 심지어 사람이 AI로 바뀌어도요.
→ 넘어가며: "자, 이번엔 가로가 아니라 세로로 나눠봅시다."

15Part 4 · L 나눈다 ⭐
가로로 쪼개고, 세로로 나눈다
⏱ 5분
★ KEY POINT
가로(P)=시간 순서 단계 / 세로(L)=성격 분리. 지식·스펙·지휘자·창구 4층.
🖥 화면
⭐오늘의 핵심 그림 — 가로축(파이프라인) × 세로축(레이어 4층) 교차도.
💬 이렇게 말하세요
세 번째 칼, L — Layer, 나눈다. 지금까지 P에서 가로로 쪼갰죠. 이번엔 세로로 나눕니다. 이 그림이 오늘 제일 중요해요. 가로로 쪼개고(단계), 세로로 나눈다(레이어). 세로 네 층은 — 지식(안 변하는 규칙·자료), 스펙(각 칸의 계약서), 지휘자(칸들을 순서대로 시키는 놈), 창구(사람이 요청 넣는 곳). 가로는 '시간'으로 나눈 거고, 세로는 '성격'으로 나눈 거예요. 6차에서 '파일 하나 = 한 책임' 배웠죠? 그게 시스템 규모로 커지면 이렇게 층이 됩니다.

16Part 4 · 네 층을 하나씩
각 층은 무엇을 맡나
⏱ 4분
★ KEY POINT
지식(무엇을 아는가)·스펙(계약서)·지휘자(순서·상태)·창구(입출력). 규칙 바꾸면 지식층만, 순서 바꾸면 지휘자층만.
🖥 화면
지식/스펙/지휘자/창구 각 한 줄 설명 목록.
💬 이렇게 말하세요
네 층을 하나씩 볼게요. 지식층은 안 변하는 재료·규칙이에요 — 제품 지식, 제작 지침, 스타일 템플릿. "무엇을 아는가"만 담고, 실행은 몰라요. 스펙층은 각 칸의 계약서예요 — 입력·출력·규칙. 누가 실행해도 똑같이 읽히죠. 지휘자층은 칸들을 순서대로 시키고 상태를 관리해요. 창의나 생성은 안 하고 '순서·상태·호출'만. 창구층은 사람이 요청 넣고 결과 받는 곳이고요. 이렇게 나눠두면 뭐가 좋냐 — 규칙 하나 바꾸려면 지식층만 건드리면 되고, 순서 바꾸려면 지휘자층만 건드리면 돼요. 서로 안 엉켜요.

상황을 하나 그려볼게요. 대본까지 만들었는데 노트북이 꺼졌어요. 처음부터 다시? 아니에요. 파일에 상태가 있으니까 — 다시 켜서 폴더를 열면 '아, 대본 서류까지 있네' 하고 어디까지 됐는지 바로 보여요. 그럼 그림 단계부터 이어가면 됩니다. 이미 있는 접수·분석·대본은 건너뛰어요, 이걸 '멱등'이라고 해요, 두 번 해도 결과가 같다는 뜻. 더 놀라운 건, Cowork로 시작했어도 나중에 파이썬 지휘자가 같은 폴더를 읽어서 이어갈 수 있다는 거예요. 자, 여기서 다섯 원칙이 하나로 모여요. 쪼개고(P), 계약으로 잇고(I), 층으로 나누고(L), 관문 두고(O), 상태를 남기면(T) — 멈춰도 이어지고, 지휘자를 갈아끼워도 굴러가는 진짜 자동화가 됩니다.
📌 참고
5차의 '기록(Record)'이 곧 이 T. 시리즈 연결 한 번 짚기.
→ 넘어가며: "자, 이제 여러분 차례입니다."

26Part 7 · 예시

★ KEY POINT
수집→분류→요약→작성→검토. 작성 뒤 사람 확인, 작업 폴더에 단계별 파일.
🖥 화면
주간 리포트 5칸 완성 예시(파이프라인 + I / L·O·T).

28Part 8 · 마무리
PILOT 한 장 요약
⏱ 3분
★ KEY POINT
P 쪼갠다·I 정한다·L 나눈다·O 지킨다·T 남긴다. 뼈대 P·L, 관절 I, 브레이크 O, 피 T.
🖥 화면
PILOT 5줄 요약표.
💬 이렇게 말하세요
정리합니다. PILOT — Pipeline 쪼갠다, I/O 정한다, Layer 나눈다, Oversight 지킨다, Trace 남긴다. 외우는 법은 이래요. 가로로 쪼개고 세로로 나눈다가 뼈대(P·L), 그 뼈를 잇는 관절이 계약(I), 위험한 곳의 브레이크가 관문(O), 그리고 온몸에 흐르는 피가 상태(T)예요. 이 다섯이 서면, 손발인 도구나 지휘자는 언제든 갈아끼우면 됩니다.
→ 넘어가며: "그리고 오늘의 한 문장."

29Part 8 · 관통 문장
자동화는 코드가 아니라 설계다
⏱ 2분

"잘 쪼개고 잘 이으면, 지휘자는 갈아끼우면 된다." 여러분 설계도가 그 시작.

Q. 이거 우리도 만들 수 있나요?
설계는 오늘 다 배웠어요. 만드는 건 Claude Code로, 6·7차 방식. 규모가 클 뿐 원리는 같습니다.
Q. MCP랑 API 차이 다시?
MCP는 AI에 도구 꽂는 USB, API는 프로그램 주문 창구. MCP 안에도 결국 API가 있어요.
Q. 관문(사람 확인) 없이 완전 자동은 안 되나요?
됩니다. 단 초기엔 관문 두는 걸 권해요. 믿을 만해지면 하나씩 뗍니다.
Q. 단계는 몇 개가 정답?
3~7개. 정답은 없고, '한 칸=한 책임·끝이 분명'이면 됩니다.
Q. 우리 회사엔 영상 같은 거 없는데요?
PILOT은 영상 전용이 아니에요. 리포트·이메일·데이터 정리 등 '여러 단계로 이뤄진 반복 업무'면 다 적용됩니다.
