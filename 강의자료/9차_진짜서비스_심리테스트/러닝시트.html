06이론 ① · 앱과 서비스
localhost의 정체 — "내 컴퓨터 안"
⏱ 2분
★ KEY POINT
남이 오려면 ① 24시간 컴퓨터 ② 전 세계가 찾는 주소 ③ HTTPS — 셋 다 내 노트북엔 없다. 그래서 빌린다.

⏱ 3분

'클라우드'라는 말, 뉴스에서 많이 들으셨죠. 별거 아닙니다 — 데이터센터에 컴퓨터를 수만 대 켜놓고 빌려주는 사업이에요. 오늘 쓰는 세 회사도 전부 클라우드 회사입니다. 다만 빌려주는 물건이 달라요. GitHub는 코드 보관용 컴퓨터 — 기억. Vercel은 앱 실행용 컴퓨터에 주소와 자물쇠까지 — 무대. Supabase는 데이터 보관용 컴퓨터에 관리 화면까지 — 창고. 그리고 재밌는 게, 셋 다 무료로 시작하고 셋 다 GitHub 계정 하나로 로그인됩니다. GitHub가 개발 세계의 신분증이란 말이 그래서 나옵니다.

숙제로 계정 3개 가입을 미리 시켰다는 전제. 안 한 수강생은 쉬는 시간에 지원.

09이론 ② · GitHub — 기억
'최종_진짜_최종.js'의 지옥
⏱ 3분
★ KEY POINT
GitHub는 백업집 + 역사책 + 접선 장소. 특히 '접선 장소'가 없으면 자동배포 자체가 성립 안 한다.
🖥 화면
없으면 ✗ vs 있으면 ✓ 2단.
💬 이렇게 말하세요
코드가 내 폴더에만 있으면 무슨 일이 생기냐. 첫째, 노트북이 고장 나면 서비스가 통째로 증발합니다. 둘째, '어제까진 됐는데' 상태로 못 돌아갑니다 — 6차 때 정리했던 '회의록 진짜최종.docx' 지옥이 코드에서 재현되는 거죠. 셋째, 이게 오늘의 핵심인데 — Vercel이 내 코드를 가져가려면 '공식 주소'가 있어야 해요. GitHub가 없으면 자동배포라는 개념 자체가 성립을 안 합니다. GitHub는 백업집이자 역사책이면서, 다른 서비스들이 내 코드를 데려가는 접선 장소입니다.
→ 넘어가며: "이 '역사를 남기는 기술'이 버전 관리 — 게임 세이브랑 똑같습니다."

10이론 ② · GitHub — 기억
버전 관리 = 게임 세이브
⏱ 4분
★ KEY POINT
Git=게임기(세이브 프로그램) · GitHub=클라우드 세이브 · 커밋=세이브 1회 · push=올리기.
🖥 화면
Git/GitHub/커밋/push/브랜치 정의 리스트.
💬 이렇게 말하세요
게임 하면서 세이브 안 하는 분 없죠. 버전 관리가 정확히 그겁니다. Git이라는 프로그램이 내 컴퓨터에서 도는 세이브 기능이에요 — 게임기라고 생각하세요. '커밋'이 세이브 한 번입니다. 지금 상태의 스냅샷에 "뭘 바꿨는지" 메모를 붙여 저장하는 거예요. 이 메모가 중요합니다 — 미래의 내가 읽을 쪽지거든요. 그리고 'push'가 그 세이브들을 GitHub, 즉 클라우드 세이브 서버에 올리는 겁니다. push해야 비로소 내 컴퓨터 밖에 존재하는 거예요. 브랜치라는 것도 있는데 — 세이브를 복제해서 딴 길로 가보는 기능 — 오늘은 본선 하나만 씁니다.
💡 강사 팁
"커밋 = 세이브, push = 클라우드 업로드" 이 두 등식만 각인되면 이 파트는 성공.
→ 넘어가며: "GitHub에 뭐가 있는지 지도를 한번 펼쳐볼게요."
