## 3. 핵심 정의 (모든 자료에서 이 문구 그대로)

**창고 해부 4단**
| 단 | 실명 | 한 줄 정의 | 채점기에서 |
|---|---|---|---|
| 표 | 테이블 | 창고는 표의 묶음 — 한 표 = 한 종류의 사실, 한 줄 = 사실 하나 | 세션 표(7열) · 제출 표(8열). 리더보드는 표가 아니라 읽어 그린 것 |
| 열 | 컬럼 | 열마다 들어갈 것이 정해져 있다 — 종류(글자·숫자·시각·참/거짓·덩어리)·필수·기본값 | 총점은 숫자(글자면 "9">"87") · 호스트 이름은 선택 · 만료 시각 기본 +24h · 요소 점수는 덩어리 |
| 규칙 | 제약·관계 | 표는 스스로를 지킨다 — 유일·허용목록·필수 + 줄 잇기(삭제 연쇄) | 코드 유일(중복→거절→3회 재시도) · 모드 5종 · 제출.세션번호 → 세션.번호 |
| 열쇠 | 보안 | 열쇠는 둘(비밀=서버 서랍 / 공개=브라우저) + 문지기(표마다 읽기·쓰기·고치기·지우기) | Claude 키 .env / 창고 키 공개 · 읽기 O 쓰기 O **고치기 X 지우기 X** |

**데이터가 사는 세 곳**: 주머니(브라우저 — 쓰다 만 프롬프트) · 손(서버 메모리 — 1분 10회) · 창고(DB). 가르는 질문 "껐다 켜도 있어야 하나? 남이 봐야 하나?"

**문장들**: "엑셀은 사람이 지키고, 창고는 창고가 지킨다" / "앱은 여럿이 되고 창고는 하나" / "표 두 장과 줄 하나 — 데이터 설계의 90%" / "창고는 사실을 남기고, 판단은 읽을 때 한다" / "문지기가 없으면 공개 열쇠는 창고 열쇠를 길에 떨어뜨린 것" / "폴더를 갈랐고, 부품을 갈랐고, 오늘은 표를 가른다 — 같은 원리가 크기만 다르게 세 번" / "12차엔 지형으로, 14차엔 화면으로, 오늘은 창고로 — 3종 세트 완성"

**좋은 데이터의 원칙 5**: ① 한 표 = 한 종류의 사실 ② 반복되면 표를 가르고 줄로 잇는다 ③ 규칙은 앱이 아니라 창고에 ④ 비밀 열쇠는 서버에만, 공개 열쇠엔 문지기 ⭐ ⑤ 지우지 말고 남긴다. 증거 = 리더보드 표를 따로 만들지 않음.

**여정 ③ 6스텝(창고 눈)**: 버튼[—] → 기다림[손] → 서버[🔑 비밀] → 결과 카드[흐르는 것] → 등록[🗝 공개+문지기 → 제출 표 줄 하나] → 리더보드[읽기+색인+실시간]. 창고에 남는 순간은 5번 딱 한 번.
