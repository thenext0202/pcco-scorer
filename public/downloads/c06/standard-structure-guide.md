# 6차 강의 — 프로젝트 표준구조 가이드 (재사용 스캐폴드) ⭐

> **이 강의의 핵심 자산.** 파일 변경기는 *예제*일 뿐, 수강생이 가져갈 진짜는 **"어떤 프로그램을 만들든 따라 하는 구조"**다.
> **한 줄 원리**: *기능부터 짜지 말고, 구조(파일 뼈대)부터 깐다. 그래야 혼자서도 안 무너진다.*

---

## 0. 왜 '구조부터'인가

초보가 혼자 프로그램을 만들 때 무너지는 이유는 코드 실력이 아니라 **구조가 없어서**다.
- 어제 뭘 했는지 까먹는다 → `DEVLOG`가 없어서
- AI가 매번 같은 설명을 요구한다 → `CLAUDE.md`가 없어서
- 세션이 끊기면 처음부터 → `HANDOVER`가 없어서
- 비밀키가 깃에 올라간다 → `.env`/`.gitignore`가 없어서
- 단계가 엉킨다 → `specs/` 지침이 없어서

> **그래서 "프로그램 = 코드"가 아니라 "프로그램 = 코드 + 구조 파일들"이다.**
> 이 가이드의 파일 세트를 한 번 익히면, 다음 프로그램부터는 *복붙*으로 시작한다.

---

## 1. 표준 폴더 구조 (어떤 프로그램이든 이 뼈대)

```
my-project/
├── CLAUDE.md              # 🤖 AI가 매 세션 자동으로 읽는 프로젝트 지침
├── README.md              # 🧑 사람용 설명서 (남이 받아서 실행하는 법)
├── DEVLOG.md              # 📒 개발로그 — 무엇을·언제·왜 했나
├── HANDOVER.md            # 🤝 핸드오버 — 현재 상태·다음 할 일 (세션/사람 인계)
├── .env                   # 🔒 비밀키·설정 (절대 깃에 안 올림)
├── .env.example           # 🔑 .env의 '키 이름만' 공유용 견본
├── .gitignore             # 🛡 깃에서 뺄 것 (.env, node_modules, 기록파일…)
├── package.json           # 📦 실행 명령·의존성
├── specs/                 # 📐 단계별 지침 (레이어 I/O 계약) — 2단계 이상일 때
│   ├── 01_수집.md
│   ├── 02_변환.md
│   └── 03_출력.md
├── .claude/
│   ├── settings.json      # ⚙️ 권한 allow/deny
│   └── skills/
│       └── <스킬이름>/
│           └── SKILL.md   # 🍳 반복 작업 레시피
└── src/                   # 💻 실제 코드 (단계별 모듈)
```

> 처음부터 다 만들 필요 없다. **🥚 최소 → 🐣 권장 → 🐦 풀**로 키운다 (§7).

## 2. 파일 카탈로그 — 각 파일이 뭐고, 언제, 왜

| 파일 | 분류 | AI 자동읽힘 | 언제 만드나 | 한 줄 역할 |
|---|---|:---:|---|---|
| `CLAUDE.md` | AI 지침 | ✅ | 시작 직후 `/init` | 이 프로젝트의 규칙·실행법·금지를 AI에게 |
| `specs/*.md` | AI 지침 | ✅(참조) | 2단계 이상으로 쪼갤 때 | 단계별 I/O 계약(포·필·범·메) |
| `.claude/skills/<>/SKILL.md` | AI 레시피 | ✅(호출 시) | 반복 작업이 보일 때 | 같은 절차를 레시피로 저장·재사용 |
| `.claude/settings.json` | 권한 | ✅ | 자주 쓰는 명령 자동허용 필요할 때 | allow/deny 안전 규칙 |
| `README.md` | 사람용 | ❌ | 남에게 줄 때(=거의 항상) | 설치·실행·사용법 |
| `DEVLOG.md` | 기록 | ❌ | 첫날부터 매 작업 | 작업·결정·시행착오 일지 |
| `HANDOVER.md` | 인계 | ❌ | 세션 끝낼 때/넘길 때 | 현재 상태+다음 할 일 |
| `.env` | 비밀·설정 | ❌(읽되 깃 제외) | 키·포트·설정이 생길 때 | 비밀값·환경설정 보관 |
| `.env.example` | 견본 | ❌ | `.env` 만들 때 같이 | 키 '이름만' 공유(값은 비움) |
| `.gitignore` | 안전망 | ❌ | git 시작할 때 | 비밀·쓰레기 파일 깃 제외 |

> **자동읽힘 ✅** = 폴더에 두기만 하면 Claude가 알아서 읽음. 이게 핵심 — 한 번 써두면 매번 설명 안 해도 됨.

## 3. 복붙 템플릿 (파일 변경기 예시로 채움 / 빈칸 버전)

### 3-1. `CLAUDE.md` (AI용 지침)
```markdown
# 파일 이름 일괄 변경기

## 개요
내 폴더의 파일 이름을 규칙대로 제자리에서 바꾸는 Node 로컬 도구.
- 기술: Node 내장 모듈만 (http, fs, path) — 추가 설치 없음
- 실행: `node server.js` → http://localhost:3000

## 구조 (레이어)
- src/collect.js  : 1단계 수집 (폴더 → 파일목록 JSON)
- src/transform.js: 2단계 변환계획 (규칙 → 변경계획 JSON)
- src/validate.js : 2.5 검증 (충돌)
- src/output.js   : 3단계 출력 (fs.rename + 되돌리기 기록)
- specs/*.md      : 각 단계 I/O 계약

## 코드 규칙
- 한 모듈 = 한 단계 책임. 단계 사이는 JSON으로만 주고받는다.
- 주석은 한국어 OK.

## 절대 하지 마세요
- 미리보기 없이 파일 변경 ❌
- 지정 폴더 '바로 아래' 외 재귀 변경 ❌
- 시스템 폴더(C:\Windows 등) 대상 ❌
- .env 값을 코드/깃에 노출 ❌
```

### 3-2. `DEVLOG.md` (개발로그 — 매 작업 한 줄씩)
```markdown
# 개발로그

## 2026-06-02
- [한 일] collect/transform/output 3단계로 레이어 분리
- [결정] 단계 사이는 JSON으로 고정 (2차 I/O 계약 적용)
  - [이유] 한 파일에 다 넣었더니 수정할 때마다 엉켜서
- [시행착오] 한글 파일명이 깨짐 → UTF-8 유지로 해결
- [다음] 되돌리기(undo) 기능 추가

## 2026-06-01
- [한 일] 접두사 붙이는 최소 버전 완성, 로컬 서버로 확인
```
> 💡 효과: 다음에 열었을 때 "내가 여기까지 했고, 왜 이렇게 했지"가 1초에 복원.

### 3-3. `HANDOVER.md` (핸드오버 — 세션 끝낼 때/넘길 때)
```markdown
# 핸드오버

## 현재 상태 (2026-06-02 기준)
- ✅ 완료: 3단계 레이어, 미리보기, 적용
- 🚧 진행중: 되돌리기(undo) — output.js에 기록까지 됐고 복원 미구현
- ⛔ 미착수: 배포(GitHub 공유)

## 다음에 할 일 (우선순위)
1. undo 복원 로직 (.rename-history.json 역방향 rename)
2. 충돌 시 적용 차단 메시지
3. README 마무리

## 실행 방법
- `node server.js` → http://localhost:3000
- 테스트 폴더: ./test-files

## 주의점
- 시스템 폴더 대상 금지(코드에 가드 있음)
- .env의 PORT 바꾸면 주소도 바뀜
```
> 💡 효과: Claude 세션이 끊기거나(`/clear`) 다른 사람이 받아도 **여기만 읽으면 이어서 작업**. (가이드 10 세션관리와 짝)

### 3-4. `.env` / `.env.example`
```bash
# .env  (절대 깃에 올리지 않음 → .gitignore에 등록)
PORT=3000
# 예) 외부 API 쓰는 프로그램이면:
# OPENAI_API_KEY=sk-실제값

# .env.example  (값은 비우고 '키 이름'만 → 깃에 올려 공유)
PORT=
# OPENAI_API_KEY=
```
> 규칙: **비밀은 `.env`(깃 제외), 공유는 `.env.example`(키 이름만).** 남이 받으면 example 보고 자기 값 채움.

### 3-5. `.gitignore`
```gitignore
node_modules/
.env
.rename-history.json
.DS_Store
```

### 3-6. `.claude/settings.json` (권한)
```json
{
  "permissions": {
    "allow": ["Bash(node:*)", "Read", "Edit"],
    "deny": ["Bash(rm -rf:*)"]
  }
}
```
> 자주 쓰는 안전한 명령은 allow로 자동허용, 위험한 건 deny로 차단. (가이드 07·12)

### 3-7. `.claude/skills/커밋정리/SKILL.md` (스킬 견본)
```markdown
---
name: 커밋정리
description: 변경사항을 conventional commits 규칙으로 커밋한다
---

# 커밋 정리 절차
1. `git status`로 변경 확인
2. 관련 변경끼리 묶기
3. 형식: `feat: ...` / `fix: ...` / `docs: ...`
4. 커밋 메시지는 한국어 한 줄 요약 + 필요시 본문
```
> 효과: "커밋 정리해줘" 한마디면 매번 같은 규칙으로. (가이드 17)

### 3-8. `README.md` (사람용)
```markdown
# 파일 이름 일괄 변경기

내 폴더의 파일 이름을 규칙대로 제자리에서 바꿔주는 로컬 도구.

## 설치
1. Node.js 설치
2. 이 저장소를 받기: `git clone <주소>`

## 실행
```bash
node server.js
```
브라우저에서 http://localhost:3000 열기.

## 사용법
1. 폴더 경로 입력
2. 규칙 선택(접두사/순번/찾기바꾸기…)
3. 미리보기 확인 → 적용
4. 잘못되면 되돌리기

## 안전
- 적용 전 미리보기 필수, 되돌리기 지원
- 연습용 폴더에서 먼저 테스트하세요
```

## 4. /명령어 — 워크플로우 단계에 매핑

| 타이밍 | 명령어 | 한 일 |
|---|---|---|
| 새 폴더 시작 | `/init` | CLAUDE.md 초안 자동 생성 |
| 새 작업 시작 | `/clear` | 이전 대화 컨텍스트 비우기 |
| 위험 변경 전 | **plan(계획) 모드** `Shift+Tab` | 안 바꾸고 계획만 먼저 |
| 막혔을 때 | `/help` | 명령어 목록 |
| 모델 바꿀 때 | `/model` | Opus↔Sonnet↔Haiku |
| 비용 볼 때 | `/cost` | 이번 세션 토큰 |
| 대화 길어질 때 | `/compact` | 요약 압축 |
| 셸 직접 실행 | `> !명령` | 권한 안 묻고 빠르게 |
| 파일 지정 | `> @파일` | 그 파일 콕 집어 첨부 |

> 외울 핵심 4개: **`/help` · `/init` · `/clear` · `/permissions`** (가이드 09)

## 5. 프로그램 만들기 표준 흐름 (이 순서를 외워라)

```
0. 폴더 만들기 → claude → /init  (CLAUDE.md 생성)
1. R-PCCO로 의도 설명 → 작게 시작 (한 덩어리 OK)
2. 로컬에서 바로 돌려보기 (작동 확인)
3. ▶ 2단계 이상이면: 레이어로 쪼개고 specs/ 지침(I/O 계약) 작성 → 그대로 구현
4. 에러? → 디버깅 5요소로 부탁
5. CLAUDE.md·README·.env 정리, 반복작업은 SKILL로
6. DEVLOG에 기록, 끝낼 땐 HANDOVER 작성
7. git commit → 공유 결정(§6)
```

> 가이드 05 '만능 5단계' + 2차 '레이어/I-O 계약' + 이 가이드의 '스캐폴드'를 합친 한 장.

## 6. 배포/공유 결정 트리

```
이 프로그램이 '내 컴퓨터의 파일/자원'을 직접 만지나?
├─ 예 (파일 변경기, 폴더 정리 등)
│    → URL 배포 불가(남의 파일 못 만짐)
│    → ✅ GitHub로 코드 공유 → 남이 받아 자기 PC에서 실행
│
└─ 아니오 (순수 화면/계산/조회)
     ├─ 백엔드(DB·서버 로직) 필요?
     │    ├─ 예 → ✅ Railway 등 서버 배포
     │    └─ 아니오(정적 화면) → ✅ Vercel/Netlify URL 배포
     └─ 결과: 남이 URL로 바로 사용
```

> 교훈: **무엇을 만드느냐가 배포 방식을 정한다.** (4차 운세앱=Vercel / 6차 변경기=GitHub 공유)

## 7. 단계별 도입 — 처음부터 다 만들지 마라

| 단계 | 만드는 것 | 소요 |
|---|---|---|
| 🥚 최소 | `CLAUDE.md` + `README.md` + `.gitignore` | 10분 |
| 🐣 권장 | + `DEVLOG.md` + `.env`/`.env.example` + `specs/`(2단계 이상이면) | 한 시간 |
| 🐦 풀 | + `HANDOVER.md` + `.claude/settings.json` + `SKILL.md` | 반나절 |

> 작게 심고 크게 기른다(2차 레이어링 원칙과 동일).

## 8. ⭐ 새 프로그램 시작 체크리스트 (복붙해서 쓰세요)

```
[ ] 폴더 만들고 claude 실행 → /init 으로 CLAUDE.md 초안
[ ] CLAUDE.md 다듬기 (개요·실행법·절대금지)
[ ] .gitignore 만들기 (.env, node_modules 포함)
[ ] R-PCCO로 의도 설명 → 최소 버전 만들기
[ ] 로컬에서 돌려보기
[ ] 2단계 이상? → specs/에 단계별 지침(I/O 계약 포·필·범·메)
[ ] 비밀·설정 생기면 .env + .env.example
[ ] DEVLOG.md에 오늘 한 일 기록
[ ] 반복작업 있으면 SKILL.md
[ ] git commit
[ ] 끝낼 때 HANDOVER.md (다음 할 일)
[ ] 공유 결정 (배포 트리) → GitHub or URL 배포
```

> 이 체크리스트가 이 강의가 수강생에게 남기는 **한 장**이다. 다음 프로그램도, 그다음도 이걸로 시작한다.
