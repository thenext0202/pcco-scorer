# R-PCCO 프롬프트 채점 루브릭 v1.0

> 강의 "AI의 프롬프트란?" (정금구) 부속 실습 앱용 채점 기준서
> 최종 수정: 2026-04-22

---

## 0. 설계 철학

### 0.1 채점의 목적
단순히 "잘함/못함"을 구분하는 것이 아니라, **수강생이 자신의 프롬프트가 R-PCCO 중 어느 부분이 약한지 즉시 인지하고, 한 줄만 추가하면 되는 구체적 개선 포인트를 받는 것**이 목표입니다.

### 0.2 세 가지 원칙
1. **투명성** — 왜 이 점수를 받았는지 감지된 텍스트와 함께 근거 제시
2. **실행 가능성** — 피드백은 "구체적으로 써주세요" 같은 추상이 아닌 "'10년차 ~ 마케터' 문구를 추가해보세요" 수준
3. **긍정성** — 잘한 점(strengths)을 먼저 짚은 뒤 개선점(improvements) 제안

### 0.3 총점 체계
- 각 요소 **20점 × 5 = 100점 만점**
- 보너스 최대 +10점 (단, 총점 100점 초과 불가 — cap 적용)
- 등급: **S**(95+) / **A**(85+) / **B**(70+) / **C**(50+) / **D**(30+) / **F**(30 미만)
- 등급은 슬라이드 17의 "단순 / 실무 / 전문가" 3단계와도 대응 (F~D / C~B / A~S)

### 0.4 "요청" 부분에 대한 주석
강의 슬라이드 16 템플릿에 "요청: OO"이 명시되어 있으나, 요청의 **내용 자체**(무엇을 부탁하는지)는 사용자의 업무 영역이라 품질 평가 대상이 아닙니다. 다만 "요청이 아예 빠진 경우"(예: 역할만 주고 아무것도 시키지 않음)는 Purpose(P) 항목에서 0~5점으로 반영됩니다.

---

## 1. R — Role (역할) · 20점

### 1.1 평가 관점
역할 지정은 AI가 응답에 끌어올 "어휘·관점·체크리스트"의 출발점. **구체성**과 **실재성**이 핵심.

### 1.2 점수 기준표

| 점수 | 레벨 | 기준 | 예시 |
|:---:|:---:|---|---|
| **0** | none | 역할 지정 전혀 없음 | "마케팅 글 써줘" |
| **5** | vague | "전문가", "AI", "너" 등 추상적 지칭만 | "너는 전문가야" |
| **10** | basic | 직군·직업·분야명만 있음 | "너는 마케터야" |
| **15** | good | 경력(연차) + 직군 | "너는 10년차 마케터야" |
| **20** | excellent | 경력 + **세부 전문 분야** | "너는 10년차 B2B SaaS 콘텐츠 마케터야" |

### 1.3 감점 요소
- **과장된 수식어 (−2점)**: "세계 최고", "천재", "박사급 초능력자" 등 실재 불가능한 역할. 강의 슬라이드 10에서 명시적으로 지적한 안티 패턴.

### 1.4 피드백 템플릿
- `0점` → "역할이 빠져있어요. '너는 OO년차 OO 전문가야'로 시작하면 답변의 톤과 깊이가 완전히 달라집니다."
- `5~10점` → "직군은 명시됐어요. 경력 연차와 세부 분야(예: B2B vs B2C, 업계)를 추가하면 20점까지 갑니다."
- `15점` → "좋아요. 한 걸음 더 — 산업이나 대상 시장(스타트업/대기업, 국내/해외 등)을 붙여보세요."

## 2. P — Purpose (목적) · 20점

### 2.1 평가 관점
"이 결과물로 무엇을 할 것인가"가 명확해야 AI가 톤·구조·강조점을 결정할 수 있음.

### 2.2 점수 기준표

| 점수 | 레벨 | 기준 | 예시 |
|:---:|:---:|---|---|
| **0** | none | 목적·요청 자체 없음 | "너는 마케터야" (지시 없음) |
| **5** | implicit | 결과물 종류만 언급 ("글 써줘") | "광고 카피 써줘" |
| **10** | basic | "~하기 위해"가 명시됨 | "신제품 홍보를 위해" |
| **15** | specific | 대상의 **구체적 행동** 유도가 명시됨 | "구매 페이지 클릭을 유도하기 위해" |
| **20** | measurable | 목적 + **성공 기준**이 측정 가능 | "20대 여성이 '이건 나한테 필요하다' 느끼고 CTA 버튼 클릭하도록" |

### 2.3 피드백 템플릿
- `0~5점` → "이 글이 '무엇을 위한' 글인지 말해주세요. 홍보? 설득? 교육? 전환?"
- `10점` → "'누가(대상) 무엇을(행동) 하게 만들기 위해'까지 구체화하면 AI가 톤을 정확히 잡아요."
- `15점` → "성공·실패의 측정 기준을 한 줄 더 추가해보세요."

---

## 3. C₁ — Context (맥락) · 20점

### 3.1 평가 관점 — 3차원 (강의 슬라이드 13)
- **Who**: 누가 읽는가 (연령 / 직무 / 지식수준)
- **Where**: 어디에서 읽히나 (플랫폼 / 채널 / 문서 종류)
- **Why**: 어떤 상황에서 (시간대 / 감정 / 긴급도)

### 3.2 점수 기준표

| 점수 | 레벨 | 기준 | 예시 |
|:---:|:---:|---|---|
| **0** | none | 맥락 전혀 없음 | - |
| **5** | 1D | 3차원 중 1개만 | "20대 대상" (Who만) |
| **10** | 2D | 3차원 중 2개 | "20대 여성, 인스타그램" |
| **15** | 3D | 3차원 모두 언급 | "20대 여성, 인스타 릴스, 출근길" |
| **20** | 3D+granular | 각 차원이 구체적 | "27~32세 직장 여성, 인스타 릴스 피드, 출근 지하철에서 엄지로 넘기며 1.5초 내 판단" |

### 3.3 피드백 템플릿
각 요소별로 빠진 차원을 명시적으로 지적:
- "맥락의 3차원 중 **Where**가 빠졌어요. 어디에 쓰일 글인가요? (블로그/메일/카톡공지 등)"
- `15점 이상` → "3차원 모두 있어요. 각 차원을 한 단계 구체화(연령 범위 → 직무/라이프스타일)하면 만점입니다."

---

## 4. C₂ — Constraints (제약) · 20점

### 4.1 평가 관점
제약은 4개 카테고리 (강의 슬라이드 14):
- **분량**: 글자/단어/문단/페이지 수
- **톤**: 친근 / 격식 / 학술 / 반말 / 존댓말 등
- **어휘**: 전문용어 허용 여부, 난이도, 금지어
- **구조**: 표 / 리스트 / Q&A 등 (※ 출력 형식 O와 구분: 여기선 "불릿 3개만", "단락 2개" 같은 **내부 구조 제약**)

### 4.2 점수 기준표

| 점수 | 레벨 | 기준 | 예시 |
|:---:|:---:|---|---|
| **0** | none | 제약 전혀 없음 | - |
| **5** | 1개 | 1개 카테고리만 | "짧게" (분량만) |
| **10** | 2개 | 2개 카테고리 | "200자 이내, 친근한 톤" |
| **15** | 3개+구체 | 3개 카테고리 + 각각 구체적 | "200자 이내, 20대 반말, 전문용어 금지" |
| **20** | 4개 or 3개 granular | 4개 모두 OR 3개가 매우 구체 | "200자 이내, 20대 반말, 전문용어 금지, 이모지 1개, 가격보다 감정 먼저" |

### 4.3 감점 요소
- **부정형 과다 (−2점)**: "~하지 마" 3회 이상 연속. 강의 슬라이드 14에서 긍정형 권장.
- **모순 (−3점)**: "짧고 자세히 써줘" 등 양립 불가 지시.

### 4.4 피드백 템플릿
- `0~5점` → "제약은 AI의 혼란이 아니라 **집중 도구**예요. 분량 / 톤 / 어휘 / 구조 중 부족한 것을 2~3개 추가해보세요."
- 부정형 과다 → "'~하지 마'보다 '~하게 써줘' 형태로 바꾸면 AI가 더 잘 따릅니다."

---

## 5. O — Output (출력 형식) · 20점

### 5.1 평가 관점
형식을 먼저 지정하면 결과물을 받고 다시 가공할 시간이 사라짐 (강의 슬라이드 15).
**주의**: C₂(제약)의 "구조"와 구분되는 지점은, O는 **최종 전달 매체의 모양**(표/리스트/대본/단계별 가이드), C₂는 **내부 작성 규칙**(단락 수, 불릿 개수).

### 5.2 점수 기준표

| 점수 | 레벨 | 기준 | 예시 |
|:---:|:---:|---|---|
| **0** | none | 형식 지정 없음 (기본값 산문) | - |
| **5** | type-only | 형식명만 | "표로" |
| **10** | type+basic | 형식 + 기본 구성 요소 | "표로, 열은 이름·가격" |
| **15** | type+detailed | 형식 + 행·열·섹션 구체 지정 | "3행 표, 열: 이름 / 가격 / 특징 / 추천대상" |
| **20** | type+schema | 형식 + 세부 구조 + 셀 내부 형태까지 | "3행 표, 열: 이름/가격/특징/추천대상. 특징은 ✓로 시작하는 3개 불릿" |

### 5.3 피드백 템플릿
- `0점` → "받은 결과를 **바로 사용할 수 있는 모양**이 뭔가요? 표? 리스트? 회의록 양식? 먼저 지정하세요."
- `5~10점` → "형식은 있어요. 표라면 '열 구성'까지, 리스트라면 '항목 수와 각 항목 형태'까지 써보세요."

## 6. 보너스 — 최대 +10점 (총점 100 cap)

루브릭 이외에 특별히 뛰어난 프롬프트에 가산:

| 항목 | 점수 | 기준 |
|---|:---:|---|
| **일관성** | +3 | 5요소가 서로 어긋나지 않고 하나의 톤으로 정렬됨 (예: "격식 있는 톤" + "이모지 3개" 같은 모순 없음) |
| **창의적 제약** | +3 | 독창적 설계 (예: "가격 대신 감정을 먼저 건드려라", "첫 문장은 질문으로") |
| **메타 자기검증** | +4 | AI에게 결과물 자체 검증을 요청 (예: "결과를 셀프 체크하고 약점 3개 알려줘") |

## 7. 종합 등급 체계

| 등급 | 점수 | 해석 | 강의 대응 |
|:---:|:---:|---|---|
| **S** | 95~100 | 전문가 수준 — 즉시 실무 투입 가능 | ⭐⭐⭐⭐⭐ 전문가급 |
| **A** | 85~94 | 우수 — 약간의 튜닝만 하면 완성 | ⭐⭐⭐⭐ |
| **B** | 70~84 | 실무 수준 — 1개 요소 보완 필요 | 슬라이드 17 "실무" |
| **C** | 50~69 | 기본 — 2~3개 요소 누락 | ⭐⭐ |
| **D** | 30~49 | 모호 — 핵심 요소 다수 결여 | ⭐ |
| **F** | 0~29 | 매우 부족 — "글 써줘" 수준 | 슬라이드 17 "단순" |

## 8. LLM 시스템 프롬프트 (실사용 버전)

아래는 Claude Haiku 4.5에 그대로 넣을 수 있는 시스템 프롬프트입니다.

````
당신은 R-PCCO 프롬프트 채점 전문가입니다. 사용자가 입력한 프롬프트를 다섯 가지 요소로 채점하고, 구체적이고 실행 가능한 피드백을 한국어로 제공합니다.

[R-PCCO 정의]
- R (Role/역할): 경력 + 세부 전문 분야가 명시된 직군 지정 (0/5/10/15/20)
- P (Purpose/목적): 누가 무엇을 하게 만들 것인가 (0/5/10/15/20)
- C (Context/맥락): Who(대상) · Where(채널) · Why(상황) 3차원 (0/5/10/15/20)
- C (Constraints/제약): 분량 · 톤 · 어휘 · 구조 4카테고리 (0/5/10/15/20)
- O (Output/출력): 결과물 형식과 세부 구조 (0/5/10/15/20)

[채점 원칙]
1. 각 요소는 반드시 0/5/10/15/20 중 하나 (중간값 금지)
2. 감점 요소: 역할 과장 -2, 제약 부정형 3회↑ -2, 지시 모순 -3
3. 보너스(일관성+3, 창의적제약+3, 자기검증+4)는 별도 합산. 단 총점 100 초과 불가.
4. 등급: S(95+) / A(85+) / B(70+) / C(50+) / D(30+) / F(0~29)
5. 피드백은 추상적 조언 금지. "이 한 줄을 추가하세요" 수준으로 구체적.
6. 강점(strengths) 먼저, 개선점(improvements) 나중.

[상세 기준표]
(본 문서의 1~5절 점수 기준표 전체를 여기에 삽입)

[응답 형식]
반드시 아래 JSON 스키마로만 응답하세요. 다른 텍스트 일절 금지.

{
  "total_score": 75,
  "grade": "B",
  "elements": {
    "role":        { "score": 15, "level": "good",      "detected": "10년차 마케터", "feedback": "..." },
    "purpose":     { "score": 10, "level": "basic",     "detected": "홍보를 위해",   "feedback": "..." },
    "context":     { "score": 15, "level": "3D",        "detected": "20대 여성, 인스타, 출근길", "feedback": "..." },
    "constraints": { "score": 15, "level": "3개+구체",  "detected": "200자, 반말, 이모지1개", "feedback": "..." },
    "output":      { "score": 20, "level": "type+schema", "detected": "3행 표, 열 구조 명시", "feedback": "..." }
  },
  "bonuses":   [ { "type": "creative_constraint", "points": 3, "reason": "..." } ],
  "penalties": [],
  "strengths": [ "역할이 구체적", "출력 형식 명확" ],
  "improvements": [
    "목적을 '누가 무엇을 하도록'까지 구체화 (예: '구매 버튼 클릭하도록')",
    "제약에 톤 종류 1개 추가 (예: '친근한 반말')"
  ],
  "improved_example": "사용자 프롬프트를 바탕으로 90점 이상으로 개선한 버전 (200~300자)"
}

detected 필드는 원문에서 해당 요소를 감지한 경우 그 문구를 짧게 인용, 없으면 null.
level 값 예시: none / vague / basic / good / excellent / measurable / 3D / type-only 등.
````

## 9. Few-shot 채점 예시 (시스템 프롬프트에 추가 가능)

### 예시 1 · F등급 (10점)

**입력**
> 블로그 글 써줘

**JSON 응답**
```json
{
  "total_score": 10,
  "grade": "F",
  "elements": {
    "role":        { "score": 0,  "level": "none",      "detected": null, "feedback": "역할이 없어요. '너는 OO년차 OO야'로 시작하세요." },
    "purpose":     { "score": 5,  "level": "implicit",  "detected": "블로그 글", "feedback": "결과물 종류만 있어요. '~을 위해'를 추가하세요." },
```

## 10. 구현 시 주의사항

- **응답 시간**: Haiku 4.5 기준 2~4초. 로딩 애니메이션 + "AI가 5요소를 해부하는 중..." 문구로 대기 체감 감소.
- **토큰 비용**: 입력 ~1500토큰 (시스템 프롬프트 포함) + 출력 ~600토큰 ≈ **요청당 $0.002~0.003**.
  - 30명 × 5회 실습 = 150회 = **약 $0.3~0.45**
- **JSON 파싱 실패 대비**: 재시도 1회 → 실패 시 규칙 기반 fallback (간단한 키워드 매칭으로 최소 점수만 제공).
- **악용 방지**:
  - 입력 1000자 제한 (길어질수록 점수 높아지는 편향 방지 겸)
  - 사용자당 분당 10회 rate limit
  - 욕설/민감정보 간이 필터
- **프라이버시 경고**: 실명·회사명·고객정보 포함 감지 시 "개인정보는 빼고 테스트하세요" 토스트.
- **리더보드 표기**: 점수 + 등급 + 상위 5요소 중 강점 1개 (피드백 전문 노출은 프라이버시상 본인만).
