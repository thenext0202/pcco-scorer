# I-MRKO 지침 채점 루브릭 v1.0

> 강의 "AI의 지침이란?" (정금구) 부속 실습 앱용 채점 기준서
> pcco-scorer의 R-PCCO 루브릭(v1.0)을 기반으로 I-MRKO 체계에 맞게 재설계
> 최종 수정: 2026-04-23

---

## 0. 설계 철학

### 0.1 채점의 목적
수강생이 작성한 **지침(Instruction)**이 I-MRKO 다섯 요소 중 어디가 약한지 즉시 인지하고, **한 줄만 고치면 되는 구체적 개선 포인트**를 받는 것이 목표입니다.

지침은 프롬프트보다 훨씬 길고 한 번 세팅하면 오래 쓰기 때문에, 단순 점수보다 **"이 지침을 실전에서 썼을 때 AI가 어디에서 엉킬지"**를 짚어주는 것이 핵심입니다.

### 0.2 세 가지 원칙
1. **투명성** — 왜 이 점수를 받았는지 감지된 텍스트와 함께 근거 제시
2. **실행 가능성** — "구체적으로 써주세요" 같은 추상이 아닌 "`'결론 1줄 + 근거 3줄'`처럼 숫자로 박으세요" 수준
3. **긍정성** — 잘한 점(strengths)을 먼저 짚은 뒤 개선점(improvements) 제안

### 0.3 2차 강의만의 고유 채점 기준
1차 강의(프롬프트)와 가장 다른 점 두 가지:
- **규칙의 측정 가능성**이 핵심 평가 축 (슬라이드 12 "해석의 여지를 없애라")
- **예시의 함정**을 감점으로 포착 (슬라이드 15 · 킬러 인사이트 1)

### 0.4 총점 체계
- 각 요소 **20점 × 5 = 100점 만점**
- 감점 최대 -15점 (예시 함정 -5 포함)
- 보너스 최대 +10점 (단, 총점 100점 초과 불가 — cap 적용)
- 등급: **S**(95+) / **A**(85+) / **B**(70+) / **C**(50+) / **D**(30+) / **F**(30 미만)

### 0.5 R-PCCO 루브릭과의 관계
I-MRKO는 R-PCCO의 상시 버전입니다. 매핑:
- R (역할) → **I (정체성)** + 이름·성격 추가
- P (목적) → **M (임무)** · 상시 업무 범위로 확장
- C (제약) → **R (규칙)** · 측정 가능성 강조
- C (맥락) → **K (지식)** · 상시 참고자료로 확장
- O (출력) → **O (출력)** · 기본 포맷으로 박아둠

## 1. I — Identity (정체성) · 20점

### 1.1 평가 관점
정체성은 AI가 대화 전체에서 유지할 **이름 + 역할 + 성격**. 이름이 있으면 긴 대화에서 캐릭터가 흔들리지 않음.

### 1.2 점수 기준표

| 점수 | 레벨 | 기준 | 예시 |
|:---:|:---:|---|---|
| **0** | none | 정체성 지정 없음 | (역할 없이 업무만 기술) |
| **5** | vague | "전문가", "AI", "어시스턴트" 등 추상 | "너는 친절한 비서야" |
| **10** | basic | 직군·직업·분야 | "너는 마케터야" |
| **15** | good | 경력 + 직군 (또는 이름 + 직군) | "너는 10년차 마케터야" / "너는 '정비서'라는 비서야" |
| **20** | excellent | 이름 + 경력/세부분야 + 성격 2~3개 | "너는 '정비서'라는 10년차 임원 비서. 성격: 간결·선제안·숫자 우선." |

### 1.3 감점 요소
- **과장 (−2점)**: "세계 최고", "천재", "박사급 초능력", "모든 것을 아는" 등 실재 불가능한 정체성. 강의 슬라이드 10에서 "실재할 법한 이름이 제일 잘 먹힙니다"라고 명시.

### 1.4 피드백 템플릿
- `0점` → "정체성이 빠져있어요. `'너는 〈이름〉이라는 〈경력/역할〉이다. 성격은 〈특성 2~3개〉.'` 패턴으로 시작하세요."
- `5~10점` → "역할은 있는데 이름과 성격이 없어요. 이름이 있으면 대화가 길어져도 캐릭터가 안 흔들립니다."
- `15점` → "한 걸음 더 — 성격 특성 2~3개를 추가하세요. 예: 간결·선제안·숫자 우선."
- `20점 + 과장 감점` → "정체성은 완성됐는데 `'세계 최고'` 같은 표현은 오히려 AI의 톤을 흔듭니다. 담백한 경력 지칭으로 바꾸세요."

## 2. M — Mission (임무) · 20점

### 2.1 평가 관점
"이 AI가 **주로** 무엇을 돕는가"의 범위. 강의 슬라이드 11의 핵심: **"뭐든 다 해주는 AI는 결국 뭐 하나 제대로 못 하는 AI"**. 범위를 좁혀야 품질이 오름.

### 2.2 점수 기준표

| 점수 | 레벨 | 기준 | 예시 |
|:---:|:---:|---|---|
| **0** | none | 임무 없음 (또는 "뭐든 도와줘") | "무엇이든 도와드립니다" |
| **5** | too-broad | 너무 포괄적 | "사용자 요청에 답한다" |
| **10** | basic | 업무 분야는 있음 | "마케팅 업무를 돕는다" |
| **15** | scoped | 구체 업무 2~3가지 나열 | "주간 보고 초안, 회의록 요약, 이메일 톤 교정을 돕는다" |
| **20** | scoped+fallback | 구체 업무 + **범위 밖 처리 지침** | "이 3가지를 주로 돕고, 그 외 요청은 짧게 답한 뒤 본업으로 돌려라" |

### 2.3 감점 요소
- **임무-정체성 불일치 (−2점)**: 예) 정체성은 "마케터"인데 임무는 "코딩 디버깅까지 한다" (강의 슬라이드 11 "범위를 좁혀야 품질이 오른다")

### 2.4 피드백 템플릿
- `0~5점` → "이 AI가 **주로 뭘 돕는지**가 없어요. 구체 업무 3가지를 `'① ② ③'`으로 나열하세요."
- `10점` → "분야는 있는데 **업무 단위**가 안 잡혔어요. 주간 보고, 회의록, 이메일처럼 구체 단위로 쪼개세요."
- `15점` → "임무 3가지까지 좋아요. `'그 외 요청은 짧게 답하고 본업으로 돌려라'` 한 줄 추가하면 20점입니다."
- `20점` → "훌륭한 임무 정의. 이게 체인으로 쪼개기도 쉬운 지침입니다."

## 3. R — Rules (규칙) · 20점 · 🔥 강의 핵심 축

### 3.1 평가 관점
규칙은 **"AI가 일하는 방식"**. 강의 슬라이드 12의 한 문장: **"해석의 여지가 있는 규칙은 작동하지 않는다"**. 이 요소가 I-MRKO에서 가장 엄격하게 채점됨.

**핵심 판별 기준:**
- 숫자로 표현됐는가? (글자 수, 줄 수, 항목 수)
- 금지어가 명시됐는가? (`'~라는 것' 금지`)
- 이유가 붙었는가? (`'~이므로 ~해라'`)

### 3.2 점수 기준표

| 점수 | 레벨 | 기준 | 예시 |
|:---:|:---:|---|---|
| **0** | none | 규칙 없음 | - |
| **5** | abstract | 추상적 형용사만 | "간결하게, 친근하게, 전문적으로" |
| **10** | mixed | 추상 + 측정 가능 혼재 | "간결하게 (결론 1줄)" |
| **15** | measurable | Do/Don't 3개 이상, 모두 측정 가능 | "결론 1줄 + 근거 3줄, 문장 끝 '요' 금지, 추측 시 '추측' 먼저 명시" |
| **20** | measurable+reasoned | 측정 가능 규칙 + **이유 명시** | "결론 1줄 + 근거 3줄 (읽는 사람이 3초 안에 판단해야 하므로), 문장 끝 '요' 금지 (반말 페르소나 유지)" |

### 3.3 감점 요소
- **모순 (−3점)**: "짧고 자세히" / "친근하고 격식 있게" 등 양립 불가 규칙 (강의 슬라이드 12 표의 "추상적 규칙" 상단)
- **부정형 과다 (−2점)**: "~하지 마" 4회 이상 연속 (긍정형 `'~해라'` 권장)

### 3.4 피드백 템플릿
- `0~5점` → "규칙이 **추상적 형용사**만 있어요. AI가 생각하는 `'간결'`과 당신이 생각하는 `'간결'`은 다릅니다. `'결론 1줄 + 근거 3줄 이내'` 같이 **숫자로 박으세요**."
- `10점` → "일부 규칙이 측정 가능하네요. 나머지도 `숫자 / 금지어 / 고정 포맷` 중 하나로 바꾸세요."
- `15점` → "측정 가능한 규칙 좋아요. 각 규칙에 `'~이므로'` 형태로 **이유**를 붙이면 AI가 새 상황에도 응용합니다. → 20점."
- `모순 감점 시` → "`'〈A〉'`와 `'〈B〉'`가 서로 충돌해요. 둘 중 하나를 선택하거나, 우선순위를 명시하세요."

## 4. K — Knowledge (지식) · 20점

### 4.1 평가 관점
지식은 AI가 **항상 참고하는 자료실**. 강의 슬라이드 13: "매번 맥락을 설명하지 말고, 한 번 올려두세요."

**주의 — 지식 vs 임무 구분:**
- 임무(M) = **무엇을 하는가** (행동)
- 지식(K) = **무엇을 참고하는가** (레퍼런스)

### 4.2 점수 기준표

| 점수 | 레벨 | 기준 | 예시 |
|:---:|:---:|---|---|
| **0** | none | 참고 자료 언급 없음 | - |
| **5** | implicit | "이런 상황이야" 수준의 암묵적 배경만 | "우리 회사는 B2B SaaS다" |
| **10** | basic | 참고 자료 1~2종 명시 | "우리 회사 용어집과 작년 보고서 형식을 참고하라" |
| **15** | structured | 참고 자료 3종 이상, 각각 용도 명시 | "① 회사 용어집 (약어 풀 때) ② 작년 Q1 보고서 (포맷) ③ 고객 페르소나 문서 (톤)" |
| **20** | structured+file | 3종 이상 + **첨부 파일/섹션**으로 분리 관리 | "지식 섹션 참조. 회사 용어집·포맷 샘플·브랜드 가이드가 업로드됨" |

### 4.3 감점 요소
- **보안 위반 감지 (−3점)**: 지침 본문에 회사 기밀·개인정보·API 키 같은 민감 정보가 평문으로 박혀 있음 (강의 슬라이드 13 보안 주의)
  - 예: "담당자 이메일은 kim@acme.com이다", "DB 비밀번호는 abc123이다"
- **지식-임무 혼동 (−2점)**: 지식 섹션에 행동 규칙이 섞여 있음 ("회사 용어집을 참고해서 전문용어 쉽게 풀어줘" → 이건 규칙 영역)

### 4.4 피드백 템플릿
- `0~5점` → "AI가 **항상 참고할 자료**가 없어요. 자주 쓰는 용어집, 포맷 샘플, 페르소나 문서 중 1개라도 지식으로 박으세요."
- `10점` → "참고 자료 1~2개 좋아요. 각 자료의 **용도**를 명시하면 AI가 언제 끌어올지 압니다."
- `보안 감점 시` → "⚠️ 지침에 민감 정보가 포함됐어요. 기밀 정보는 Enterprise/팀 버전에서만 다루세요. 일반 버전은 학습 데이터가 될 수 있습니다."
- `지식 없음이 적절할 경우` → "개인 학습용 AI라면 지식은 생략 가능합니다. 다만 업무용이라면 꼭 추가하세요."

## 5. O — Output (출력) · 20점

### 5.1 평가 관점
출력은 **매번 요청하지 않아도 나오는 기본 포맷**. 강의 슬라이드 14: "지침에 박아두면 매번 '표로 해줘' 안 해도 됩니다."

**1차 강의 O(출력)와의 차이:**
- 프롬프트 O = **이번 한 번**의 출력 형식
- 지침 O = **기본값(default)**으로 박는 출력 형식 → 체인에서 다음 AI의 입력이 됨 (슬라이드 14 하단 "체인 설계와의 연결")

### 5.2 점수 기준표

| 점수 | 레벨 | 기준 | 예시 |
|:---:|:---:|---|---|
| **0** | none | 기본 포맷 지정 없음 | - |
| **5** | type-only | 형식명만 | "답변은 표로" |
| **10** | type+basic | 형식 + 기본 구성 요소 | "답변은 표. 열은 항목·내용" |
| **15** | type+detailed | 형식 + 섹션/필드 구체 지정 | "답변 기본 포맷: ① 결론 1줄 ② 근거 3줄 ③ 다음 행동 1개" |
| **20** | type+schema+chainready | 구조화된 포맷 + 체인 재활용 가능 | "Markdown `##` 헤더로 3섹션: **요약** (1줄) / **근거** (3줄 불릿) / **다음 행동** (체크리스트). 각 섹션 끝에 `---` 구분선" |

### 5.3 감점 요소
- **출력-임무 불일치 (−2점)**: 예) 임무는 "이메일 교정"인데 출력은 "표 3행". 도구 포맷이 결과물과 안 맞음.

### 5.4 피드백 템플릿
- `0점` → "`'매번 포맷 지정 안 해도 되는 기본값'`을 박아두세요. `'결론 1줄 + 근거 3줄'`처럼 **세 요소 구조**가 실전에서 잘 먹힙니다."
- `5~10점` → "형식은 있는데 **내부 구조**가 비어 있어요. 각 섹션의 길이와 내용까지 지정하세요."
- `15점` → "이 출력이 **다음 AI의 입력**이 될 수 있을까요? 체인을 염두에 두면 Markdown/JSON 같은 구조화 포맷이 유리합니다."

## 6. 🔥 감점 · 예시의 함정 (−5점) · 강의 킬러 인사이트 1

### 6.1 배경 (강의 슬라이드 15)
> **"예시 1개는 복사, 3개는 감옥."**
> 
> 지침에 예시를 넣으면 AI가 표면을 흉내 냅니다. 이모지 썼으면 매번 이모지, 3문단이면 매번 3문단. 예시 3개면 그 안에만 갇힙니다. 지침은 **규칙**으로, 예시는 프롬프트에.

### 6.2 감점 기준

| 상태 | 감점 | 판별 근거 |
|:---:|:---:|---|
| 예시 0개 | 0 | 감점 없음 |
| 예시 1~2개 | −2 | "예:", "예를 들어", "e.g.", 또는 견본 텍스트 인용 1~2회 |
| 예시 3개 이상 | −5 | 위 패턴 3회 이상 또는 여러 줄 견본 다수 |
| 고정 포맷 템플릿 예시 | 0 (면제) | 명백히 "이 포맷으로 출력하라"는 고정 템플릿 1개는 감점 없음 (출력 섹션 구조 예시) |

### 6.3 판별 패턴
LLM이 지침 텍스트에서 감지할 신호:
- `"예:"`, `"예시:"`, `"예를 들어"`, `"가령"`, `"e.g."`, `"ex:"` 같은 리드어
- 따옴표·백틱으로 감싼 견본 문장 (1줄 이상)
- `"다음처럼 작성하라"` + 뒤따르는 예문
- 같은 유형의 예시가 반복되는 패턴

### 6.4 감점 면제 예외
**"이 포맷으로 고정하라"는 템플릿 1개는 예시가 아니라 규칙**:
- ✅ "출력은 다음 Markdown 구조 고정: `## 요약 / ## 근거 / ## 다음 행동`"
- ❌ "예를 들어 `'오늘 회의록 요약: 결정사항 1개, 액션 3개'`처럼 쓰라"

LLM이 판단할 때: **해당 예시가 "항상 이 포맷"을 의미하면 면제, "이런 느낌으로"를 의미하면 감점**.

### 6.5 피드백 템플릿
- 감점 −2 시 → "지침에 예시 1~2개 발견. **예시는 프롬프트에**, 지침에는 규칙만 두세요. 왜냐면 AI가 예시를 '복사'하기 때문이에요."
- 감점 −5 시 → "⚠️ **예시의 함정** — 지침에 예시가 3개 이상 들어있어요. 이러면 AI가 그 안에만 갇힙니다 (슬라이드 15). 예시를 전부 빼고, 대신 `'~하게 해라'` 규칙으로 바꾸세요. 예시가 꼭 필요한 요청이면 **프롬프트**에 쓰세요."

## 7. 추가 감점

| 항목 | 점수 | 기준 |
|---|:---:|---|
| **정체성 과장** | −2 | "세계 최고", "천재", "무엇이든" (§1.3) |
| **규칙 모순** | −3 | 양립 불가한 규칙 공존 (§3.3) |
| **부정형 과다** | −2 | "~하지 마" 4회 이상 (§3.3) |
| **보안 위반** | −3 | 민감 정보 평문 포함 (§4.3) |
| **지식-임무 혼동** | −2 | 섹션 경계 흐림 (§4.3) |
| **출력-임무 불일치** | −2 | 도구 포맷 미스매치 (§5.3) |
| **예시의 함정** | −2 또는 −5 | 예시 개수 (§6) |

⚠️ 총 감점이 지나치게 커지지 않도록, **감점 상한 −15점** 적용 (합계가 −15 초과 시 −15로 고정).

## 8. 보너스 · 최대 +10점 (총점 100 cap)

2차 강의의 고급 실천을 가산:

| 항목 | 점수 | 기준 |
|---|:---:|---|
| **측정 가능한 규칙 전환** | +3 | 규칙 대부분이 숫자·금지어·고정 포맷 (§3의 15점 이상 구간) |
| **레이어링** | +2 | `## 정체성` `## 규칙` 같은 Markdown 섹션 헤더로 구조화 (슬라이드 16·17) |
| **이유 명시** | +2 | `'~이므로 ~해라'` 패턴이 규칙 2개 이상에 등장 (§3.2의 20점 기준) |
| **임무 경계 관리** | +2 | "범위 밖 요청은 짧게 답하고 본업으로" 같은 fallback 규칙 (§2.2의 20점 기준) |
| **자기검증** | +4 | "답변 전 규칙 체크리스트 확인하라", "부족하면 먼저 질문하라" 같은 메타 규칙 |

⚠️ 보너스 합계 +10 상한. 총점 100점 초과 불가 (cap).

| **A** | 85~94 | 우수 — 미세 조정만 | ⭐⭐⭐⭐ |

| **F** | 0~29 | 매우 부족 | 슬라이드 8 "친절한 비서야" 수준 |

## 10. total_score 계산 공식

```
raw_score = identity + mission + rules + knowledge + output (각 0~20, 합계 0~100)

final_score = raw_score - max(sum(penalties), -15) + min(sum(bonuses), +10)

final_score = clamp(final_score, 0, 100)
```

예시:
- 각 요소 15점씩 (75점) + 보너스 자기검증 +4, 측정규칙 +3 (보너스 합 +7, cap 통과) - 예시 함정 -5 = **77점 / B**

## 11. LLM 시스템 프롬프트 (실사용 버전)

아래는 Claude Sonnet 4.6에 그대로 넣을 수 있는 시스템 프롬프트입니다.

````
당신은 I-MRKO 지침 채점 전문가입니다. 사용자가 입력한 AI 지침(Instruction)을 다섯 가지 요소로 채점하고, 구체적이고 실행 가능한 피드백을 한국어로 제공합니다.

[I-MRKO 정의]
- I (Identity/정체성): 이름 + 역할 + 성격 (0/5/10/15/20)
- M (Mission/임무): 상시 업무 범위 (0/5/10/15/20)
- R (Rules/규칙): 측정 가능한 Do/Don't (0/5/10/15/20) ★ 가장 엄격
- K (Knowledge/지식): 상시 참고 자료 (0/5/10/15/20)
- O (Output/출력): 기본 답변 포맷 (0/5/10/15/20)

[채점 원칙]
1. 각 요소는 반드시 0/5/10/15/20 중 하나 (중간값 금지)
2. 규칙(R)은 "측정 가능성"이 핵심. "간결하게" 같은 추상적 형용사는 5점 이하.
3. 감점 요소:
   - 예시의 함정: 지침에 예시 1~2개 -2점, 3개 이상 -5점 (★ 강의 킬러)
   - 정체성 과장 -2, 규칙 모순 -3, 부정형 과다 -2
   - 보안 위반 -3, 지식-임무 혼동 -2, 출력-임무 불일치 -2
   - 감점 합계는 -15점 상한
4. 보너스:
   - 측정 가능 규칙 +3, 레이어링(## 헤더) +2, 이유 명시 +2
   - 임무 경계 관리 +2, 자기검증 +4
   - 보너스 합계는 +10점 상한
5. total_score = elements_sum - penalties_sum + bonuses_sum (0~100 clamp)
6. 등급: S(95+)/A(85+)/B(70+)/C(50+)/D(30+)/F(0~29)
7. 피드백은 "이 한 줄을 추가하세요" 수준으로 구체적.
8. 강점(strengths) 먼저, 개선점(improvements) 나중.

[예시의 함정 판별 주의사항]
- "예:", "예시:", "예를 들어", "가령", "e.g." 등의 리드어 + 견본 문장을 세라
- 단, "출력은 다음 Markdown 구조 고정"처럼 **항상 이 포맷**을 의미하는 템플릿 1개는 감점 면제
- 판별 기준: 이 예시가 "항상 이 포맷"인가(면제), "이런 느낌으로"인가(감점)

[응답 형식]
**중요: 반드시 순수 JSON 형식으로만 응답하세요. 다른 텍스트, 마크다운 코드블록, 주석 금지.**

응답은 반드시 { 로 시작해서 } 로 끝나야 합니다:

{
  "total_score": 75,
  "grade": "B",
  "elements": {
    "identity":  { "score": 15, "level": "good",               "detected": "...", "feedback": "..." },
    "mission":   { "score": 10, "level": "basic",              "detected": "...", "feedback": "..." },
    "rules":     { "score": 15, "level": "measurable",         "detected": "...", "feedback": "..." },
    "knowledge": { "score": 10, "level": "basic",              "detected": "...", "feedback": "..." },
    "output":    { "score": 20, "level": "type+schema+chain",  "detected": "...", "feedback": "..." }
  },
  "bonuses":   [ { "type": "measurable_rules",  "points": 3, "reason": "..." } ],
  "penalties": [ { "type": "example_trap",      "points": -5, "reason": "..." } ],
  "strengths": [ "정체성이 구체적", "출력 포맷 명확" ],
  "improvements": [
    "규칙에 숫자 추가: '결론 1줄, 근거 3줄'",
    "지식 섹션 추가: '회사 용어집 참고'"
  ],
  "improved_example": "사용자 지침을 바탕으로 90점 이상으로 개선한 버전 (300~600자)"
}

level 값:
- identity: none / vague / basic / good / excellent
- mission: none / too-broad / basic / scoped / scoped+fallback
- rules: none / abstract / mixed / measurable / measurable+reasoned
- knowledge: none / implicit / basic / structured / structured+file
- output: none / type-only / type+basic / type+detailed / type+schema+chain

penalties type 값:
- example_trap, identity_exaggeration, rules_contradiction, rules_negatives_excess,
- security_violation, knowledge_mission_confusion, output_mission_mismatch

bonuses type 값:
- measurable_rules, layering, reasons_given, scope_boundary, self_verification

**다시 강조: 순수 JSON만 출력. 앞뒤 텍스트 금지.**
````

## 13. 구현 시 주의사항

- **입력 길이**:
  - MIN 100자 (지침은 프롬프트보다 길어야 함)
  - MAX 5000자 (실전 지침은 30~100줄 = 1500~5000자)
- **응답 시간**: Sonnet 4.6 기준 5~8초 (지침이 길수록 느려짐). 로딩 문구: "AI가 I-MRKO 다섯 요소를 해부하는 중..."
- **토큰 비용**: 입력 ~3000토큰 (시스템 + 지침) + 출력 ~1000토큰 ≈ **요청당 $0.015~0.020**
  - 30명 × 5회 실습 = 150회 = **약 $2.5~3**
- **JSON 파싱 실패 대비**: 재시도 1회 (기존 pcco-scorer 구조 유지)
- **Rate Limit**: 분당 10회 유지 (지침 채점은 더 느리지만 빈도는 낮음)
- **보안**: 지침에 회사 기밀·개인정보 감지 시 감점 + 프론트에 경고 토스트
