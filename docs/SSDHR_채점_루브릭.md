# SSDHR 이미지 프롬프트 채점 루브릭 v1.0

> 강의 "이미지 프롬프트 설계 가이드" (정금구) 부속 실습 앱용 채점 기준서
> pcco-scorer의 R-PCCO·I-MRKO 루브릭(v1.0)을 기반으로 SSDHR 체계에 맞게 재설계
> 최종 수정: 2026-05-04

---

## 0. 설계 철학

### 0.1 채점의 목적
수강생이 작성한 **이미지 생성 프롬프트**가 SSDHR 다섯 요소 중 어디가 약한지 즉시 인지하고, **한 줄만 고치면 되는 구체적 개선 포인트**를 받는 것이 목표.

이미지 프롬프트는 텍스트와 달리 결과물의 "어색함"을 사후에 진단하기 어렵기 때문에, 프롬프트 단계에서 **빈 칸을 남기지 않았는지**를 평가하는 것이 핵심입니다.

### 0.2 세 가지 원칙
1. **투명성** — 왜 이 점수를 받았는지 감지된 텍스트와 함께 근거 제시
2. **실행 가능성** — "구체적으로 써주세요" 같은 추상이 아닌 "`50mm f/2.8` 같은 카메라 사양을 추가하세요" 수준
3. **긍정성** — 잘한 점(strengths)을 먼저 짚은 뒤 개선점(improvements) 제안

### 0.3 3차 강의만의 고유 채점 축
이전 두 강의(R-PCCO, I-MRKO)와 가장 다른 점:
- **평가 대상은 텍스트 프롬프트** (생성된 이미지 X) — LLM은 이미지를 보지 않고 프롬프트의 구조와 명시성만 평가
- **불완전함의 설계**가 평가 항목 — '더 정교하게'가 아니라 '이만큼 어긋나게'
- **AI 약점 5가지(텍스트·손·시선·접촉·그림자) 명시 통제**가 디테일 점수에 직접 반영
- **충돌 검출**이 위생 가점에 별도로 들어감 (예: "사실적 사진 + 수채화 느낌")

### 0.4 총점 체계
- 각 요소 **20점 × 5 = 100점 만점**
- 가점 최대 **+10점** (5개 항목 × +2점, 단 총점 100점 초과 불가 — cap 적용)
- 감점 최대 **-15점**
- 등급: **S**(95+) / **A**(85+) / **B**(70+) / **C**(50+) / **D**(30+) / **F**(30 미만)

### 0.5 R-PCCO·I-MRKO 루브릭과의 관계
SSDHR은 시각 도메인 전용 변형:
- R (역할) → **S (Scene)** · 누가·무엇·어디·구도로 확장
- C (제약) → **S (Style) + H (Hard)** · 시각 언어 4 레이어 + 절대 규칙으로 분리
- O (출력) → **D (Detail)** · 결과물의 "모양"이 아니라 "질감·완성도"로 변형
- (신규) → **R (Reality)** · 물리·논리 일관성 (텍스트 도메인엔 없는 축)

## 1. S — Scene (장면) · 20점

### 1.1 평가 관점 — 4요소 (강의 슬라이드 7)
- **주체**: 누가/무엇이 (인물·사물·동물·풍경)
- **행동**: 무엇을 하고 있는지 (동사 명시)
- **환경**: 어디서·언제 (장소·시간·날씨)
- **구도**: 카메라 시점·앵글·거리

### 1.2 점수 기준표

| 점수 | 레벨 | 기준 | 예시 |
|:---:|:---:|---|---|
| **0** | none | 장면 묘사 전혀 없음 | "예쁜 그림 그려줘" |
| **5** | 1요소 | 4요소 중 1개만 | "아이를 그려줘" (주체만) |
| **10** | 2~3요소 | 주체 + 행동 또는 주체 + 환경 | "아이가 책상에 앉아 있는 모습" |
| **15** | 4요소 | 4요소 모두 있음 | "한국인 7세 남자 아이가 책상에서 일기 쓰는 모습, 위에서 본 시점" |
| **20** | 4요소+granular | 4요소 모두 + **동사 구체** + **구도 명시** | "한국인 7세 남자 아이가 책상에 앉아 일기를 쓰는 모습, 위에서 내려다본 탑뷰, 자연광이 왼쪽에서 들어옴" |

### 1.3 감점 요소
- **정적 동사 (-1점)**: "있는 모습", "서 있는" 등 무동작. 강의 슬라이드 7에서 명시적 안티패턴.

### 1.4 피드백 템플릿
- `0~5점` → "장면이 비어 있어요. **주체·행동·환경·구도** 4요소를 한 줄에 박으세요. 예: '한국인 7세 아이가 책상에서 일기 쓰는 모습, 탑뷰'"
- `10점` → "주체와 행동은 있는데 환경 또는 구도가 빠졌어요. '어디서·언제·어떤 카메라 시점인지' 한 줄 추가."
- `15점` → "4요소 다 있어요. 동사를 더 구체화하거나(예: '쓰는' → '연필로 일기를 쓰는'), 카메라 사양을 명시하면 만점."

## 2. S — Style (스타일) · 20점

### 2.1 평가 관점 — 4 레이어 (강의 슬라이드 8)
- **L1 매체**: photograph / illustration / 3D render / watercolor
- **L2 카메라**: lens(35mm), aperture(f/2.8), ISO, depth of field
- **L3 색감**: warm earth tones, golden hour, low contrast 등
- **L4 앵커**: era / 사조 / 매체 단위 참조 (Kodak Gold 200, documentary photography 등)

### 2.2 점수 기준표

| 점수 | 레벨 | 기준 | 예시 |
|:---:|:---:|---|---|
| **0** | none | 스타일 지정 없음 | - |
| **5** | 1레이어 | 1개 레이어만 | "사실적으로" (L1만, 모호) |
| **10** | 2레이어 | 2개 레이어 | "photograph, warm tones" |
| **15** | 3레이어+구체 | 3개 레이어 + 각 구체적 | "photograph, 35mm f/2.8, golden hour" |
| **20** | 4레이어+granular | 4개 모두 + 카메라 사양 정확 | "photograph, 35mm f/2.8 ISO 400 shallow DoF, warm earth tones low contrast, early 2000s Kodak Gold 200 documentary photography" |

### 2.3 감점 요소
- **생존 작가/IP 참조 (-2점)**: 특정 살아있는 작가명, 캐릭터 IP, 브랜드명 직접 참조. 강의 슬라이드 8에서 명시적으로 회피 권고.
- **모호한 단어 (-1점)**: "드라마틱하게", "예술적으로", "감성적으로" 같이 매번 다르게 해석되는 표현 단독 사용.

### 2.4 피드백 템플릿
- `0~5점` → "'사실적으로'만 쓰면 매번 다르게 해석돼요. **L1 매체 + L2 카메라 + L3 색감 + L4 앵커** 4 레이어로 분리하세요."
- `10점` → "2 레이어는 잡혔어요. 카메라 사양(예: `50mm f/2.8`)이 빠지면 일러스트풍으로 빠질 수 있어요."
- `15점` → "거의 다 왔어요. 시대·매체 앵커(예: 'early 2000s Kodak Gold 200')를 한 줄 추가하면 만점."

## 3. D — Detail (디테일) · 20점

### 3.1 평가 관점 — 두 영역
**A. 불완전함 설계** (강의 슬라이드 9): "더 정교하게"가 아니라 "이만큼 어긋나게". 손때·미세한 비대칭·일정하지 않은 글자 간격·종이 구김.

**B. AI 약점 명시 통제** (강의 슬라이드 10) — 우선순위 순:
1. **텍스트** — 정확한 문장 + OCR 가능 여부
2. **손가락** — "정확히 다섯", 사물 잡는 방향
3. **시선** — "카메라를 보지 않음", 응시 방향
4. **물리적 접촉** — "연필이 종이에 닿아 있음"
5. **그림자 방향** — 광원과 일치

### 3.2 점수 기준표

| 점수 | 레벨 | 기준 | 예시 |
|:---:|:---:|---|---|
| **0** | none | 디테일 지정 없음 | - |
| **5** | A 또는 B 1개 | 인간미 요소 1개 OR 약점 통제 1개 | "약간 삐뚤어진 글씨" |
| **10** | A·B 합쳐 2~3개 | 두 영역 중 어느 한 쪽 충실 | "삐뚤어진 글씨 + 종이 구김" (A 2개) |
| **15** | A·B 모두 + 텍스트 통제 | 인간미 1~2개 + 약점 1~2개 + **텍스트 정확 명시** | "삐뚤어진 글씨, 종이 구김, 일기장에 '오늘은 비가 왔다'가 정확히 적혀 있음" |
| **20** | A·B 풍부 + 약점 우선순위 1~3번 | 인간미 2~3개 + 약점 우선순위 상위 3개(텍스트·손·시선) 모두 통제 | "삐뚤어진 글씨, 일정하지 않은 필압, 종이 구김 / '오늘은 비가 왔다' 정확 명시, 정확히 다섯 손가락, 시선은 종이를 향함" |

### 3.3 피드백 템플릿
- `0~5점` → "완벽한 이미지는 'AI스러워' 보입니다. **불완전함을 설계**하세요. 예: '글자 간격 일정하지 않음', '종이 살짝 구겨짐'"
- `10점` → "인간미 또는 약점 통제 중 한 쪽만 있어요. **AI가 잘 틀리는 텍스트·손·시선** 중 1개라도 명시 통제 추가하세요."
- `15점` → "거의 다. 약점 우선순위 1순위(텍스트)·2순위(손가락)·3순위(시선)까지 다 잡으면 만점."

## 4. H — Hard Constraints (강제 규칙) · 20점

### 4.1 평가 관점 — 3유형 (강의 슬라이드 11)
- **반드시 포함**: "일기장에 '오늘은 비가 왔다'가 적혀 있음"
- **절대 변형 금지**: "글자 하나도 바꾸지 말 것"
- **정확성 검증**: "OCR로 읽혀야 함" / "로고 비율 유지"

### 4.2 점수 기준표

| 점수 | 레벨 | 기준 | 예시 |
|:---:|:---:|---|---|
| **0** | none | 강제 규칙 없음 | - |
| **5** | 모호 | 강제처럼 보이나 모호함 | "예쁘게 써줘" (= 권유) |
| **10** | 1유형 명시 | 3유형 중 1개를 명시적으로 박음 | "'오늘은 비가 왔다'가 적혀 있음" |
| **15** | 2유형 + 정확성 | 2개 유형 + 정확성 검증 1개 | 위 + "글자 하나도 바꾸지 말 것" |
| **20** | 3유형 모두 명시 | 반드시 포함 + 변형 금지 + 정확성 검증 모두 | 위 + "OCR로 읽혀야 함" |

### 4.3 감점 요소
- **모호한 강제 표현 (-2점)**: "예쁘게", "잘", "느낌 있게" 같이 측정 불가능한 강제 규칙. 강의 슬라이드 11 안티패턴.
- **고유명사 무규칙 (-2점)**: 텍스트·로고·숫자·고유명사가 프롬프트에 등장하지만 강제 규칙으로 보호되지 않음.

### 4.4 피드백 템플릿
- `0~5점` → "**강제 규칙은 울타리, 모호하면 권유**예요. 텍스트·로고·숫자가 들어가면 무조건 '글자 하나도 바꾸지 말 것' 같은 명시적 규칙으로 박으세요."
- `10점` → "1유형은 명시했어요. **변형 금지**나 **정확성 검증**을 한 줄 더 추가하면 모델이 어기지 않아요."

## 5. R — Reality (물리 규칙) · 20점

### 5.1 평가 관점 — 3차원 (강의 슬라이드 12)
- **방향성**: 앞뒤·좌우·위아래 (예: 탑뷰에서 글씨는 카메라 기준 180도)
- **물리적 일관성**: 광원-그림자 일치, 중력, 부유 금지
- **행동 흐름**: 손 움직임과 필기 방향 일치, 동작-결과 인과

### 5.2 점수 기준표

| 점수 | 레벨 | 기준 | 예시 |
|:---:|:---:|---|---|
| **0** | none | 물리 규칙 언급 없음 | - |
| **5** | 1차원 | 3차원 중 1개만 | "광원은 왼쪽" (물리적 일관성만) |
| **10** | 2차원 | 3차원 중 2개 | "광원 왼쪽, 글씨는 카메라 기준 뒤집힘" |
| **15** | 3차원 모두 + 각 1개 | 3차원 모두 언급, 각 1개 규칙 | "광원 왼쪽 그림자 오른쪽, 글씨 180도 뒤집힘, 연필 끝이 글씨 끝과 일치" |
| **20** | 3차원 + granular | 3차원 + 각 차원이 구체적으로 인과까지 명시 | 위 + "사물이 떠 있지 않음, 연필을 잡은 손과 종이 표면이 실제로 닿아 있음" |

### 5.3 피드백 템플릿
- `0~5점` → "**'왜 이상한지 콕 집어 말하기 어려운데 이상한' 이미지**의 원인이 여기예요. 방향성·물리 일관성·행동 흐름 중 1~2개라도 명시하세요."
- `10~15점` → "탑뷰면 '글씨는 카메라 기준 180도 뒤집혀야 함'까지 명시. 광원이 있으면 그림자 방향까지 일치 명시."

## 6. 가점 — 최대 +10점 (총점 100 cap)

5개 항목 × +2점. **N/A 항목은 평가 대상 아님 (감점 X)**.

| 항목 | 점수 | 평가 기준 | 적용 케이스 |
|---|:---:|---|---|
| **토큰 순서** | +2 | 핵심 주체·행동이 프롬프트 앞 25% 안에 배치 | 모든 케이스 |
| **충돌 없음** | +2 | 모순된 시각 언어 없음 (예: "사실적 사진 + 수채화" 같은 충돌 X) | 모든 케이스 |
| **양방향 정의** | +2 | Negative(만들지 않을 것) 명시 — "깨진 글씨 금지", "여분 손가락 금지" 등 | 모든 케이스 |
| **JSON 자산화** | +2 | Style Lock / Character Lock 등 JSON 구조 활용 | 시리즈물 케이스 (단일 이미지면 N/A) |
| **레퍼런스 분리** | +2 | "유지/변경/무시" 또는 "Image A의 X를, Image B의 Y로" 같은 라벨링 | 사진 첨부 케이스 (없으면 N/A) |

### 6.1 N/A 처리
- JSON 자산화·레퍼런스 분리는 케이스에 따라 평가 대상이 아닐 수 있음
- LLM 채점 프롬프트에서 "이 케이스에 해당 안 되면 `null` 반환"
- UI는 "이번 케이스에선 평가 대상 아님"으로 표시 (감점 없음)

## 7. 감점 요소 — 최대 -15점

| 항목 | 점수 | 기준 | 출처 |
|---|:---:|---|---|
| **충돌 표현** | -3 | "사실적 사진 + 수채화 느낌" 같은 모순된 시각 언어 | 슬라이드 14 |
| **생존 작가/IP 참조** | -2 | 살아있는 작가명·캐릭터 IP·브랜드명 직접 참조 | 슬라이드 8 |
| **길이 초과** | -2 | 200단어 초과 (핵심 토큰 가중치 희석) | 슬라이드 14 |
| **모호한 강제 규칙** | -2 | "예쁘게", "잘", "감성 있게" 같은 측정 불가 강제 표현 | 슬라이드 11 |
| **정적 동사** | -1 | "있는 모습" 같이 동작 부재 | 슬라이드 7 |
| **모호한 스타일 단어** | -1 | "드라마틱하게", "예술적으로" 단독 사용 | 슬라이드 8 |
| **부정형 과다** | -2 | "~하지 마"가 5개 이상 (네거티브 자체는 권장이나 과다 시 가중치 희석) | 슬라이드 14 |

(중복 감점 가능, 합산은 -15점 cap)

## 8. 종합 등급 체계

| 등급 | 점수 | 해석 | 강의 대응 |
|:---:|:---:|---|---|
| **S** | 95~100 | 전문가 — 시리즈 100컷 그대로 재사용 가능 | 9가지 특징 모두 충족 |
| **A** | 85~94 | 우수 — 1개 가점 항목만 보강하면 완성 | 5단 + 가점 4/5 |
| **B** | 70~84 | 실무 — 5단 골격은 OK, 메타·자산화 부족 | 5단 충실 |
| **C** | 50~69 | 기본 — 2~3개 요소 누락 | 일부 5단 통과 |
| **D** | 30~49 | 모호 — 핵심 요소 다수 결여 | 묘사형 프롬프트 |
| **F** | 0~29 | 매우 부족 — "예쁜 그림 그려줘" 수준 | 슬라이드 2의 4대 함정 |

## 9. LLM 시스템 프롬프트 (실사용 버전)

````
당신은 SSDHR 이미지 프롬프트 채점 전문가입니다. 사용자가 입력한 이미지 생성 프롬프트를 다섯 가지 요소로 채점하고, 구체적이고 실행 가능한 피드백을 한국어로 제공합니다.

[SSDHR 정의]
- S (Scene/장면): 주체·행동·환경·구도 4요소 (0/5/10/15/20)
- S (Style/스타일): L1 매체·L2 카메라·L3 색감·L4 앵커 4 레이어 (0/5/10/15/20)
- D (Detail/디테일): 불완전함 설계 + AI 약점 5가지(텍스트·손·시선·접촉·그림자) 명시 통제 (0/5/10/15/20)
- H (Hard/강제 규칙): 반드시 포함·변형 금지·정확성 검증 3유형 (0/5/10/15/20)
- R (Reality/물리): 방향성·물리적 일관성·행동 흐름 3차원 (0/5/10/15/20)

[채점 원칙]
1. 각 요소는 반드시 0/5/10/15/20 중 하나 (중간값 금지)
2. 가점 +2점 항목 5개:
   - 토큰 순서 (핵심 주체가 앞 25%)
   - 충돌 없음 (시각 언어 일관)
   - 양방향 정의 (Negative 명시)
   - JSON 자산화 (해당 시)
   - 레퍼런스 분리 (해당 시)
   * JSON·레퍼런스는 케이스에 해당 안 되면 null 반환 (감점 X)
3. 감점: 충돌 -3, 생존 IP -2, 길이 초과 -2, 모호 강제 -2, 정적 동사 -1, 모호 스타일 -1, 부정형 과다 -2 (합 -15점 cap)
4. 보너스 합산 후에도 총점 100 초과 불가
5. 등급: S(95+) / A(85+) / B(70+) / C(50+) / D(30+) / F(0~29)
6. 피드백은 추상적 조언 금지. "이 한 줄을 추가하세요" 수준으로 구체적
7. 강점(strengths) 먼저, 개선점(improvements) 나중

[상세 기준표]
(본 문서의 1~7절 점수 기준표 전체를 여기에 삽입)

[응답 형식]
반드시 아래 JSON 스키마로만 응답하세요. 다른 텍스트 일절 금지.

{
  "total_score": 75,
  "grade": "B",
  "elements": {
    "scene":   { "score": 15, "level": "4요소",       "detected": "한국인 7세 아이가 책상에서 일기 쓰는 모습, 탑뷰", "feedback": "..." },
    "style":   { "score": 10, "level": "2레이어",     "detected": "photograph, warm tones", "feedback": "..." },
    "detail":  { "score": 15, "level": "A·B + 텍스트", "detected": "삐뚤어진 글씨, '오늘은 비가 왔다' 명시", "feedback": "..." },
    "hard":    { "score": 15, "level": "2유형+정확성","detected": "글자 하나도 바꾸지 말 것, OCR 가능", "feedback": "..." },
    "reality": { "score": 20, "level": "3차원+granular","detected": "탑뷰 글씨 180도, 광원 왼쪽 그림자 오른쪽", "feedback": "..." }
  },
  "bonuses": [
    { "type": "token_order",     "points": 2, "reason": "..." },
    { "type": "negative_defined","points": 2, "reason": "..." },
    { "type": "json_asset",      "points": null, "reason": "단일 이미지 케이스라 N/A" },
    { "type": "reference_split", "points": null, "reason": "사진 첨부 없음, N/A" }
  ],
  "penalties": [],
  "strengths": [ "장면 4요소 모두 명시", "물리 규칙 3차원 충실" ],
  "improvements": [
    "스타일에 카메라 사양 추가 (예: '35mm f/2.8 ISO 400')",
    "L4 앵커 한 줄 추가 (예: 'early 2000s Kodak Gold 200')"
  ],
  "improved_example": "사용자 프롬프트를 바탕으로 90점 이상으로 개선한 버전 (200~400자)"
}

detected 필드는 원문에서 해당 요소를 감지한 경우 그 문구를 짧게 인용, 없으면 null.
bonuses의 points는 적용 시 2, N/A 시 null.
````

## 10. Few-shot 채점 예시

### 예시 1 · F등급 (10점)

**입력**
> 따뜻한 색감, 옛날 필름 느낌, 한국인 7세 남자 아이가 일기 쓰는 모습

**핵심 채점**
- S(Scene): 10 (주체+행동+환경 일부, 구도 없음, 동사는 "쓰는")
- S(Style): 5 (색감 1 레이어만, 카메라 사양 없음, "옛날 필름 느낌"은 모호)
- D(Detail): 0 (불완전함·약점 통제 모두 없음)
- H(Hard): 0 (강제 규칙 없음)
- R(Reality): 0 (물리 규칙 없음)
- **합계 15점, F등급**
- 토큰 순서 가점: ❌ (스타일이 앞에 있어 인물보다 질감이 우선됨)
- 충돌 표현 감점: -3 (해당 없음)
- **최종 15점 / F**

### 예시 2 · A등급 (88점) — 강의 슬라이드 20 하이브리드 예시

**입력**
> 한국인 7세 남자 아이가 책상에서 일기를 쓰는 모습, 탑뷰. 일기장에 "오늘은 비가 왔다"가 정확히 적혀 있음. photograph, 35mm f/2.8 ISO 400 shallow DoF, warm earth tones low contrast, early 2000s Kodak Gold 200. 약간 삐뚤어진 글씨, 종이 살짝 구겨짐, 정확히 다섯 손가락. 글자 하나도 바꾸지 말 것, OCR로 읽혀야 함. 탑뷰에서 글씨는 카메라 기준 180도, 광원 왼쪽 자연광. Negative: 깨진 글씨 금지, 여분 손가락 금지.

**핵심 채점**
- Scene: 20 (4요소 모두 + 동사 + 카메라 시점 명시)
- Style: 20 (L1 photograph + L2 카메라 + L3 색감 + L4 앵커 모두 + 정확)
- Detail: 15 (A 2개 + B 1개 + 텍스트 명시. 시선·접촉·그림자는 부분만)
- Hard: 15 (반드시 포함 + 변형 금지 + OCR 정확성)
- Reality: 15 (방향+물리 일치, 행동 흐름 부분만)
- **합계 85점**
- 가점: 토큰 순서 +2 (인물이 앞), Negative 명시 +2 = +4
- **최종 89점 / A**
- 개선 포인트: 시선 명시("종이를 응시"), 연필이 종이에 닿는 접촉 명시 → 만점 가능

## 11. 구현 시 주의사항

- **응답 시간**: Haiku 4.5 기준 2~4초. 로딩 애니메이션 + "AI가 5단을 해부하는 중..." 문구로 대기 체감 감소.
- **토큰 비용**: 입력 ~2000토큰 (시스템 프롬프트 포함) + 출력 ~700토큰 ≈ **요청당 $0.003~0.004**.
  - 30명 × 5회 실습 = 150회 = **약 $0.5**
- **JSON 파싱 실패 대비**: 재시도 1회 → 실패 시 규칙 기반 fallback (키워드 매칭으로 최소 점수만 제공).
- **케이스 자동 감지** (가점 N/A 처리용):
  - 입력에 `{`, `}`, `JSON`, `style_lock`, `character_lock` 등 키워드 감지 → JSON 자산화 평가 대상
  - 입력에 `Image A`, `레퍼런스`, `사진`, `--cref`, `--sref` 등 키워드 감지 → 레퍼런스 분리 평가 대상
- **악용 방지**:
  - 입력 1500자 제한 (이미지 프롬프트는 텍스트보다 약간 길어질 수 있음)
  - 사용자당 분당 10회 rate limit
- **프라이버시**: 실명·회사 로고·민감 사진 첨부 금지 안내

## 12. 향후 개선 아이디어 (v2)

- **모드별 채점**: 단일 이미지 / 시리즈 / 레퍼런스 — 각각 가중치를 다르게 (예: 시리즈는 JSON 자산화를 가점이 아닌 정규 항목으로)
- **실제 이미지 멀티모달 채점**: Claude의 vision 기능으로 생성된 이미지를 함께 평가 (텍스트와 이미지 일치도 채점)
- **레퍼런스 사진 첨부 채점**: 사진 + 프롬프트 동시 입력 시 "유지·변경·무시" 분리도를 LLM이 직접 평가
- **체크카드 자동 분류**: 입력 프롬프트가 CARD 1/2/3 중 어느 케이스인지 자동 판별 후 해당 카드 기준으로만 채점
- **드리프트 감지 (시리즈 전용)**: 같은 사용자가 여러 컷 입력 시 일관성 점수 별도 산출
